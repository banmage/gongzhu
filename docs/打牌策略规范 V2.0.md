## 0. 审核结论与本次统一原则

### 0.1 总体结论

《打牌策略规范 V1.0》的方向是合理的：它把出牌决策拆成“公开信息与关键牌归属 → 四方动态概率 → 攻防模式 → 候选评分”三层，信息边界清楚，覆盖了全红、满贯、变压器、避猪、争羊和分数临界等主要团队目标，并且已经把满贯口径修正为 SRS V3.1 的“本队赢下本局、对方画 1/2 头”，不再采用旧版“满贯 +800”口径。

但 V1.0 还不能直接作为开发与验收基线，主要问题如下：

| 类别 | V1.0 的问题 | 本规范的修正 |
|---|---|---|
| 术语 | “首轮”同时指“本副第一墩”和“某花色首次领出的限制”，容易造成实现和测试歧义；`猪圈`未定义 | 统一改用“本副首墩”与“花色首引限制”；定义 `猪圈` 为策略术语 |
| 信号 | 声明“不依赖暗号”，却又写“固定配合信号”“明确告知同伴”，与 SRS 9.3“不做信号系统、AI 不依赖信号”冲突 | 明确：只使用公开出牌推断，不定义、不依赖任何约定信号；人类约定不属于 AI 规范 |
| 绝对化 | “逼其自收窝猪”“首轮亮猪牌不能出”“无猪无猪圈必须拱猪”等写法把概率性策略写成确定性规则 | 全部改为条件化策略，并补充反例与例外 |
| 概率完整性 | 缺一致性约束、平滑/收缩、置信度、`±1000` 概率、概率来源分层；团队概率“不能相加”的理由不成立 | 补齐约束、平滑、来源与团队聚合；互斥事件在归一后可相加，只需截断 |
| 决策维度 | 把“分数临界”放进威胁模式优先级第 9 位，和旧稿“分数情境与概率模式正交”的原则冲突 | 分数情境作为独立的风险偏好层，终局事件用效用覆盖，不与“争羊”等模式抢固定顺位 |
| 满贯优先级 | 把“己方/搭档满贯”放在威胁模式第 1 位，隐含“满贯必然优先”，未比较满贯画 1/2 头与普通 `+1000` 画 2/3 头的差异 | 保留满贯的高杠杆定位，但新增 `finish-race`：本队接近 `+1000` 时按终局画头数比较，非全亮满贯不自动优先 |
| 评分 | 权重没有量纲、没有防重复计分、没有平局规则，且与当前实现不一致 | 定义相对权重、量纲、防重复计分、确定性平局；另列“当前实现映射” |
| 规则基线 | 只引用 SRS，未列全亮、满贯最终收牌判定、不生成正式个人分、窝猪免窝猪例外、变压器零小计、20 副上限、6.4/6.5、5/8 局制等策略必须知道的规则 | 增加“规则基线”一章，作为策略实现的共同前提 |
| 测试 | 缺概率约束、校准、性能、整盘边界、信号独立性测试；部分场景写成绝对期望 | 重写验收矩阵，区分 P0 硬约束、P1 行为、P2 强度与校准 |
| 实现状态 | 迟滞、PIMC 等尚未实现，但文档读起来像已落地 | 区分“规范目标”与“当前 fast 层已实现/未实现” |

### 0.2 旧评审稿的取舍

《团队出牌策略设计（评审稿）》的长处是工程架构完整：公开观察白名单、信息边界三道防线、四方概率向量、采样世界、PIMC、盘级效用、分阶段实施、测试与风险表。这些内容本规范保留并压缩为可执行条款。

旧稿的问题是大而全、评审问题多、部分阈值和模式与当前实现不一致，且同样存在“团队概率不能简单相加”的数学表述错误。本规范不再保留“评审稿”体裁，而是把已确认的原则固化为规范，把未实现的 PIMC 明确标为后续强度扩展。

### 0.3 权威顺序

1. **SRS V3.1**：规则、计分、赛制、信息可见性、合法出牌的最高权威。
2. **本规范 V2.0**：出牌策略、概率模型、模式、评分、测试的规范基线。
3. **当前代码**：实现事实；若与规范不一致，以实现审计或后续任务修正，不得反过来解释规则。
4. **历史文档**：`_archive/` 中的 V1.0、评审稿、旧规则草案仅作追溯，不再作为开发依据。

> `docs/中式拱猪 对家组队版 完整规则.md` 是早期产品草案，其中“满贯 +800 / 四张全亮最高 +3200”“猪头只看全局累计阈值”等口径已被 SRS V3.1 替代。它不参与本规范的策略推导；如需查阅，应按历史资料对待。

## 1. 定位、目标与非目标

### 1.1 目标

在**合法出牌**和**严格信息边界**下，最大化己方团队从“本副小分 → 本局画头 → 本盘猪头/胜负”的期望收益。具体包括：

1. **合法性**：首引限制、强制跟牌、唯一合法牌、兜底领出全部正确。
2. **信息边界**：只使用公开信息，不读取其他玩家手牌、原始手牌、牌堆顺序或未揭晓亮牌。
3. **团队性**：区分搭档与对手；搭档赢墩不无谓盖压；对手赢墩优先甩负；能配合全红/满贯。
4. **分数感知**：理解正分是进攻资源、负分是防守风险；理解 `±1000` 画头、20 副上限、5/8 局制、加赛与回溯。
5. **概率感知**：动态估计四家全红、满贯、得猪、得羊、得变压器、变压器负向放大、`±1000` 概率。
6. **可解释**：每个模式、每个候选分数都能说明依据。
7. **可复现**：固定公开观察 + 固定种子 → 固定出牌。
8. **可降级**：普通设备默认快速档；标准/强化档可扩展采样与搜索。

### 1.2 非目标

- 不读取任何未公开手牌，包括其他三家的手牌、原始手牌、牌堆剩余顺序、未揭晓亮牌。
- 不做“上帝视角”完美信息求解器。
- 不实现暗号、表情、固定张数编码等搭档信号系统；AI 不依赖信号。
- 不改变亮牌规则、计分流水线、画头规则、赛制与 UI 主流程。
- 不承诺数学意义上的全局最优；只追求可接受算力下的近似最优期望。
- 不把“人类策略提示”与“AI 出牌”分成两套信息边界；两者使用同一公开信息。

### 1.3 成功标准

| 维度 | 标准 |
|---|---|
| 合法性 | 任意局面只返回 `legalCards` 中的牌；首引限制、强制跟牌、唯一合法牌、兜底领出全部正确 |
| 信息边界 | AI 接口不含他人手牌；隐藏手牌不同但公开观察相同，固定种子下决策相同 |
| 团队性 | 搭档赢墩不无谓盖压；对手赢墩优先甩负；能识别搭档全红/满贯与变压器风险 |
| 分数感知 | 己方接近 `-1000` 明显收敛；对方接近 `-1000` 主动施压；`+1000` 能判断攻防 |
| 概率约束 | 概率满足第 7 章一致性约束；硬事实优先于采样；概率随公开信息单调更新 |
| 可解释 | 能输出当前模式、概率来源、候选分数与降级原因 |
| 性能 | fast 单次出牌 P95 ≤ 20ms；standard P95 ≤ 300ms；strong P95 ≤ 800ms（可配置） |
| 可复现 | 固定观察 + 固定种子 → 固定出牌；同公开信息不同隐藏手牌 → 同决策 |
| 强度 | 大样本自对弈中，团队猪头差/胜率稳定优于旧启发式；概率校准不劣于常数基线 |

## 2. 规则基线（策略必须知道的规则）

本章只列与出牌策略直接相关的规则。若本章与 SRS V3.1 有出入，以 SRS 为准。

### 2.1 牌与基础分值

花色编码：`0=♣ 1=♦ 2=♥ 3=♠`；点数：`0=2 … 12=A`。牌大小：`A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2`。

| 牌 | 名称 | 基础分 | 亮牌后 |
|---|---|---|---|
| ♠Q | 猪 | -100 | -200 |
| ♦J | 羊 | +100 | +200 |
| ♣10 | 变压器 | 特殊倍率 | 倍率 ×2 → ×4 |
| ♥A | 红桃A | -50 | -100；同时使全场红桃分值 ×2（含自身） |
| ♥K | 红桃K | -40 | -80 |
| ♥Q | 红桃Q | -30 | -60 |
| ♥J | 红桃J | -20 | -40 |
| ♥10~♥5 | 红桃10~5 | 各 -10 | 各 -20 |
| ♥4~♥2 | 红桃4~2 | 0 | 0 |

- 全部红桃原始总分：`-200`。
- `♥4~♥2` 虽为 0 分，仍属于“红桃牌/计分牌”，影响变压器独拿判定与“非计分牌优先”的超时垫牌。
- 关键牌：`PIG=♠Q=49`、`SHEEP=♦J=22`、`TRANSFORMER=♣10=8`、`HEART_A=♥A=38`。

### 2.2 发牌、领出与出牌顺序

1. 52 张无大小王，每人 13 张。
2. 每局第一副：持 ♠3 的玩家领出，首引花色不限。
3. 局内后续副：上一副拿到猪（♠Q）的玩家领出，领出花色不限。
4. 若上一副因满贯结束，本局随即结束，不进入下一副；新局第一副重新按 ♠3 规则。
5. 画猪头后本局结束，新局第一副重新按 ♠3 规则。
6. 出牌顺序逆时针：南 → 东 → 北 → 西。

### 2.3 一墩规则

1. 领出一家出一张，其余三家依次跟牌，4 张为一墩，共 13 墩。
2. 有领出花色必须跟同花色；没有该花色可任意垫其他花色；垫牌视为本墩最小。
3. 同花色点数最大者赢墩；无将牌，不同花色不比较大小。
4. 赢墩者收下本墩所有分牌，并获得下一墩领出权。
5. 一墩分牌归赢墩个人；结算时先算个人分，再相加为团队小分。

### 2.4 全红、满贯、窝猪、变压器

#### 全红

- 单个玩家收集全部 13 张红桃：红桃总分从 `-200` 反转为 `+200`；若 ♥A 已亮，先翻倍至 `-400` 再反转为 `+400`。
- 全红只反转红桃分数；猪分照常计算。
- 全红是个人事件，不支持两人合全红。
- 其他任何一家已收至少 1 张红桃，则该家永远不可能全红。
- 全红 + 窝猪：先反转红桃，再叠加窝猪。例：窝猪 + 全红 = `-400 + 200 = -200`；窝猪 + 全红 + 亮♥A = `-400 + 400 = 0`。

#### 满贯

- 条件：**单个玩家**集齐猪、羊、变压器、全部 13 张红桃；必须个人拿齐，不支持合满贯。
- 判定时点：**整副牌结算时**，依据**本副最终收牌归属**，不看手牌、亮牌或曾经持有。
- 触发后：**本队立即赢下本局**；对方画 1 头（该副四张关键牌非全亮）或 2 头（该副四张关键牌全亮，含自动亮，不论谁亮）。
- 满贯优先于普通画头阈值：不再检查 `±1000` 表。这里的“优先”是**规则判定顺序**，不是策略结论；策略上满贯与普通 `+1000` 的画头收益必须比较，见 7.7。
- 本副**不生成正式普通个人分**，不加入本局小分；本局此前累计小分不再用于画头，本局结束清零；可生成仅用于展示/复盘的“模拟展示分”，必须标注非正式。
- **不触发窝猪**；满贯者收猪不计负分；普通分牌仅可展示。
- 满贯者仍需要全红，因此 `pGrandSlam ≤ pAllRed`。

> **策略含义**：满贯结束本局时，对方只画 1 头（该副四张关键牌非全亮）或 2 头（全亮）；普通 `+1000` 结束时，对方通常画 2 头，若同时对方 `≤ -1000` 则画 3 头。因此“能满贯”不等于“应满贯”，本队已接近 `+1000` 时尤其要比较两条路线的画头数，见 7.7、8.1 `finish-race` 与 9.2。

#### 窝猪

- 仅当**亮猪者本人最终自己收下 ♠Q** 时触发，猪分直接记 `-400`，不再按亮猪 `-200` 计算。
- 非亮猪者收下 ♠Q：无论同伴还是对手，均按亮猪后 `-200`；猪未亮则按 `-100`。
- **免窝猪例外**：亮猪时亮猪者手中只有一张黑桃（即 ♠Q 本身），最终由本人自收 ♠Q，不记窝猪；猪分仍按亮猪后的 `-200`。
- 自动亮的猪若本人自收，算窝猪（SRS V3.1 默认）。

#### 变压器

- **独拿**：实际收牌中除 ♣10 外没有任何其他计分牌（♠Q、♦J、任意红桃，含 ♥4~♥2），基础 `+50`；亮变 `+100`。普通黑桃/方块/梅花非关键牌不影响独拿。
- **非独拿**：除 ♣10 外还有任意计分牌，不适用 `+50/+100`；先按计分顺序累加该玩家修正后总分（含猪、羊、红桃、全红、窝猪等），再对该非零总分 ×2；亮变 ×4。
- 若修正后总分为 0，则 ×2/×4 仍为 0，不触发 `+50/+100`。
- 变压器放大的是**拿到它的个人分**，不是团队分。
- 例：窝猪 `-400` 且亮变 → `-1600`；窝猪 + 全红 + 亮♥A = 0，且亮变 → 仍为 0；仅 ♣10 + ♥4（0 分红桃）为非独拿，结果为 0，不 +50。

### 2.5 画猪头与一局结束

设 A 队、B 队本局累计小分为 `SA`、`SB`。**画头结果列指“被画头的一方”**。正分阈值是进攻：某队小分达到 `+1000` 或更高，由对方被画头；负分阈值是防守：某队小分达到 `-1000` 或更低，本队被画头。

| 触发条件 | 画头结果（被画头方） | 本局胜者 |
|---|---|---|
| 仅 `SA ≤ -1000` | A 队画 1 头 | B 队 |
| 仅 `SA ≥ +1000` | B 队画 2 头 | A 队 |
| 仅 `SB ≤ -1000` | B 队画 1 头 | A 队 |
| 仅 `SB ≥ +1000` | A 队画 2 头 | B 队 |
| `SA ≤ -1000` 且 `SB ≥ +1000` | A 队画 3 头 | B 队 |
| `SA ≥ +1000` 且 `SB ≤ -1000` | B 队画 3 头 | A 队 |
| `SA ≥ +1000` 且 `SB ≥ +1000` | 双方各画 2 头 | 按 6.4 裁决 |
| `SA ≤ -1000` 且 `SB ≤ -1000` | 双方各画 1 头 | 按 6.4 裁决 |

补充：

- **团队小分 = 本队两人个人分之和**。策略判断必须看团队小分，不要只看某一家的个人分：一人收羊可能被搭档红桃抵消，一人收猪也可能被搭档羊抵消。
- 单队不可能同时满足正负两条阈值。
- 某队小分达到 `+2000` 或更高，仍按“对方被画 2 头”处理。
- 双方均正高时，双方各自的正高分别使对方画 2 头，故双方各画 2 头。
- 双方均负低时，双方各自的负低分别使本队画 1 头，故双方各画 1 头。

本局胜负字段：

- `roundWinner`：本局胜者，可为 A 队、B 队、`NONE`。
- `roundLoser`：本局负者，可为 A 队、B 队、`NONE`。
- `roundResult`：`A_WIN`、`B_WIN`、`DRAW`。
- 6.4 仅用于记录本局胜负和 8 局制回溯，不改变总猪头比较。

6.4：双方本局新增猪头数相同时，依次比较本局累计小分，小分更低（更负）的一方为本局负者；若小分也相同，判和局，双方各记本局平。

6.5：单局副数上限默认 20 副。达到上限仍未触发画头时，比较双方本局累计小分，小分更低方被画 1 头，另一方为本局胜者；小分相同则双方各画 1 头，按 6.4 判和局。

### 2.6 赛制与盘终

- **5 局制**：固定 5 局，累计双方总猪头，少者胜。5 局后相同则加赛，采用“突然死亡”：每加赛 1 局结束后比较总猪头，少者立即获胜；仍相同则继续加赛。加赛局产生的猪头正常累计。
- **固定 8 局制**：固定 8 局，累计总猪头，少者胜。8 局后相同，判**最后一局输者负**：
  1. 最后一局新增猪头多者为本局输者；
  2. 若相同，按 6.4 判本局胜负；若判出胜负，该局负者为输者；
  3. 若 6.4 判和，依次向前回溯最近一局有胜负的局，该局负者为输者；
  4. 若整盘无胜负局，双方判和。
- 本局胜负用于记录、8 局制回溯、展示与战绩；最终胜负仍以总猪头少者为准。

### 2.7 亮牌首引限制

SRS 使用“首轮限制”这一名称，本规范为避免与“本副第一墩”混淆，写作**花色首引限制**：

1. 每副牌中，某花色**第一次作为领出花色**的那一墩，该花色中**被亮过的牌**不能领出，也不能跟牌。
2. 限制只作用于该墩；该墩结算后，该花色首引限制解除。
3. 若某花色此前仅被垫牌、未被作为领出花色，不消耗该花色首引限制；该花色首次被领出时才触发。
4. 例外①（跟牌）：若玩家手中该花色仅剩这一张受限制亮牌，跟牌时必须出。
5. 例外②（领出）：玩家不允许主动领出受限制亮牌；允许领出同花色非亮牌。若轮到领出且手中只剩受限制亮牌、无其他合法领出牌，兜底允许任选一张受限制亮牌领出，避免死锁。
6. 该限制对亮猪、亮羊、亮变、亮♥A一致适用；自动亮的牌同样适用。
7. 受限制亮牌仍可在**其他花色**领出且自己缺门时作为垫牌打出；限制只针对该花色首次作为领出花色时的领出/跟牌，不限制跨花色垫牌。
8. 服务端须维护 `firstLedSuitStatus`：`♣/♦/♥/♠` 各为 `NOT_LED` 或 `LED`；某花色首次成为领出花色时置为 `LED`，并在该墩执行合法性校验。

### 2.8 策略不得改变的事情

- 不改变 `scoreDeal()`、`evaluatePigHeads()`、`resolveMatch()` 的正式规则。
- 不改变合法出牌集合；策略只能在合法集合内选择。
- 不改变亮牌阶段、自动亮、揭晓时机。
- 不把“策略概率”当作正式计分；正式结算一律调用真实计分函数。
- 不把“人类提示”用于向其他玩家泄露隐藏信息。

## 3. 术语与口径

| rollout | 从当前局面按策略模拟到终局。 |

## 4. 信息边界与公开知识

### 4.1 唯一允许的信息

出牌 AI 只接收一个裁剪后的 `PlayObservation`。允许字段：

- 自己的当前手牌；
- 自己的原始手牌（仅用于自己亮猪时的“单张黑桃免窝猪”判断）；
- 每家剩余手牌数（`13 - 已出牌数`）；
- 当前墩的出牌顺序、牌面、领出者、首引花色、是否本副首墩、是否最后一家；
- 历史每墩的四张牌、赢家、首引花色、是否首墩；
- 每家已收牌（所有打出的牌本来就是公开的）；
- 已亮关键牌、亮牌者、自动亮标记（仅揭晓后）；
- 四个花色的 `firstLedSuitStatus`；
- 当前合法出牌集合；
- 本局小分、本盘总猪头、局数、副数、单局副数上限、赛制、是否加赛、历史局摘要；
- 本副序号、领出者、是否开局副、发牌种子；
- 采样/平局种子（只用于可复现，不得用于还原他人手牌）。

禁止的信息：

- 其他三家的当前手牌；
- 其他三家的原始手牌；
- 牌堆剩余顺序；
- 未揭晓的亮牌；
- 任何由服务端/本地状态直接暴露的隐藏牌；
- 其他玩家的 UI 选择、提示点击、表情等非牌面信息。

### 4.2 信息边界的三道防线

1. **类型防线**：`PlayObservation` 类型中没有 `hands` / `originalHands` 字段；其他座位只暴露 `handSizes`。
2. **构造防线**：`buildPlayObservation()` 只逐字段复制白名单，禁止 `{ ...deal, self }` 之类整对象展开。
3. **测试防线**：构造两个隐藏手牌不同、公开观察完全相同的牌局，固定种子下 AI 必须给出相同出牌。

### 4.3 公开知识 `PublicKnowledge`

AI 自己维护：

| 知识 | 推导方式 |
|---|---|
| 每家剩余张数 | `13 - 已出牌数` |
| 某家某花色缺门 | 该家曾在某花色领出时垫过其他花色 |
| 某家可能持有某花色 | 曾跟过该花色，或亮牌显示持有 |
| 已打出的牌 | 历史墩 + 当前墩 |
| 已收牌 | `collected` |
| 未见牌 | 全牌堆 − 自己手牌 − 已打出牌 |
| 已亮但未打出的牌 | 属于亮牌者手牌（揭晓后） |
| 关键牌归属 | 已亮/已出/已收为硬信息；其余未知 |
| 首引限制 | `firstLedSuitStatus` + 当前墩 `isFirstLed` |
| 猪/羊/变压器/♥A 是否已出 | 历史墩 + 当前墩 + 收牌区 |
| 当前赢家 | 当前墩同花色最大牌 |
| 剩余红桃、剩余大牌 | 未见牌集合 |

### 4.4 必须显式建模的不确定性

1. 其他三家手牌：只能按公开约束估计/采样。
2. 未亮关键牌的位置：可能在任意未缺门玩家手中。
3. 亮猪者的原始黑桃张数：如果不是自己，公开信息无法精确知道；它影响“单张黑桃亮猪免窝猪”。只能按公开信息约束假设。
4. 对手后续策略：用统一理性策略近似，不做信号解读。
5. 未来发牌：本副内不存在；当前决策不需要预测下一副的牌。

### 4.5 无信号原则

- 本规范**不定义、不依赖**任何搭档暗号、固定张数编码、表情或口头约定。
- 从出牌大小、领出花色、垫牌顺序中推断意图，只能作为**软信息**，不得当成承诺或硬约束。
- 人类玩家可以自行约定，但 AI 与推荐系统不得假设这些约定存在；AI 仍只按公开牌面与公开分数决策。
- 因此，“跟大牌=欢迎继续”“领某花色=我有 ♦A”这类说法只描述**可能的公开推断**，不是规则，也不是 AI 必须遵循的信号。

## 5. 决策框架

每一手按以下顺序决策：

1. **合法牌过滤**：唯一合法牌直接出；处理花色首引限制、强制跟牌、兜底领出。
2. **更新公开知识**：未见牌、缺门、剩余张数、关键牌归属、已收关键牌、当前赢家。
3. **更新四方动态概率**：四家全红、满贯、得猪、得羊、得变压器、变压器负向放大、`±1000`。
4. **判定分数情境**：己方/对方距 `±1000`、总猪头差、是否最后一副/加赛/盘末。
5. **判定威胁模式**：己方/搭档全红或满贯、敌方全红或满贯、搭档变压器风险、避猪/争羊、♥A 处置、残局留牌。
6. **判断当前墩归属与攻防方向**：谁赢对本队有利、本墩分数、关键牌。
7. **候选牌评分**：本墩收益 + 未来控制 + 关键牌处理 + 分数情境 + 威胁模式 − 风险 − 信息泄露。
8. **选择最高分**；平局按“安全 > 少泄露 > 确定性种子”处理。

> **关键原则**：正分是进攻资源（己方 `+1000` 使对方画头）；负分是防守风险（己方 `-1000` 本队被画头）。出牌不能只看“本墩谁收分”，必须看“谁收、收后概率如何变、是否改变画头/满贯路线”。

## 6. 关键牌归属与收牌概率

### 6.1 持有概率 ≠ 收牌概率

- `P(c ∈ p)`：未见牌 `c` 在玩家 `p` 手中的概率。
- `P(p 收 c)`：`c` 最终进入 `p` 的收牌区的概率。

亮猪者持有 ♠Q 的概率是 100%，但他可以用黑桃大牌把猪送出去，所以收猪概率可能远低于 100%。策略必须区分两者。

### 6.2 硬事实优先

| 信息 | 推断 |
|---|---|
| 已亮且未打出 | 100% 在亮牌者手中 |
| 已打出/已收 | 归属收牌者，不再属于手牌 |
| 自己手牌 | 100% 自己持有 |
| 某家在某花色领出时垫过其他花色 | 该家该花色已缺门，剩余张数 0 |
| 某家已收红桃 | 其他家全红概率立即归零；若多家已收红桃，所有人全红归零 |
| 某家已收任意关键牌（猪/羊/变/♥A） | 其他家该牌概率归零；其他家满贯概率归零 |
| 某家已收齐猪、羊、变（3 张满贯关键牌） | 该家满贯概率退化为全红概率 |
| 某家已收猪 | 其他家得猪概率归零 |
| 某家已收羊/变/♥A | 其他家得该牌概率归零 |

### 6.3 软信息推断

在硬事实之外，用公开出牌修正概率。以下均为**可能推断**，不是信号承诺：

| 观察 | 可能推断 | 策略含义 |
|---|---|---|
| 领短套 | 想制造缺门，卖出猪/♥A/红桃；或短套无控制，请同伴接手 | 同伴短套可帮其垫负；敌方短套要防其甩负 |
| 领长套 | 有控制，想帮同伴卖牌、建立长套或领羊 | 保留该花色大牌配合/阻止 |
| 领 A | 强控信号，想收该花色或逼关键牌；也可能是“我有强套，你放心垫负分” | 不轻易盖，除非要破全红/满贯 |
| 跟同花色大牌 | 可能有控制、欢迎继续；也可能是被迫 | 可继续领；防诱骗 |
| 跟同花色最小牌 | 可能不欢迎、无控制、请求换花色 | 换花色或让同伴接手 |
| 搭档赢墩时不盖 | 让搭档收 | 若本墩负分且搭档有变压器风险，考虑接手 |
| 对手赢墩时垫负分 | 甩负 | 不要让同伴接；能截则截 |
| 敌方主动拱猪 | 想送猪 | 避免自己收猪；可用黑桃控制逼其自收 |
| 敌方不领黑桃 | 可能持猪等断门 | 保持黑桃压力，不帮其解套 |
| 敌方亮猪 | 想送猪，且猪分翻倍 | 不接猪；有猪圈可考虑逼其自收，但受花色首引限制，不能保证 |
| 敌方亮羊 | 想争羊 | 抢方块控制，阻止其落羊 |
| 敌方亮变 | 可能正分放大或陷阱 | 若其小计为负，塞猪/大红桃放大；若为正，阻止正分 |
| 敌方亮♥A | 红桃翻倍 | 若其全红概率低，让其收红桃放大负分；全红概率升高则优先破红 |

### 6.4 关键牌剩余分布与安全脱手

维护每张关键牌 `k` 的 `P(k ∈ p)` 与 `P(p 收 k)`。当剩余关键牌集合缩小，可确定脱手目标。

**示例**：♠Q 未出，黑桃未见牌只剩 ♠Q 和一张小黑桃 ♠x；东、西已缺黑桃，则 ♠Q 只能在南/北中；若自己持 ♠x，则 ♠Q 必在另一家。若另一家是敌方且接近 `-1000`、或亮变、或负分风险高，可出 ♠x 诱导其赢墩收猪；若另一家是同伴，避免让其收猪，除非同伴在走满贯。

**安全脱手矩阵**：

| 关键牌高概率归属 | 优先让谁收 | 避免让谁收 |
|---|---|---|
| 猪在敌方且敌方负分风险高/亮变 | 该敌方 | 同伴、自己 |
| 猪在敌方普通 | 敌方 | 同伴；自己单张亮猪可控时可接受 |
| 猪在同伴 | 敌方 | 同伴，除非同伴满贯路线 |
| 羊在己方控制范围 | 己方 | 敌方 |
| 变在搭档且搭档小计为负 | 自己截负 | 搭档 |
| 变在对手且对手小计为负 | 塞猪/大红桃给对手 | 给对手正分 |
| ♥A 在敌方且敌方全红概率低 | 让其收红桃放大负分 | 帮其全红 |
| ♥A 在敌方且全红概率升高 | 破红 | 继续喂红 |

## 7. 四方动态威胁模型

### 7.1 单家概率向量

对每家 `p`（含自己）维护：

| 字段 | 含义 |
|---|---|
| `pAllRed(p)` | 最终收齐 13 张红桃 |
| `pGrandSlam(p)` | 最终集齐猪、羊、变、全部红桃 |
| `pPig(p)` | 最终收猪 |
| `pSheep(p)` | 最终收羊 |
| `pTransformer(p)` | 最终收变 |
| `pTransformerNegative(p)` | 收变且变压器前小计为负 |
| `pTransformerTrap(p)` | 收变且同时收猪/大红桃（危险组合提示，不等于必然负分） |
| `pHeartA(p)` | 最终收♥A |
| `pEffectivePig(p)` | 满贯抑制后的有效猪风险 |
| `confirmed` | 已确定收下的关键牌、红桃张数、关键牌数 |
| `subtotalEstimate` | 已收牌 + 期望未来收牌的粗略小计（变压器前） |
| `confidence` | 概率置信度（来源、样本数、是否解析近似） |

### 7.2 团队级聚合

| 字段 | 含义 |
|---|---|
| `pAllRedAny` | 该队任一成员全红 |
| `pGrandSlamAny` | 该队任一成员满贯 |
| `maxAllRedProgress` | 已收红桃进度（其他家已收红桃时为 0） |
| `maxGrandSlamProgress` | 已收关键牌进度（其他家收走关键牌后失效） |
| `pPositive1000` | 该队最终小分 ≥ `+1000` |
| `pNegative1000` | 该队最终小分 ≤ `-1000` |
| `pPigAny` | 该队任一成员收猪 |
| `pSheepAny` | 该队任一成员收羊 |
| `pTransformerTrapAny` | 该队任一成员陷入变压器陷阱 |

**聚合规则**：

- 全红、满贯、猪、羊、变压器、♥A 在同一副牌中都是**唯一归属**事件，队员之间互斥。概率已归一的前提下，团队“任一成员”概率 = 两名队员概率之和，再截断到 `[0,1]`。
- 若概率来自独立近似导致和大于 1，应归一化或直接用采样频率统计；不得把同一事件重复计入。
- 不要因为“两人不可能同时完成”就拒绝相加；互斥事件的概率本来就应相加。
- `pTransformerTrapAny` 不是唯一归属分区，允许与其他事件重叠，不要强行归一。

### 7.3 一致性约束（单元测试必须覆盖）

| 约束 | 说明 |
|---|---|
| `Σ_p pPig = 1` | 猪未打出前必然属于某一家；打出后收猪者 1，其余 0 |
| `Σ_p pSheep = 1` | 同上 |
| `Σ_p pTransformer = 1` | 同上 |
| `Σ_p pHeartA = 1` | 同上 |
| `Σ_p pAllRed ≤ 1` | 一副牌最多一人全红 |
| `Σ_p pGrandSlam ≤ 1` | 一副牌最多一人满贯 |
| `pGrandSlam(p) ≤ pAllRed(p)` | 满贯必须包含全红 |
| `pTransformerNegative(p) ≤ pTransformer(p)` | 负向放大是收变的子事件 |
| `pTransformerTrap(p) ≤ pTransformer(p)` | 陷阱是收变的子事件 |
| `pEffectivePig(p) ≤ pPig(p)` | 满贯抑制猪后，有效猪概率下降 |
| `pPositive1000 + pNegative1000 ≤ 1` | 同一队不可能同时达到正负阈值 |
| 团队唯一归属事件 | 两名队员概率之和 = 团队概率，截断到 `[0,1]` |

### 7.4 概率来源与精度层级

| 来源 | 适用 | 精度 | 成本 |
|---|---|---|---|
| 已确定事实 | 已收牌、已打出、已亮且未打出的牌 | 0/1 | 0 |
| 解析近似 | 未见牌归属、关键牌持有、全红上界 | 中 | 极低 |
| 采样频率 | 收牌归属、全红、满贯、`±1000` | 高 | 中 |
| 末局精确 | 剩余 ≤5 墩时的条件概率 | 最高 | 高 |

统一约定：

- **fast**：只用已确定事实 + 解析近似；默认出牌与人类提示使用此档。
- **standard**：解析近似作为先验，采样频率作为主估计。
- **strong**：增加世界数，末局用精确搜索统计事件频率。
- 任何概率都必须来自公开信息；禁止用真实隐藏手牌直接算 0/1。

### 7.5 持有概率与收牌概率

未见牌集合：

```text
U = 全 52 张 − 自己手牌 − 所有已打出的牌
```

每家剩余容量：

```text
cap[p] = 13 − 已出牌数[p]
```

无花色约束时的超几何近似：

```text
P(某张未见牌 c 属于 p) ≈ cap[p] / Σ_q cap[q]
```

有缺门约束时按花色分配：设花色 `s` 的未见牌集合为 `U_s`，可持有该花色的玩家集合为 `Eligible_s`（未在该花色垫过牌），则：

```text
P(c ∈ p) ≈ E[分配给 p 的 s 花色张数] / |U_s|,  c ∈ U_s
```

精确值由采样器统计：

```text
P(c ∈ p) = (1/N) × Σ_world 1[c 在 world 中属于 p]
```

收牌概率：

```text
P(p 收 c) = (1/N) × Σ_world 1[c 最终进入 collected[p]]
```

解析近似（fast）：

```text
P(p 收 c) ≈ P(c ∈ p) × P(p 赢下 c 所在墩 | c ∈ p)
```

“赢下该墩”的能力由以下特征估计：

- 该花色剩余更大的牌数量；
- 该家该花色长度与控制；
- 该家是否可能缺门；
- 该墩是否已被更高牌压住；
- 该家是否愿意为该墩付出代价（策略层修正，不进入纯概率）。

### 7.6 全红模型

定义：某一家最终收齐全部 13 张红桃。

必要条件：

```text
该家已收红桃数 + 该家将收的剩余红桃数 = 13
```

硬事实：

- 若其他任何一家已收至少 1 张红桃，则该家永远不可能全红。
- 若某家已收 `h` 张红桃，则剩余 `13 − 已出红桃数` 张红桃必须全部由该家收下。
- 全红概率随剩余红桃数减少而单调上升，最后一张红桃归属确定时变为 0 或 1。

解析上界：

```text
pAllRedUpper(p) =
    1,   若 p 已收 13 张红桃
    0,   若其他任一家已收 ≥1 张红桃
    Π_{每张剩余红桃 h} P(p 赢下 h 所在墩),  否则
```

这个上界假设“每张剩余红桃独立”，实际存在强相关（同一花色控制、同一领出者），只能作为 fast 粗估。

采样估计（standard/strong）：

```text
pAllRed(p) = (1/N) × Σ_world 1[world 结束时 collected[p] 含 13 张红桃]
```

全红的可控杠杆：

| 杠杆 | 作用 |
|---|---|
| 红桃大牌（♥A/K/Q/J） | 决定能否赢下红桃墩 |
| 红桃长度 | 决定是否需要被迫垫红桃 |
| 其他家红桃缺门 | 缺门者垫牌时可能把红桃送给赢家 |
| 领出权 | 全红者需要持续获得领出或迫使红桃被领出 |
| 队友配合 | 队友停止收红桃、主动让红桃，可显著提高目标队友全红概率 |
| 对手破坏 | 对手只要赢下任意一墩含红桃的牌，即可破红 |

### 7.7 满贯模型

定义：某一家最终集齐猪、羊、变压器、全部 13 张红桃。

```text
pGrandSlam(p) ≤ pAllRed(p)
```

分解：

```text
pGrandSlam(p) = pAllRed(p) × P(p 收齐猪、羊、变压器 | p 全红)
```

按已确定收牌分阶段：

| 该家已收猪/羊/变张数 | 满贯概率主导因素 |
|---|---|
| 0 | 极低，需要同时收齐三张关键牌 + 全红 |
| 1 | 低，仍需要两张关键牌 + 全红 |
| 2 | 中，只差一张关键牌，且必须全红 |
| 3 | 等于全红概率（猪/羊/变已齐） |

硬事实：

- 其他任何一家已收红桃、羊、变压器或猪，该家满贯归零。
- 满贯者收猪不记负分，且不触发窝猪；走满贯路线的人不应因为“怕猪”而放弃，猪是必要拼图。
- “四张全亮”只影响对方画 1 头还是 2 头，不影响满贯是否成立，也不影响策略概率。

采样估计：

```text
pGrandSlam(p) = (1/N) × Σ_world 1[isGrandSlam(world.collected[p])]
pGrandSlamAny(team) = (1/N) × Σ_world 1[该队任一成员满贯]
```

#### 满贯画头数 vs 普通 `+1000` 画头数

满贯与普通 `+1000` 都会结束本局，但**给对方画几头不同**。设本队本局累计小分为 `SA`，对方为 `SB`：

| 本局结束方式 | 对方被画头数 | 条件 |
|---|---|---|
| 普通 `+1000` | 2 头 | `SA ≥ +1000` |
| 普通 `+1000` 且对方同时 `≤ -1000` | 3 头 | `SA ≥ +1000` 且 `SB ≤ -1000` |
| 满贯，该副四张关键牌非全亮 | 1 头 | 单人集齐猪、羊、变、13 张红桃 |
| 满贯，该副四张关键牌全亮（含自动亮） | 2 头 | 同上，且四张关键牌全亮 |

由此得到 `finish-race` 的核心比较：

1. **非全亮满贯 = 1 头 < 普通 `+1000` = 2 头**。当 `SA` 已接近 `+1000`、补足正分的来源可见且风险可控时，继续走普通正分路线通常严格更优，不应为了“能收满贯”而转入满贯。
2. **全亮满贯 = 2 头 = 普通 `+1000`**。画头数持平，但普通路线还可能因 `SB ≤ -1000` 升为 3 头，而且只需要在已有 `SA` 上补足正分，不必再冒险凑齐全部关键牌与 13 张红桃。
3. **满贯的独有价值**：它不依赖 `SA` 的绝对值，能在本队小分很低时直接结束本局；也能在本队接近 `-1000`、对方接近 `+1000` 或盘末必须锁胜时，作为“避免更坏结果”的手段。
4. **两条路线的风险不对称**：普通路线怕对方截走正分、自己反收负分、或在达到 `+1000` 前先触发本队 `-1000`；满贯路线怕关键牌被抢、红桃被破、以及凑齐前本局已被其他方式结束。
5. **不得把“满贯可成”当作无条件优先级**。决策时比较两条路线结束本局时的**画头差 × 达成概率 − 风险成本**；只有当普通路线不可达或风险过高、满贯的画头数严格更多，或满贯是避免本队 `-1000`、阻止对方 `+1000`、锁定盘胜的必要手段时，才优先满贯。画头数持平时默认普通路线，因为所需关键牌更少、被破坏风险更低。

`finish-race` 的默认进入条件建议为：`SA ≥ +700`，且剩余可见正分来源（羊、变压器、正分红桃、对手被迫收负等）足以把 `SA` 推过 `+1000`。阈值可配置；该情境只改变风险偏好，不改变满贯成立后的规则判定。

### 7.8 得猪、得羊概率

得猪：

```text
P(p 收猪) = (1/N) × Σ_world 1[PIG ∈ collected[p]]
```

风险因素：

- 是否持有 ♠Q；持有者风险最高，但可用大牌送出。
- 黑桃长度：越长越容易被逼收猪；越短越可能缺门垫牌。
- 黑桃大牌（♠A/♠K）：控制猪的流向。
- 是否亮猪：猪分翻倍，且全场知道猪在谁手里。
- 原始黑桃张数（仅自己可精确知道）：单张亮猪自收仅 `-200`，不窝猪。
- 其他家黑桃缺门：缺门者无法接猪，猪更可能回到持有者。

可接受猪的例外：

1. 走满贯：猪被抑制，收猪是必要拼图。
2. 保护搭档：搭档即将收变压器负向放大或更大负分，自己收猪可能是更小损失。
3. 阻断敌方满贯：敌方已收两张关键牌且全红概率高，自己收猪可破坏其满贯，`-100` 远小于“本局输 + 1–2 头”。
4. 单张亮猪自收：仅 `-200`，且不窝猪，风险可控，但仍不是首选。

得羊：

```text
P(p 收羊) = (1/N) × Σ_world 1[SHEEP ∈ collected[p]]
```

- 方块控制（♦A/K/Q）决定谁能赢下方块墩。
- 方块长度决定是否被迫跟牌。
- 羊是中张（J），上方还有 Q/K/A，因此“持有羊”不等于“能收羊”。
- 亮羊后价值翻倍，争夺优先级上升。

边际价值修正：

- 己方小分已接近 `+1000`：羊的边际价值下降，不必为羊破坏更重要的目标。
- 对方小分接近 `-1000`：给羊可能帮对方“回血”，需要计算净效应。
- 对方小分接近 `+1000`：阻止对方收羊优先级上升。

### 7.9 变压器陷阱概率

变压器有三种结果：

| 结果 | 条件 | 分数效果 | 策略含义 |
|---|---|---|---|
| 独拿 | 只有变压器，无猪/羊/红桃 | `+50`（未亮）/`+100`（亮） | 稳定小收益 |
| 正向放大 | 小计 > 0 | 小计 ×2/×4 | 收益放大，值得争 |
| 负向放大 | 小计 < 0 | 小计 ×2/×4 | 风险放大，必须避免 |

```text
pTransformerNegative(p) = P(p 收 ♣10 ∧ subtotalBeforeTransformer(p) < 0)
pTransformerTrap(p)     = P(p 收 ♣10 ∧ (p 收猪 ∨ p 收大红桃))
```

- 前者是真正的分数风险；后者是可解释的“危险组合”提示。
- “变压器陷阱”最终以**变压器前小计为负**为准，而不是只看猪/大红桃，因为变压器 ×2/×4 作用于小计；若该家同时收羊或正分红桃，小计可能为正，变压器反而变成收益放大器。
- 猪在满贯时被抑制，满贯路线下的“收猪”不构成陷阱。

危险示例（未亮变压器）：

```text
猪 -100 + ♥A -50 + 变压器 ×2 = (-150) × 2 = -300
```

若亮猪、亮变：

```text
窝猪 -400 + ♥A -50 + 变压器 ×4 = -1800
```

单副即可击穿 `-1000`，直接把本局送给对方。因此“变压器 + 猪/大红桃”不是普通负分，而是**可能直接决定本局胜负的尾部风险**。

对搭档的保护责任：

1. 截红桃：对手领红桃时，自己尽量抢下，避免搭档被迫收。
2. 截猪：黑桃局主动控制，必要时自己收猪，避免搭档收猪后被变压器放大。
3. 不领危险花色：不主动领搭档可能被迫赢的红桃/黑桃。
4. 放弃羊：若争羊会导致搭档收负分，优先保护搭档。
5. 反向操作：若搭档同时在全红/满贯路线，则**不要保护**，反而要继续喂红桃/关键牌，因为全红会反转红桃、满贯会抑制猪。

对对手的利用：

- 对手收变且小计为负 → 主动把猪/大红桃塞给对手，放大其负分。
- 对手收变且小计为正 → 避免给其正分，优先让其收负分或独拿。
- 对手收变且接近 `-1000` → 己方最有利，应保护该局面，不要帮对手“解套”。

### 7.10 `±1000` 概率

对每队维护：

- `pPositive1000`：本局最终小分 ≥ `+1000`（使对方被画头）。
- `pNegative1000`：本局最终小分 ≤ `-1000`（本队被画头）。

可用“当前小分 + 期望摆动”的 sigmoid 近似，或采样统计。二者都只能使用公开信息。`pPositive1000 + pNegative1000 ≤ 1`。

### 7.11 更新、平滑与迟滞

更新时机：

| 时点 | 更新 |
|---|---|
| 亮牌揭晓 | 关键牌归属硬信息、亮牌修正 |
| 每张牌打出 | 未见牌、缺门、关键牌剩余、收牌概率 |
| 每墩结算 | 收牌归属、全红/满贯/猪/羊/变状态、当前赢家 |
| 每副开始 | 重置副内概率，保留团队分数与猪头 |
| 本局结束 | 重置局内概率，更新盘级状态 |
| 盘终 | 更新盘级胜负与回溯摘要 |

硬事实增量：

- 已确定事件直接从概率变为 0/1。
- 某家已收红桃 → 其他家全红立即归零；若多家已收红桃，所有人全红归零。
- 某家已收任意关键牌 → 其他家满贯归零；某家已收齐猪、羊、变 → 该家满贯退化为全红。
- 某家已收猪 → 该家 `pPig=1`，其他家 `pPig=0`。

平滑：

```text
p_smooth = (count + α) / (N + 2α),  α 默认 0.5
p_final   = λ × p_sample + (1 − λ) × p_prior
λ         = min(1, N / 32)
```

迟滞（推荐；当前 fast 层尚未实现）：

| 模式 | 进入 | 退出 |
|---|---|---|
| `own-allred` / `partner-allred` | 60% | 45% |
| `break-opp-allred` | 40% | 25% |
| `own-slam` / `partner-slam` | 35% | 20% |
| `break-opp-slam` | 25% | 15% |
| `protect-transformer` | 40% | 25% |
| `pig-evade` | 50% | 35% |

迟滞状态在同一副内保持，跨副重置。若未实现迟滞，必须保证模式阈值本身有足够间隔，避免每手抖动。

### 7.12 概率 → 模式

| 模式 | 触发条件（默认） | 目标 | 典型动作 |
|---|---|---|---|
| `normal` | 无其他模式 | 平衡期望 | 常规启发式 |
| `own-allred` | 己方某人 `pAllRed` > 60% 或已收 ≥8 张且其他家未收红桃 | 服务全红 | 让红桃、停止争红桃、保护目标队友 |
| `partner-allred` | 搭档 `pAllRed` > 60% 或进度威胁 | 服务搭档全红 | 主动喂红桃、替搭档挡对手破红 |
| `break-opp-allred` | 敌方某人 `pAllRed` > 40% 或已收 ≥8 张 | 破红 | 赢下任意含红桃的墩、逼其垫红桃 |
| `own-slam` | 己方某人 `pGrandSlam` > 35% 或已收猪/羊/变三张 + 6 张红桃 | 服务满贯 | 让关键牌、让红桃、不避猪 |
| `partner-slam` | 搭档 `pGrandSlam` > 35% | 服务搭档满贯 | 喂关键牌/红桃，替其挡枪 |
| `break-opp-slam` | 敌方某人 `pGrandSlam` > 25% 或已收猪/羊/变三张 + 6 张红桃 | 破坏满贯 | 抢猪/羊/变、破红，必要时自己收猪 |
| `heart-a-disposal` | 自己持 ♥A + 少量小牌、自己全红/满贯概率低 | 处置 ♥A | 能垫给同伴则垫；不能则前期落墩封顶 |
| `protect-transformer` | 搭档 `pTransformerNegative` > 40% 且未走全红/满贯 | 保护搭档 | 截红桃/截猪、不领危险花色 |
| `exploit-transformer` | 对手 `pTransformerNegative` > 40% | 放大对手负分 | 塞猪/大红桃给对手 |
| `pig-evade` | 己方 `pPigAny` > 50% | 避猪 | 把黑桃控制让给对手、避免领黑桃 |
| `pig-maintain` | 对手 `pPigAny` > 60% | 保持对手猪压力 | 不主动领黑桃帮其解套 |
| `sheep-contest` | 己方 `pSheep` < 40% 且争夺成本低 | 争羊 | 用方块控制抢羊 |
| `danger-zone` | 己方 `pNegative1000` > 30% | 防守 | 强规避负分，放弃边缘收益 |
| `finish` | 己方 `pPositive1000` > 50% | 进攻 | 主动施压，争取画头 |
| `finish-race` | 己方 `SA ≥ +700` 且可见正分可补到 `+1000` | 优先普通 `+1000` | 比较满贯与普通画头数（7.7），不为满贯牺牲 2/3 头路线 |
| `high-value-endgame` | 只剩高价值正分目标、负风险低 | 留大牌争正分 | 保留大牌，争取羊/正向变压器 |
| `high-risk-endgame` | 只剩高风险负值、正收益低 | 留小牌脱手 | 优先脱手大牌，保留小牌 |

阈值可配置；默认值只用于 fast 层，标准/强化档可用采样概率替代。

> 表中 `danger-zone` / `finish` / `finish-race` 是为了兼容当前实现的命名；语义上它们属于第 8/9 章的“分数情境层”，不参与第 9.1 节的固定威胁模式顺位。`high-value-endgame` / `high-risk-endgame` 属于残局留牌模式，参与固定顺位。

## 8. 分数情境与盘级效用

### 8.1 分数情境与威胁模式正交

分数情境描述“风险偏好”；威胁模式描述“服务谁/破坏谁”。两者不得混成一个固定优先级列表。

| 情境 | 条件示例 | 策略倾向 |
|---|---|---|
| `normal` | 双方小分接近 0，非临界 | 平衡，优先正期望 |
| `protect-lead` | 己方总猪头明显领先，或本局小分领先且接近结束 | 降低方差，避免送猪/送红桃，优先安全垫牌 |
| `chase` | 己方总猪头落后，或本局小分落后 | 提高方差，争羊/变压器/全红，必要时赌博性抢分 |
| `danger-zone` | 己方小分接近 `-1000` | 强规避负分，宁可放弃羊，也不让己方收猪/红桃 |
| `finish` | 己方小分接近 `+1000` 或对方接近 `-1000` | 主动施压，争取触发画头 |
| `finish-race` | 己方 `SA ≥ +700`，且可见正分来源足以补到 `+1000` | 优先普通 `+1000` 路线而非满贯；先比较两条路线的画头数（见 7.7），不为满贯牺牲已可达的正分路线 |
| `slam-watch` | 自己或搭档已收/可能收猪、羊、变三张 + 大量红桃 | 评估满贯路线，优先关键牌；但 `finish-race` 生效时先做画头数比较 |
| `allred-watch` | 自己或搭档已收 ≥10 张红桃 | 评估全红反转，决定继续收还是止损 |
| `last-deal` | 本局最后一副或盘末关键副 | 按盘级胜负裁决调整，不只看本副 |

### 8.2 盘级效用

从己方视角看的效用，越大越好：

```text
U_match = −(己方总猪头 − 对方总猪头)
```

若本局结束：

```text
+ roundWinBonus     // 本局胜，尤其 8 局制回溯有用
− roundLossPenalty
```

本局的不同结束方式会改变画头差，因此比较路线时必须落到同一终局效用，而不能只看“本局是否胜”：

- 普通 `+1000` 通常给对方新增 2 头（对方同时 `≤ -1000` 时 3 头）。
- 满贯给对方新增 1 头（该副四张关键牌非全亮）或 2 头（全亮）。
- 若其他项相同，选择**画头差更大且达成概率更高**的路线；画头数持平时，选择所需关键牌更少、被破坏风险更低的一条。
- `finish-race` 下尤其如此：满贯带来的“本局胜”与普通 `+1000` 带来的“本局胜”在 `roundWinBonus` 上相同，真正拉开差距的是画头差与达成概率。

若本盘结束：

```text
+ matchWinBonus / − matchLossPenalty
```

若进入 5 局制突然死亡或 8 局制同猪头裁决，按真实规则给终局 ±大值。最终终局判断必须调用真实 `scoreDeal()`、`evaluatePigHeads()`、`resolveMatch()`，不得另写近似计分。

### 8.3 局内中间态效用

在 rollout 尚未结束时，用平滑势能避免短视：

```text
U_round_potential =
    w_diff      * (SA − SB) / 1000
  − w_own_neg   * max(0, −SA / 1000)   // 己方负分越深，风险越大
  − w_opp_attack* max(0,  SB / 1000)   // 对方正分越高，对方越接近 +1000
  + w_own_attack* max(0,  SA / 1000)   // 己方正分越高，己方越接近 +1000
  + w_opp_neg   * max(0, −SB / 1000)   // 对方负分越深，对方越接近 −1000
```

建议初值：

| 权重 | 建议初值 | 含义 |
|---|---|---|
| `w_diff` | 1.0 | 基础分差 |
| `w_own_neg` | 2.0 | 己方负分临界风险 |
| `w_opp_attack` | 2.0 | 对方正分进攻风险 |
| `w_own_attack` | 1.2 | 己方正分进攻收益 |
| `w_opp_neg` | 1.2 | 对方负分收益 |

这些权重只用于 rollout 内部中途评估；最终仍以真实终局计分为准。

> 变压器会放大拿到它的玩家个人分，因此本副/本局总分不是严格零和。`U_round_potential` 只是中途近似，任何终局判断都必须以真实团队分为准，不能假设“双方总分恒定”。

### 8.4 防重复计分

- `U_round_potential` 只负责“小分接近 `±1000`”的平滑势能。
- 全红/满贯/猪/羊/变压器陷阱由第 7 章 `ThreatModel` 单独进入候选评分。
- 终局由 `scoreDeal()` 统一结算。
- 满贯与普通 `+1000` 是互斥的本局结束方式，只能按实际触发的一种结算画头；不得同时预支“满贯 1/2 头”和“普通 `+1000` 2/3 头”。`finish-race` 比较的是两条虚拟路线的期望，不是叠加收益。
- 同一事件不得在“本墩分数”“势能”“威胁项”“终局效用”中重复计分；实现时必须区分各层职责。

## 9. 模式优先级与冲突消解

### 9.1 三层决策，而不是一张固定顺位表

1. **硬约束层**：合法性、信息边界、规则。任何模式都不得违反。
2. **终局/分数情境层**：若一手牌可能立即触发己方 `-1000`、对方 `+1000`、满贯或盘终，先用终局效用比较；分数情境决定风险偏好，可覆盖非终局模式。
3. **威胁模式层**：在非终局局面中，按以下默认顺位决定“服务谁/破坏谁”，最终仍由期望效用比较。

默认威胁模式顺位：

```text
1. 己方/搭档满贯（own-slam / partner-slam）；若 `finish-race` 生效，先按 7.7 比较满贯与普通 `+1000` 的画头数
2. 破坏敌方满贯（break-opp-slam）
3. 己方/搭档全红（own-allred / partner-allred）
4. 破坏敌方全红（break-opp-allred）
5. ♥A 处置（heart-a-disposal）
6. 保护搭档变压器（protect-transformer）
7. 利用对手变压器（exploit-transformer）
8. 避猪 / 保持对手猪压力（pig-evade / pig-maintain）
9. 残局留牌（high-risk-endgame / high-value-endgame）
10. 争羊（sheep-contest）
11. 常规（normal）
```

`danger-zone` / `finish` / `finish-race` 属于第 2 层，不参与上面的固定顺位；它们通过风险权重和终局效用影响所有模式。

### 9.2 冲突消解规则

1. **满贯 > 全红**：满贯包含全红，且直接赢本局。
2. **己方事件 > 阻止敌方事件**：同等概率下优先成事，而不是破坏。
3. **高概率事件 > 低概率事件**：但满贯/全红杠杆大，允许在较低概率时提前防守。
4. **确定性小损失 < 不确定性大损失**：愿意用 `-100` 的确定损失，换取避免 `-400` 或本局失败。
5. **不为小概率事件牺牲确定性收益**：概率低于阈值时只做低成本保留，不豪赌。
6. **保护不是无条件**：搭档已走全红/满贯时，不保护变压器，改为喂红桃/关键牌。
7. **破红/破满贯不是无条件**：若破红会导致己方立即 `-1000`，必须比较“敌方全红/满贯收益”与“己方画头”的终局效用。
8. **满贯不自动高于普通 `+1000`**：本队 `SA` 已接近 `+1000`（默认 `SA ≥ +700` 且可见正分足以补足）时，先比较两条路线结束本局给对方画的头数。非全亮满贯 1 头通常劣于普通 `+1000` 的 2 头；全亮满贯 2 头与普通 2 头持平，但普通路线还可能因对方 `≤ -1000` 升为 3 头，且不必再凑齐全部关键牌与 13 张红桃。只有普通路线不可达、风险过高，或满贯是避免本队 `-1000`、阻止对方 `+1000`、锁定盘胜的必要手段时，才优先满贯。详见 7.7 与 8.1 `finish-race`。

示例：

- 若“破红”需要自己吃 `-50`，而敌方全红价值 `+200`（亮♥A 时 `+400`）并可能通向满贯，则破红通常正期望。
- 若“保护搭档变压器”需要自己吃猪 `-100`，而搭档避免 `-400` 窝猪 + ×4 放大，则保护通常正期望。
- 若“服务搭档满贯”需要自己放弃羊 `+100`，而满贯价值“本局胜 + 1–2 头”，则让羊通常正期望；但若本队 `SA` 已达 `+700` 以上、普通路线可到 `+1000` 且满贯非全亮（只画 1 头），则不应为满贯让出这条 2 头路线。

## 10. 通用出牌原则

1. **常规不想收全红/满贯时**：优先出“中间安全牌”，保留两头——大牌用于控制/得羊/破全红/破满贯，小牌用于安全跟牌/垫牌。若某花色 5 张以上，可保留最小张（2、3）作为安全张，同时保留大牌控制。  
   **若己方目标转为全红/满贯**：改为出小牌、留控制张，尽量保留能赢红桃/关键墩的大牌。
2. **无得猪危险时跑猪圈**：在黑桃安全、合法、敌方亮猪且自己有控制时，可领 ♠A/♠K 跑猪圈，逼猪现身或逼亮猪者自收；但受花色首引限制影响，**不能保证**第一墩就逼出亮猪。**想收满贯时不要因为怕猪而放弃**；猪是满贯拼图，但也不要在不能确保收猪时过早浪费黑桃控制张。
3. **需要卖猪/♥A/羊时出短套**：短套领出可制造缺门，后续垫负分。但若同伴亮羊/同伴困难，应改出长套帮同伴卖；若敌方全红/满贯威胁高，优先破坏。
4. **同伴困难或亮羊时出长套**：长套建立控制，帮同伴卖出猪/红大牌或领羊。但不要把负分塞给同伴；同伴若在走全红/满贯，则改为喂红桃/关键牌。
5. **想收满贯先出小牌留控制**：满贯路线下猪被抑制，不因“怕猪”放弃；关键牌让给满贯者，红桃控制保留，搭档负责挡对手抢关键牌。
6. **默认不盖压搭档的红桃大牌**：自己全红概率很低、不计划收全红时，禁止随便盖压同伴打出的红桃大牌，避免抢同伴红桃墩、破坏全红计划。例外：搭档有变压器负向放大风险、需要破敌方全红/满贯、或本墩负分必须截断。
7. **同伴危险时保留援助牌**：同伴极易吃猪/大量红桃负分时，不能只顾自己甩负分自保；应保留后手牌作为援助。
8. **信息隐藏**：不无谓暴露关键控制张；但为配合同伴可让公开出牌本身传递意图。不得依赖约定暗号。
9. **分数情境优先于机械原则**：领先降方差、落后提方差、己方 `-1000` 先止损、对方 `-1000` 主动施压。

## 11. 领出策略

### 11.1 本副首墩：无任何亮牌

| 自身情况 | 首墩动作 | 说明与例外 |
|---|---|---|
| 无猪、无猪圈；或有 1 个猪圈但黑桃 ≥4 | 可考虑出黑桃非亮牌拱猪 | 表明自己无猪/无猪圈，逼猪现身；若搭档已亮猪、敌方满贯威胁高、或己方 `-1000` 风险高，改为安全短套/长套 |
| 有猪或黑桃短且多猪圈，有困难 | 出较短花色 | 让同伴从该花色帮自己卖猪/♥A/红桃；避免主动拱猪反被送猪 |
| 短套是红桃且同伴可能收 | 谨慎分红 | 先判断同伴是否全红/是否需要红桃；不要无谓破同伴全红 |
| 自己亮猪 | 不出受限制的亮猪；可出黑桃非亮牌或短套 | 花色首引限制期间，亮猪不能领出；唯一亮牌兜底例外见 2.7 |

### 11.2 同伴亮猪

- 一般出**长套**，帮同伴建立控制、制造断门，让同伴把猪垫给敌方。
- 自己黑桃短时，可领黑桃非亮牌逼猪现身，但不要自己收猪。
- 若敌方全红/满贯概率高，优先破坏，不机械帮卖猪。
- 若自己 `-1000` 风险高，不为了帮同伴卖猪而主动收负分。

### 11.3 同伴亮♥A

- 自己持小红心或 `♥Jxx`，可出 ♥J 或小红心，观察同伴是否继续收红桃；这不是约定信号，只是公开出牌。
- 同伴全红概率升高 → 喂红桃、让红桃墩。
- 敌方全红/满贯威胁升高 → 优先破红，不无谓送红桃给敌方。
- 不要因为同伴亮♥A 就把大红桃送给敌方收。

### 11.4 同伴亮羊

- 自己有含 ♦A 的两张以上：可出方块中间大小，第二轮用 ♦A 领羊；这是公开牌路上的配合，不是暗号。
- 若自己不是本副首墩领出者，一旦上手可优先出方块表示有 ♦A/控制；若该副已出过方块，则该信息已部分公开，按实际牌路调整。
- 自己没有大方块，但有其他长套和上手张：出长套，准备上手后领羊。
- 若敌方正分接近 `+1000`，羊的边际价值下降，优先阻止敌方而非机械争羊。

### 11.5 自己亮羊且有 ♦A

- 可先拔 ♦A，公开表明自己有方块控制；同伴可据此判断能否安全落羊。
- 同伴若只有 ♦Q，应视情况扔掉 ♦Q，让亮羊者判断能否安全落羊；若持 ♦Q 者已得变压器，另当别论（避免变压器负放大）。
- 若同伴无 ♦K、敌方全红/满贯威胁高，优先破坏/防守，不机械落羊。

### 11.6 敌方亮猪

- 可出黑桃非亮牌拱猪；有猪圈时可在合适时机领 ♠A/♠K，逼亮猪者自收窝猪。
- **注意**：花色首引限制期间，亮猪不能跟牌/领出；第一墩黑桃通常不能直接逼出亮猪。只有在限制解除、对方无其他黑桃、或唯一亮牌例外时，才可能逼其自收。不能把“窝猪”当成确定结果。
- 若自己黑桃短/无控制，不强行拱猪，改出短套让同伴控制，避免反被敌方送猪。
- 若敌方亮猪者小计为负且有变压器，拱其自收可放大负分，优先级上升。

### 11.7 敌方亮羊/亮变/亮♥A

| 敌方亮牌 | 首墩/前几墩倾向 |
|---|---|
| 亮羊 | 抢方块控制，阻止其落羊；自己有 ♦A/K 可领方块 |
| 亮变 | 若其小计为负，准备塞猪/大红桃；若为正，阻止其收正分 |
| 亮♥A | 判断其全红概率：低则让其收红桃放大负分；高则优先破红 |

### 11.8 非本副首墩领出

按优先级：

1. **安全低牌**：非计分、低点数、不送猪/红桃。
2. **短套卖负**：需要卖猪/♥A/红桃时，领短套制造缺门。
3. **长套帮同伴**：同伴困难/亮羊/亮猪时，领长套建立控制，帮其卖牌。
4. **逼缺门**：敌方缺门时领该花色，逼其垫牌；但不要把负分逼给同伴。
5. **关键牌保护**：不轻易领自己需要保留的 A/K/Q；不领搭档变压器风险花色。
6. **分数情境**：
   - 己方领先/总猪头领先：降方差，安全第一；
   - 己方落后/总猪头落后：提高方差，争羊/变/全红；
   - 己方接近 `-1000`：绝不主动领红桃/猪门；
   - 对方接近 `-1000`：主动领红桃/猪门施压；
   - 对方接近 `+1000`：阻止其正分，必要时自己收正分。
7. **威胁模式**：
   - 搭档全红/满贯：领搭档能赢的花色，喂红桃/关键牌；
   - 敌方全红：领红桃逼其赢，或领其缺门逼其垫红桃；
   - 敌方满贯：领黑桃/方块/梅花逼关键牌提前暴露；
   - 搭档变压器负风险：不领红桃/黑桃，避免搭档被迫赢；
   - 己方得猪风险高：不领黑桃，把控制让给对手；
   - 对手得猪风险高：保持黑桃压力，不帮其解套。

### 11.9 同伴亮羊但自己无上手张

- 非本副首墩后持续帮同伴打方块，让同伴自己落羊。
- 若敌方全红/满贯威胁高，改为破红/抢关键牌，不机械帮羊。

### 11.10 无敌方全红/满贯风险时的负分处理

- 手中剩较多负分张：出大牌避免上手，尽快把负分甩给对手；但**同伴得变压器需保护时除外**。
- 反之，若己方需要得羊/控制敌方全红/满贯：保留大牌，不轻易扔掉控制张。
- 搭档全红/满贯路线：不按“避免上手”处理，改为喂牌/让墩。

## 12. 跟牌策略

### 12.1 先判断当前赢家

| 当前赢家 | 策略 |
|---|---|
| 搭档 | 不无谓盖压；本墩正分让搭档收；本墩负分且搭档有变压器负风险/非全红满贯，考虑接手 |
| 对手 | 正分/关键牌能争则争；负分不抢，优先垫负给对手；不能赢则甩负 |
| 自己 | 已赢则判断是否保赢；通常一墩只需最大牌，不重复浪费 |
| 未知（后面还有人） | 估计剩余玩家胜率，不只看当前最大牌 |

### 12.2 跟牌细则

1. 有领出花色必须跟；花色首引限制下受限制亮牌不能跟，除非手中该花色仅剩这一张亮牌。
2. 搭档赢墩：
   - 不无谓盖压；尤其不随便盖压搭档的红桃大牌（自己不在全红路线时）。
   - 若自己盖压能防止对手反超且本墩负分危险，可盖。
   - 搭档全红/满贯路线：让红桃/关键牌给搭档，不抢。
3. 对手赢墩：
   - 本墩有羊/变/正分：尽量争；
   - 本墩有猪/红桃负分：不抢，优先让对手收；
   - 不能赢：优先垫负分给对手，避免垫给搭档。
4. 最后一家：
   - 当前墩结果已知，直接按“赢/不赢”的团队收益选择；
   - 能赢且收益正 → 赢；不能赢 → 选对团队最有利的垫牌。
5. 缺门垫牌：
   - 对手赢墩 → 优先垫猪/红桃/危险负分；
   - 搭档赢墩 → 优先垫非计分/安全牌；搭档全红/满贯则喂红桃/关键牌；
   - 自己赢墩 → 不垫负分给自己。
6. 跟牌大小作为信息：
   - 跟大牌可能表示欢迎继续/有控制；
   - 跟最小可能表示不欢迎/无控制/请换花色；
   - 但必须结合已知缺门与剩余张数，不机械解读，也不当成约定信号。

## 14. 候选评分与决策

### 14.1 评分维度

对每个合法牌 `c` 计算：

```text
score(c) =
    w_trick    * 本墩团队收益(c)          // 谁收、收什么、是否关键牌
  + w_future   * 未来控制/领出权收益(c)
  + w_key      * 关键牌处理收益(c)        // 猪/羊/变/♥A
  + w_score    * 分数情境收益(c)          // ±1000、猪头差、最后一副
  + w_threat   * 威胁模式收益(c)          // 全红/满贯/变压器/避猪/争羊
  - w_risk     * 风险惩罚(c)              // 送同伴负分、帮敌方全红/满贯
  - w_leak     * 信息泄露惩罚(c)          // 无谓暴露控制张/关键张
  + tie(c)                              // 确定性平局扰动
```

### 14.2 量纲与权重

- `本墩团队收益`、`未来控制`、`关键牌处理`、`分数情境`、`威胁模式` 统一折算为“团队分等价”的近似量纲；概率项必须先乘以收益杠杆再进入评分。
- 权重是相对量，不是绝对规则。建议初值：

| 权重 | 建议初值 | 说明 |
|---|---|---|
| `w_trick` | 1.0 | 本墩分 |
| `w_future` | 0.8 | 未来控制/领出权 |
| `w_key` | 1.2 | 关键牌处理 |
| `w_score` | 1.5 | 分数情境 |
| `w_threat` | 1.8 | 威胁模式；接近画头/满贯/全红时提高 |
| `w_risk` | 1.0 | 风险惩罚 |
| `w_leak` | 0.3 | 信息泄露；只作小幅修正 |

- 权重必须通过大样本自对弈校准，不得只针对少量种子调参。
- 当前 fast 层实现使用“本墩值 + 1.35×威胁值 + 搭档协同 + 分数情境 + 残局留牌/一步路线 + ♥A 处置 + 安全性 + 微小确定性扰动”的等价结构，具体系数以实现为准；本表是规范建议初值，不是对当前代码的逐项复刻。

### 14.3 防重复计分

- 本墩收益只计当前墩的基础分与收牌归属。
- 关键牌收益只计“这张牌最终被谁收”的结构性价值。
- 威胁模式收益只计“这一手如何改变全红/满贯/猪/羊/变压器陷阱概率”。
- 分数情境只计“小分接近 `±1000`、猪头差、最后一副”的风险偏好。
- 终局效用只由真实计分/盘终函数结算。
- 同一事件不得在多层重复加权；若实现中必须重叠，应在测试中用消融实验确认没有双计。

### 14.4 决策伪代码

```ts
function choosePlay(obs) {
  if (obs.legalCards.length === 1) return obs.legalCards[0];

  const knowledge = updatePublicKnowledge(obs);
  const threat = updateThreatProbabilities(obs, knowledge);
  const context = classifyScoreContext(obs);
  const modes = resolveModes(threat, context); // 含迟滞（若实现）

  let best = obs.legalCards[0], bestScore = -Infinity;
  for (const card of obs.legalCards) {
    const trick = evaluateTrickOutcome(obs, card, knowledge, threat);
    const future = evaluateFutureControl(obs, card, knowledge);
    const key = evaluateKeyCards(obs, card, knowledge, threat);
    const scoreCtx = evaluateScoreContext(obs, trick, key, context);
    const threatDelta = evaluateThreatDelta(obs, card, threat, modes, trick, key);
    const risk = evaluateRisk(obs, card, knowledge, threat);
    const leak = evaluateInformationLeak(obs, card, knowledge);

    const total =
      1.0 * trick.teamDelta +
      0.8 * future.teamDelta +
      1.2 * key.teamDelta +
      1.5 * scoreCtx.teamDelta +
      1.8 * threatDelta.teamDelta -
      1.0 * risk.penalty -
      0.3 * leak.penalty +
      deterministicTieBreak(obs, card);

    if (total > bestScore) { bestScore = total; best = card; }
  }
  return best;
}
```

### 14.5 平局与可复现

- 平局优先：安全性高 > 信息泄露少 > 不违反模式目标。
- 若仍平局，使用 `hash(deal.seed, deal.index, trickIndex, self, card)` 的确定性扰动，不得使用不可复现的 `Math.random()`。
- 固定公开观察 + 固定种子 → 固定出牌；同公开信息不同隐藏手牌 → 同决策。

### 14.6 标准/强化档：PIMC 与末局搜索（可选）

若启用 standard/strong：

1. 从公开信息采样 N 个与硬约束一致的可能世界；
2. 用同一批世界估计四方概率与模式；
3. 对每个候选牌在相同世界上 rollout；
4. 剩余 ≤5 墩时在采样世界内做精确搜索；
5. 终局调用真实计分/盘终函数；
6. 超时/异常回退到 fast 启发式；
7. 全程只接触采样世界，不接触真实隐藏手牌。

硬约束：张数、不重复、亮牌归属、缺门、已出牌、自己手牌固定、合法出牌函数真实。

采样数量建议：

| 难度 | 世界数 N | 说明 |
|---|---|---|
| fast | 0 | 纯概率启发式 |
| standard | 32–64 | 默认 |
| strong | 128–256 | 可选 |
| 末局精确 | 16–32 | 剩余 ≤5 墩 |

## 15. 信息隐藏与可解释性

### 15.1 信息隐藏

- 不无谓暴露关键控制张；但为配合同伴可让公开出牌本身传递意图。
- 不通过出牌泄露自己持有猪/变/♥A，除非能换来更大团队收益。
- AI 不依赖约定暗号；人类若自行约定，AI 不假设其存在。
- 正式对局中不向人类玩家展示其他三家的内部概率或未公开手牌推断，避免信息泄露或不必要干扰；南家自己的推荐解释只复用本人回合的公开观察、候选评分与团队概率。

### 15.2 调试与复盘

开发/复盘可输出：

```ts
interface ThreatDebug {
  seat: Record<Position, SeatThreat>;
  own: TeamThreat;
  opp: TeamThreat;
  modes: ThreatMode[];
  thresholds: Record<ThreatMode, { enter: number; exit: number; active: boolean }>;
  sources: Record<string, 'prior' | 'sample' | 'exact'>;
  worlds: number;
  elapsedMs: number;

```

UI 建议：

- 复盘面板显示四方概率条；
- 高亮当前模式（如“保护搭档变压器”）；
- 显示概率变化原因（“西家收 1 张红桃 → 东家全红归零”）；

- 南家出牌推荐可用悬停浮层展示标题、理由与公开推断；解释层入口为 `src/core/aiExplain.ts`，复用 `rankCandidates` 的评分明细，不额外读取隐藏信息。

## 16. 测试与验收

### 16.1 P0：合法性与信息边界

| 测试 | 内容 |
|---|---|
| 合法性 | 任意观察下返回的牌都在 `legalCards` 中；首引限制、唯一合法牌、兜底领出正确 |

| 确定性 | 固定观察 + 固定种子 → 固定出牌；不得使用不可复现随机 |
| 无死锁 | 任意合法局面都能返回一张牌；兜底领出不会死锁 |

### 16.2 P0：概率一致性

| 测试 | 内容 |
|---|---|
| 归属和 | `Σ pPig = 1`、`Σ pSheep = 1`、`Σ pTransformer = 1`、`Σ pHeartA = 1`（未收时） |
| 全红/满贯 | `Σ pAllRed ≤ 1`、`Σ pGrandSlam ≤ 1`、`pGrandSlam ≤ pAllRed` |

| 对方 `-1000` 机会 | 主动送猪/红桃，防其回血 |
| 己方 `+1000` 机会 | 争正分，优先普通 `+1000`；若同时在满贯路线，先按 7.7 比较画头数；防对方破坏 |
| 己方 `SA ≥ +700` 且满贯可成 | 非全亮满贯只画 1 头，优先普通 `+1000` 的 2 头路线；全亮满贯 2 头时才比较达成概率与风险；不为满贯放弃已可达的 `+1000` |
| 普通 `+1000` 不可达/风险过高，或满贯可避免己方 `-1000` | 仍争满贯；用终局画头差与达成概率比较，不因“满贯只画 1/2 头”而放弃必要防守 |
| 对方 `+1000` 风险 | 阻止其收羊/变/正分红桃；必要时自己收正分 |
| 最后一副/盘末 | 按盘级效用选择，接受本副小亏换盘胜 |
| 固定观察+固定种子 | 出牌确定、可复现；隐藏手牌不同但公开信息相同 → 同决策 |

### 16.4 P1：计分与赛制边界

| 测试 | 内容 |
|---|---|
| 全红 | 13 张红桃反转；亮♥A 后 `+400`；其他家收 1 张红桃即破红 |
| 满贯 | 以最终收牌判定；非全亮画 1 头、全亮画 2 头；不生成正式个人分；不触发窝猪；本局立即结束 |
| 窝猪 | 亮猪自收 `-400`；单张黑桃亮猪自收免窝猪 `-200`；自动亮猪自收算窝猪 |
| 变压器 | 独拿 `+50/+100`；非独拿 ×2/×4；零小计仍零；窝猪+亮变 `-1600` |
| 画头表 | 6.2 全组合正确；正分高使对方被画头，负分低使本队被画头；画头后小分清零 |
| 6.4/6.5 | 新增猪头相同裁决；20 副上限兜底；`roundWinner/roundLoser/roundResult` 正确 |
| 5/8 局制 | 5 局加赛突然死亡；8 局同猪头最后一局输者负、回溯、判和 |
| 满贯后流程 | 本局立即结束，不进入下一副；新局按 ♠3 规则 |

### 16.5 P2：模拟、强度与性能

- 1000 副全 AI 对局：无非法出牌、无死锁、52 张牌全部收完。
- 全托管连续多局进入盘终；覆盖 5/8 局制、加赛、单局上限。
- 覆盖满贯、全红、窝猪、变压器独拿/非独拿、零小计等极端结算。
- 旧 AI vs 新 AI 自对弈 ≥500 副，交换座位，指标：总猪头差、本局胜率、平均本副团队小分、画头/满贯/全红次数、敌方全红/满贯被破坏率、搭档变压器负向放大发生率、概率校准。
- 性能：fast P95 ≤ 20ms；standard P50 ≤ 150ms、P95 ≤ 300ms；strong P95 ≤ 800ms。
- 降级：超时/异常回退 fast，不返回非法牌。

### 16.6 验收门槛

| 级别 | 门槛 |
|---|---|
| P0 | 合法性、信息边界、确定性、概率约束全部通过；否则不得合入 |
| P1 | 关键行为场景通过；满贯/全红/窝猪/变压器/画头/赛制边界通过 |
| P2 | 大样本自对弈稳定优于旧基线；概率校准不劣于常数基线；性能达标 |

## 17. 风险与限制

| 风险 | 说明 | 缓解 |
|---|---|---|
| PIMC 策略融合 | 多个采样世界平均后可能选出“对每个世界都不最优”的牌 | 增加世界数、使用 ISMCTS、对候选做稳健性检查 |
| 采样偏差 | 均匀采样忽略对手出牌倾向 | 后续加入重要性权重/对手模型 |
| 计算量 | 13 墩 × 多世界 × 多候选可能很慢 | 时间预算、末局精确、启发式兜底、Worker |
| UI 阻塞 | 同步搜索卡住主线程 | 人类提示用 fast；AI 用 setTimeout/Worker |
| 隐藏黑桃张数 | 对手亮猪时无法知道是否单张 | 采样该变量；默认非单张；只影响窝猪概率 |
| 概率误估 | 采样偏差导致全红/满贯概率系统性偏高或偏低 | 平滑、向先验收缩、Brier score 校准、迟滞 |
| 概率自证 | AI 按概率行动后，采样世界被自身策略污染，导致概率失真 | 概率估计与 rollout 分离；估计阶段使用中性策略 |
| 模式抖动 | 概率在阈值附近反复穿越，导致策略摇摆 | 进入/退出双阈值 + 同一副内保持；未实现时加大阈值间隔 |
| 过度保护 | 为保护搭档变压器而放弃过多正分 | 用期望效用比较，不设无条件保护 |
| 保护与全红冲突 | 搭档走全红时仍机械保护，反而破坏全红 | 优先级：满贯 > 全红 > 变压器保护 |
| 过度拟合 | 权重只针对少量种子调优 | 大样本自对弈、交叉验证 |
| 规则变化 | 未来计分/赛制变化 | 终局统一调用真实 `scoreDeal`/`evaluatePigHeads`/`resolveMatch` |
| 信息边界回归 | 后续开发者误传全量状态 | 类型白名单 + 构造测试 + code review |
| 暗中泄露 | 调试日志、回放、UI 提示意外暴露隐藏牌 | 正式对局关闭内部概率展示；日志脱敏 |
| 信号误解 | 把软信息当成约定信号 | 第 4.5 条无信号原则；只作概率修正 |

### 17.1 明确不做“绝对最优”

完整信息不完全条件下的最优策略是信息集博弈均衡，计算量远超本地单机需求。本规范追求：

- 合法；
- 信息边界正确；
- 比现有启发式明显更强；
- 可解释、可测试、可降级。

## 附录 D：评审问题清单（已收敛）

以下问题在本规范中已给出默认答案；若产品后续调整，按 SRS 或配置变更处理：

1. **默认强度**：fast（概率启发式），人类提示同档；standard/strong 可选。
2. **人类提示**：默认 fast；如需“深度分析”，异步计算并缓存，不阻塞 UI。
3. **盘级目标**：按“总猪头差 + 本局胜负”优化；终局调用真实规则。
4. **采样策略**：第一版可接受均匀采样；后续再加对手模型。
5. **末局精确**：允许在采样世界内做精确搜索，不读真实隐藏手牌。
6. **难度设置**：可提供 fast/standard/strong；默认 fast。
7. **Web Worker**：第一版非必须；若 standard/strong 阻塞 UI 再迁移。
8. **随机性**：只允许确定性种子扰动；不要求完全无变化，但必须可复现。
9. **强度验收**：≥500 副自对弈 + 交换座位，新 AI 总猪头差稳定优于旧 AI。
10. **代码范围**：允许重构 `choosePlay` 签名与 store 调用点，但保留旧输入兼容。
11. **概率口径**：大红桃默认 ♥A/K/Q/J 或红桃基础分 ≤ -60，可配置。
12. **概率阈值**：采用附录 C 默认值；可配置，不写死在规则层。
13. **概率展示**：只在复盘/开发模式展示；正式对局隐藏。
14. **保护优先级**：满贯 > 全红 > 变压器保护 > 避猪 > 争羊；最终仍由期望效用比较。例外：本队 `SA` 接近 `+1000` 且普通 `+1000` 可达时，满贯不自动高于普通 `+1000`，按 7.7 比较画头数。
15. **概率层定位**：fast 档也启用解析近似，保证人类提示和低端设备能做基本保护/破坏。

---

**总结**：本规范把出牌策略固定为四层：**规则基线 → 公开知识与关键牌归属 → 四方动态概率与分数量纲 → 模式与候选期望评分**。它保留了 V1.0 的可操作性，吸收了评审稿的工程治理与信息边界，修正了术语、信号、绝对化、概率约束、决策维度和测试缺口。实际实现可先落地 fast 层，再逐步加入采样/搜索；所有层都必须遵守同一信息边界和同一规则基线。
