# 拱猪 2v2 自对弈训练 AI 出牌决策机：实现方案

目标先对齐：你要的不是“单副牌最优解”，而是一个在大量随机牌局自对弈中逐步变强的**通用出牌策略**。拱猪 2v2 的难点是**不完全信息 + 团队合作 + 稀疏盘级奖励 + 变压器导致非零和 + 亮牌/出牌两阶段**。因此不能直接套普通 AlphaZero，建议走“**规则引擎 → 教师策略 → 行为克隆预热 → 策略池自对弈强化 → 评估冻结**”的路线。

---

## 1. 总体架构

```text
┌─────────────────────────────────────────────┐
│ 规则引擎（唯一权威）                         │
│ 合法出牌/首轮限制/计分/画头/盘终/亮牌        │
└──────────────┬──────────────────────────────┘
               │ 只暴露 PlayObservation（白名单）
               ▼
┌─────────────────────────────────────────────┐
│ 自对弈环境（多进程/向量化）                  │
│ 随机发牌 → 亮牌 → 出牌 → 结算 → 盘终         │
│ 四家各自独立 observation，团队共享效用        │
└──────────────┬──────────────────────────────┘
               ▼
┌─────────────────────────────────────────────┐
│ 策略网络（Masked Policy + Value）            │
│ 输入：observation 编码                      │
│ 输出：合法牌概率分布 + 团队价值              │
└──────────────┬──────────────────────────────┘
               ▼
┌─────────────────────────────────────────────┐
│ 训练器                                       │
│ 行为克隆预热 → PPO/IMPALA 自对弈 → 策略池    │
└──────────────┬──────────────────────────────┘
               ▼
┌─────────────────────────────────────────────┐
│ 评估与部署                                   │
│ 固定种子集 + 随机大样本 + 信息边界测试        │
│ 导出 ONNX/量化模型，AI 座位推理              │
└─────────────────────────────────────────────┘
```

**铁律**：训练环境内部可以知道四家手牌用于结算，但**策略网络输入永远只有 `PlayObservation`**。团队合作通过“共享团队奖励/价值”实现，不通过“偷看队友手牌”实现。

---

## 2. 先做对的三件事（比算法更重要）

### 2.1 规则引擎必须可复现、可重放

- 固定 `dealSeed` 可重放整副牌；
- 每个动作记录 `actionId`、状态哈希、合法集合；
- 结算调用真实 `scoreDeal`、画头、盘终，不用近似；
- 首轮限制、窝猪、变压器独拿、满贯、6.4/6.5 全部有单元测试。

### 2.2 Observation 编码白名单

给策略网络的输入建议分块：

| 块 | 内容 | 维度建议 |
|---|---|---|
| 自己的手牌 | 52 位 multi-hot | 52 |
| 自己原始手牌（仅自己亮猪单张判断） | 52 位 | 52 |
| 已打出牌 | 52 位 | 52 |
| 已收牌按座位 | 4×52 位 | 208 |
| 亮牌 | 4 张关键牌 × 归属 one-hot + 自动亮标记 | ~20 |
| 各家剩余张数 | 4 个归一化标量 | 4 |
| 首轮限制状态 | 4 花色 × NOT_LED/LED | 8 |
| 当前墩 | 领出者、已出牌、领出花色、是否首轮 | ~60 |
| 历史墩摘要 | 最近 N 墩编码或按花色统计 | 可配置 |
| 缺门推断 | 4 家 × 4 花色 0/1 | 16 |
| 关键牌归属概率 | 猪/羊/变/♥A × 4 家 | 16 |
| 分数上下文 | 本局小分、总猪头、局数、副数、赛制、加赛 | ~10 |
| 合法出牌 mask | 52 位 | 52 |

历史墩不要简单全量堆叠，建议用“按座位×花色×是否已出/已收”的统计编码，外加最近 2–3 墩的序列编码。这样网络规模可控。

### 2.3 动作空间：变长合法集合 + mask

- 动作空间固定为 52 张牌；
- 策略网络输出 52 维 logits，用 `legalMask` 屏蔽非法牌；
- 采样和贪心都只在合法集合内；
- 首轮限制、强制跟牌由规则引擎保证，网络不需要学合法性。

## 3. 奖励与效用设计

这是自对弈成败的关键。**不要用单副小分当奖励**，否则会学到短视策略。

### 3.1 主奖励：盘级团队效用

对 A 队（南北）视角：

```text
U_match =
    - (A总猪头 - B总猪头)                 // 盘终猪头差，核心
  + roundWinBonus * 本局胜                // 记录本局胜负，8局制回溯有用
  - roundLossPenalty * 本局负
  + matchWinBonus / -matchLossPenalty     // 盘终胜负
```

B 队取相反数。**同一队两名队员共享同一个团队奖励**，但各自只看到自己的 observation。

### 3.2 中间奖励：势能塑形，避免稀疏

只在训练时使用，不改变真实规则：

```text
U_potential =
    w_diff      * (SA - SB) / 1000
  - w_own_neg   * max(0, -SA / 1000)
  - w_opp_attack* max(0,  SB / 1000)
  + w_own_attack* max(0,  SA / 1000)
  + w_opp_neg   * max(0, -SB / 1000)
```

建议初值：`w_diff=1.0, w_own_neg=2.0, w_opp_attack=2.0, w_own_attack=1.2, w_opp_neg=1.2`。每墩结算给一次势能差，盘终给真实 `U_match`。势能权重需通过自对弈调参，避免网络只追势能。

### 3.3 事件奖励（可选）

对关键事件给少量塑形：破敌方全红、破敌方满贯、保护搭档变压器、窝猪、满贯。但**必须小权重**，否则会诱导“为事件而事件”。建议只作为调试指标，不进入主奖励。

### 3.4 非零和注意

变压器会放大个人分，团队总分不守恒；全红反转红桃；满贯抑制猪。因此**终局必须用真实 `scoreDeal` + 画头 + 盘终**，不能用“零和近似”当最终价值。

## 4. 算法选型

### 4.1 推荐主路线：教师蒸馏 + PPO 自对弈 + 策略池

| 阶段 | 方法 | 目的 |
|---|---|---|
| 0 | 规则启发式 + PIMC 快速档 | 产生合法、可用的教师策略 |
| 1 | 行为克隆（BC） | 用教师对局数据预热策略网络，避免从随机开始 |
| 2 | PPO/IMPALA 自对弈 | 用团队奖励优化策略，探索超出教师 |
| 3 | 策略池联赛 | 防循环克制，提升稳健性 |
| 4 | 蒸馏/量化 | 部署到线上 AI 座位和人类提示 |

为什么选 PPO/IMPALA 而不是纯 AlphaZero：
- 拱猪是**不完全信息**，AlphaZero 的完美信息 MCTS 不能直接用；
- 动作空间小（≤13 合法牌），但状态含隐藏信息，纯搜索成本高；
- PPO 对团队共享奖励、变长 mask、多进程采样支持成熟；
- 教师蒸馏能显著降低冷启动成本。

### 4.2 备选：Deep CFR / NFSP

如果发现 PPO 自对弈出现严重策略循环或利用漏洞，可切到 CFR 类方法：
- Deep CFR 更适合求近似均衡；
- NFSP 适合不完全信息自对弈；
- 但工程复杂度和训练成本更高，建议作为第二阶段备选。

### 4.3 不建议第一版做纯 AlphaZero/PIMC+NN

PIMC+神经网络搜索可以作为**强对手/评估基准**，但作为主训练算法成本高、工程复杂。先用 PPO 自对弈把策略拉到较高水平，再考虑加搜索增强。

## 5. 训练循环

```text
初始化：
  规则引擎 + 环境池（多进程）
  教师策略（规则+PIMC fast）
  策略网络 π_θ（随机或 BC 预热）
  价值网络 V_φ（团队价值）
  策略池 P = {教师, 历史检查点}

循环：
  1. 从 P 采样对手策略（含当前策略、历史版本、教师、规则变体）
  2. 并行跑 N 局自对弈：
     - 随机发牌、随机亮牌组合、随机座位、随机赛制阶段
     - 四家各自用 π_θ 或池中策略，按 observation 决策
     - 记录 (obs, legalMask, action, logProb, teamReward, valueTarget)
  3. 计算 GAE / 团队回报
  4. PPO 更新 π_θ, V_φ（团队奖励共享）
  5. 每隔 K 轮评估：
     - 固定种子集胜率/猪头差
     - 对教师/旧检查点/规则基线
     - 信息边界测试、合法性测试
  6. 达标则加入策略池，保留检查点
  7. 课程学习：先单副→整局→整盘；先固定亮牌→联合亮牌
```

### 5.1 自对弈对局配置

- 每局随机 `dealSeed`，但同一批对局内四家共享同一副牌；
- 亮牌阶段：初期固定亮牌策略（如教师），后期联合训练亮牌网络；
- 座位随机交换，消除南北/东西偏差；
- 赛制混合：5 局制、8 局制、加赛、单局 20 副上限都要覆盖；
- 难度课程：先短局（单副结算）、再整局、再整盘。

### 5.2 策略池与对手采样

- 池中保留：教师、最近 K 个检查点、规则变体、PIMC 强基线；
- 采样比例：当前策略 40%、最近检查点 30%、教师/旧策略 20%、强基线 10%（可调）；
- 用 Elo 或胜率矩阵管理池，淘汰长期弱策略，防止池无限膨胀。

### 5.3 探索

- PPO 熵正则，初期较高，后期衰减；
- 亮牌阶段可加温度采样；
- 出牌阶段合法集合小，熵不宜过高，避免随机送分。

## 6. 网络结构建议

```text
输入分块编码
  ├─ 手牌/已出/已收：MLP 或 1D Conv
  ├─ 当前墩/历史墩：序列编码（GRU/Transformer 小模型）
  ├─ 分数/阶段/亮牌：MLP
  └─ 拼接 → 共享 trunk（2–4 层 MLP，256–512 宽）
        ├─ Policy head：52 维 logits + legalMask
        └─ Value head：团队价值标量（A/B 两队各一个或一个对称输出）
```

建议：
- 参数量控制在 1–5M，便于多进程推理和线上部署；
- 输入做归一化（分数 /1000，张数 /13）；
- 价值头输出**团队视角**价值，A/B 两队可共享 trunk、分开 head，或用一个对称输出加队伍标识；
- 合法 mask 在 softmax 前应用，保证概率为 0。

## 7. 评估体系

### 7.1 固定评估集

- 500–1000 个固定 `dealSeed` + 固定亮牌组合；
- 覆盖关键边界：首轮限制、窝猪、变压器独拿、满贯、全亮、6.4/6.5、加赛；
- 每次检查点都在同一评估集上跑，降低方差。

### 7.2 随机大样本评估

- ≥1000 副随机对局，交换座位；
- 指标：
  - 总猪头差、本局胜率、盘胜率；
  - 平均每局副数、满贯/全红/窝猪/变压器陷阱发生率；
  - 破敌方全红/满贯率；
  - 搭档变压器保护率；
  - 非法出牌率（必须为 0）；
  - 信息边界测试通过率（必须 100%）。

### 7.3 强度门槛

新策略对教师/旧检查点/规则基线：
- 总猪头差稳定优于基线（带置信区间）；
- 盘胜率显著提升；
- 不出现“只赢小分、盘胜率下降”的退化。

### 7.4 校准

如果网络输出威胁概率，用 Brier score 校准；但主策略网络不一定需要显式概率头，可先用规则/PIMC 概率作为辅助特征。

## 8. 工程实现要点

### 8.1 多进程自对弈

```text
主进程：参数服务器 + 策略池 + 评估
  ├─ Worker 1..N：环境实例，跑自对弈，回传轨迹
  ├─ GPU 推理/训练：批量前向、PPO 更新
  └─ 回放缓冲：按对局/按墩存储，支持 GAE
```

- 环境用纯 CPU 多进程，规则引擎要快（位图表示、缓存合法集合）；
- 策略网络推理可批量化，CPU/GPU 都行；
- 训练和采样分离，避免采样被训练阻塞。

### 8.2 数据存储

- 每条样本：`obs`、`legalMask`、`action`、`oldLogProb`、`value`、`teamReward`、`done`、`seat`、`team`；
- 按对局存，便于计算团队回报和 GAE；
- 定期清理旧数据，控制磁盘。

### 8.3 确定性

- 固定 `dealSeed` + 固定策略参数 + 固定采样种子 → 固定对局；
- 评估时用贪心或低温度，训练时用采样；
- 保证可复现，便于 debug 和回放。

### 8.4 部署

- 训练完导出 ONNX 或 TorchScript；
- 线上 AI 座位用批量推理或单次推理；
- 人类提示可用小模型/蒸馏模型，低延迟；
- 保留规则启发式作为兜底，模型异常时降级。

## 9. 阶段路线（最小可行 → 强化）

| 阶段 | 目标 | 产出 |
|---|---|---|
| 0 | 规则引擎 + observation + 教师策略 | 可自对弈的合法环境 |
| 1 | 行为克隆预热 | 不随机送分的初始网络 |
| 2 | PPO 自对弈（固定亮牌） | 出牌策略明显强于教师 |
| 3 | 策略池 + 课程学习（整局/整盘） | 稳健的盘级策略 |
| 4 | 联合训练亮牌 + 出牌 | 完整 AI |
| 5 | 蒸馏/量化/部署 | 线上可用模型 |
| 6 | 可选：PIMC/搜索增强 | 更强但更慢的版本 |

**建议第一版先只训出牌、固定亮牌策略**，把出牌策略拉到稳定强于教师，再联合训练亮牌。这样问题可分解，评估清晰。

## 10. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 单副过拟合 | 随机牌局池 + 固定评估集分离；课程学习 |
| 信息泄漏 | observation 白名单 + 隐藏手牌不同但公开信息相同的边界测试 |
| 团队合作学不到 | 团队共享奖励 + 队友 observation 独立 + 课程中增加配合场景 |
| 奖励稀疏 | 势能塑形 + 盘级主奖励；势能权重要调 |
| 策略循环 | 策略池 + 历史检查点 + 强基线混合 |
| 非零和导致价值偏差 | 终局用真实计分；价值头学团队真实效用 |
| 训练慢 | 多进程环境 + 批量推理 + 位图规则引擎 |
| 线上延迟 | 模型蒸馏/量化 + 规则兜底 + 人类提示用小模型 |
| 规则变更 | 规则引擎与训练解耦；评估集随规则更新 |

## 11. 一句话实施建议

**先花 60% 精力把规则引擎、observation 白名单、固定评估集做扎实；再用教师策略做行为克隆预热；然后用 PPO + 策略池做大规模随机自对弈，奖励用“盘级团队效用 + 少量势能塑形”；最后用固定评估集和随机大样本双重验收，达标后蒸馏部署。** 不要第一版就上纯 AlphaZero 或复杂搜索，先把“合法、不泄漏、团队奖励正确、可复现”四件事做到位，训练出来的 AI 才会真正变强而不是学会钻规则空子。

## 1. 上帝视角能做什么

对一副固定牌，离线知道四家手牌、亮牌结果、首轮状态、分数上下文，可以构造一个**完美信息团队博弈求解器**：

```text
输入：四家手牌 + 亮牌结果 + 当前墩/历史 + 本局小分 + 盘级状态
目标：最大化南北团队效用，或求双方近似最优
方法：alpha-beta / CFR / MCTS / 动态规划 + 等价类剪枝
输出：每一手的最优/近似最优出牌、该副上界、关键分支对比
```

它能回答：
1. 这副牌南北理论上最多能拿多少猪头优势？
2. 某一手“出♥A 还是♥2”在完美信息下的差值是多少？
3. 哪些亮牌组合会显著改变胜负？
4. 某个启发式策略离上界差多远？
5. 哪些局面存在“反直觉但正确”的战术，可提炼成规则。

这些用途是合理的，而且比纯自对弈更可解释。

## 2. 为什么不能直接作为实战最终原则

### 2.1 实战没有上帝视角
实战亮牌是暗亮，出牌时看不到：
- 其他三家手牌；
- 未揭晓亮牌；
- 牌堆剩余；
- 对手真实策略。

单副完美信息最优经常依赖“我知道同伴手里有♦A”这类不可得信息。直接照搬会变成作弊式策略，线上不可用。

### 2.2 “最优”依赖对手策略
完美信息下可以求 minimax，但实战是不完全信息团队博弈：
- 对手不是完美理性；
- 同伴也不是；
- 最优是相对于对手/同伴策略的 best response，不是绝对真理；
- 单副 best response 可能利用对手漏洞，泛化差。

### 2.3 单副最优 ≠ 整局/整盘最优
拱猪的最终目标是盘级猪头少者胜：
- 单副小分不直接决定胜负；
- 单局可多副累计；
- 5/8 局制、加赛、8 局同猪头回溯、20 副兜底都影响效用；
- 变压器导致团队总分非零和；
- 单副“多拿 +100”可能把队伍推向 +1000 使对方被画头，是好事；但单副小分本身不是终局目标。

所以求解器的目标函数必须是**盘级团队效用**，不能只优化本副小分。

### 2.4 单副过拟合
只对一副牌穷举，得到的“原则”可能是这副牌的特例。要形成实战原则，必须在大量随机牌局上统计验证。

### 2.5 计算复杂度
单副完美信息仍有巨大分支：
- 13 墩 × 4 家 × 合法牌集合；
- 亮牌组合受持有约束；
- 变压器/全红/满贯使终局计分非线性；
- 团队合作使“南北联合最优”状态更大。

可以求解，但需要：
- 等价类剪枝（同花色连续小牌可合并）；
- 置换表；
- 终局精确计分；
- 限定“固定对手策略”求 best response，而不是全博弈 minimax；
- 或采样/近似。

---

## 3. 正确用法：三层体系

### 第一层：离线完美信息求解器（上帝视角）
作用：
- 求单副上界；
- 做反事实分析；
- 生成高质量标签；
- 评估实战策略差距；
- 发现战术模式。

**禁止**：把四家手牌输入线上 AI。

### 第二层：实战策略蒸馏
从大量“上帝视角最优对局”中提取只依赖公开信息的策略：
- 行为克隆：输入 `PlayObservation`，输出完美信息最优动作；
- 特征提炼：统计“什么公开特征下，最优动作倾向是什么”；
- 规则提取：形成可解释原则，如“同伴亮羊且自己有♦A+两张时出方块中间张”；
- 评估：蒸馏策略在随机牌局上对教师/旧 AI 的胜率。

### 第三层：自对弈强化与验证
- 用蒸馏策略作为初始策略；
- 大规模随机自对弈，团队奖励用盘级效用；
- 策略池防循环；
- 固定评估集 + 随机大样本验证；
- 最终上线策略只接收公开信息。

---

## 4. 亮牌的特殊性

亮牌阶段是**暗亮**，上帝视角可以知道四家手牌，但实战亮牌决策时不知道别人亮什么。因此：
- 上帝视角亮牌最优只能用于分析“亮牌价值”和“亮牌对出牌策略的影响”；
- 不能直接作为实战亮牌原则；
- 正确做法：在大量随机牌局上，用完美信息求解器评估“亮/不亮”的期望差，训练一个只依赖自己手牌+公开分数的亮牌评估器；
- 亮牌与出牌应联合评估，但可分阶段训练。

## 5. 推荐实现方案

### 5.1 固定牌局求解器
```text
DealFixture（四家手牌、亮牌、分数、种子）
  → 完美信息团队搜索（alpha-beta/CFR/MCTS）
  → 输出：每手最优动作、上界、分支差值
  → 存入战术库/训练标签
```

### 5.2 反事实评估
同一副牌、同一亮牌、同一随机种子，只改一手：
- 出♥A vs ♥2；
- 首轮拱猪 vs 短套；
- 亮猪 vs 不亮。
比较盘级效用差，形成“关键决策表”。

### 5.3 蒸馏
```text
完美信息最优动作 + PlayObservation → 监督学习
  → 实战策略网络/决策树/规则集
```

### 5.4 自对弈强化
用蒸馏策略初始化，PPO/策略池自对弈，奖励用真实盘级效用。

### 5.5 验证
- 固定回归集：关键边界、亮牌组合、首轮限制、窝猪、变压器、满贯；
- 随机大样本：≥1000 副，交换座位；
- 信息边界测试：隐藏手牌不同但公开信息相同 → 同决策；
- 强度：对教师/旧 AI 的猪头差、盘胜率、破全红/满贯率、搭档保护率。

---

## 6. 能提炼出的“实战原则”长什么样

不是“这副牌出♥A”，而是条件化规则：

```text
如果 同伴亮羊 且 自己持♦A+至少两张方块 且 首轮
则 出方块中间张，准备第二轮♦A领羊
```

```text
如果 敌方全红概率>40% 且 自己能赢含红桃墩
则 优先破红，即使本墩吃小负分
```

```text
如果 猪只剩最后两张 且 另两家已缺黑桃 且 自己持小黑桃
则 出小黑桃诱导目标敌方收猪
```

这些原则来自大量完美信息求解的统计，再经过随机牌局验证，才是可用的实战原则。

---

## 7. 最终建议

**可以建上帝视角求解器，但定位是“离线教师/上界/评估器”，不是线上策略。**  
正确路线：

1. 规则引擎 + 盘级效用定义；
2. 固定牌局完美信息求解器；
3. 大量随机牌局生成“最优标签”；
4. 蒸馏成只依赖公开信息的实战策略；
5. 自对弈强化 + 策略池；
6. 固定评估集 + 随机大样本 + 信息边界测试；
7. 上线策略永远只接收 `PlayObservation`。

一句话：**上帝视角用来“知道上限和正确答案”，实战策略用来“在不知道答案时做最接近正确的决策”。两者必须隔离，不能混用。**
