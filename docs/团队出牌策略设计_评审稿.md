# 拱猪 2v2 团队出牌策略设计（评审稿）

> 版本：v0.2  
> 日期：2026-11-22  
> 状态：设计稿；快速概率层已实现，PIMC 搜索层保留为后续强度扩展  
> 范围：仅出牌阶段 AI / 推荐出牌；不改变亮牌规则、计分规则、赛制与 UI 主流程  
> 目标：在**严格信息边界**内，尽可能最大化己方（南北 A 队或东西 B 队）的长期比赛利益

---

## 0. 评审摘要

**核心方案**：

1. 出牌 AI 只接收一个裁剪后的 `PlayObservation`，其中不含其他玩家手牌；
2. 用公开信息构造“缺门/剩余牌/亮牌归属”等公共知识；
3. **对包括自己在内的 4 家，动态估计全红、满贯、得猪、得羊、变压器陷阱五类概率**；
4. 从公共知识中采样 N 个与公开信息一致的假设世界；
5. 在每个假设世界上用团队启发式 + 末局精确搜索模拟到终局；
6. 用真实 `scoreDeal`、画猪头与盘终规则计算效用，对 N 个世界求平均，选择期望最优出牌。

**四方动态概率模型（新增核心）**：每一手都从“自己的牌型 + 亮牌 + 公开出牌信息”出发，估计四方收全红、满贯、得猪、得羊、变压器负向放大的概率；概率随每张牌打出动态变化，用于配合搭档全红/满贯、保护收变压器的搭档、破坏敌方全红/满贯。

**与已移除的完美信息求解器的区别**：本方案搜索的是**采样出来的假设手牌**，不是真实隐藏手牌；AI 接口层不提供真实手牌。概率也全部来自公开信息。

**主要新增模块**：`aiObservation`、`aiKnowledge`、`aiBelief`、`aiThreat`、`aiPolicy`、`aiSearch`、`aiUtility`，并改造 `src/core/ai.ts` 与 `src/store/game.ts` 的调用点。

**预期收益**：从“只看当前墩的基础启发式”升级为“四方概率 + 分数情境 + 牌型 + 缺门 + 关键牌 + 搭档保护 + 盘级胜负”的团队策略。

**需要评审拍板**：默认强度与时间预算、是否默认启用 PIMC、是否第一版就上 Web Worker、人类提示是否只保留快速版、概率阈值与“大红桃”口径、强度验收门槛。

**当前实现（2026-11-22）**：已落地第 2–7 节的快速概率层与团队启发式，入口为 `src/core/ai.ts` 的 `choosePlay(PlayObservation | PlayAiInput)`，配套模块 `aiObservation`、`aiKnowledge`、`aiThreat`、`aiPolicy`。其中全红概率按“已收红桃进度 × 剩余高红桃控制力”做动态下限修正，避免边际乘积在“收下一圈红桃、手中仅剩 ♥A”时低估；满贯概率受“其他家已收任意红桃/羊/变压器/猪即归零”的硬约束，并对持羊短方片、持猪早期落猪做关键牌难度区分。红桃去向还区分两种局面：同伴尚未被证实放弃全红（概率不为 0）时，不把红桃垫给其他家并优先喂同伴；敌方全红压力升高时，优先垫给同伴或非目标敌方破红，当前赢家恰为目标时不喂牌；一旦其他家收下红桃、同伴全红被证实破产，则恢复正常垫牌。默认 `fast` 强度不采样完整牌局，保证完整比赛/UI 性能；`standard/strong` 的 PIMC、终局搜索与 Web Worker 尚未启用。实现不改变本文的信息边界与评分原则。

## 1. 背景与目标

### 1.1 原始基线（已替换）

本节记录改造前的出牌 AI，位于 `src/core/ai.ts` 的 `choosePlay()`，是一个轻量启发式：

- 只读取自己的手牌、当前墩、合法出牌集合与 `isLastToPlay`；
- 领出时偏好低点数非计分牌；
- 跟牌时如果搭档当前赢墩，尽量不盖压；
- 能赢时考虑本墩分数，不能赢时倾向垫负分牌；
- 不使用历史出牌、缺门推断、亮牌归属、当前局小分、猪头阈值、单局副数上限等上下文。

它能保证合法性和基本不犯错，但距离“根据分数现状、牌型、牌张与动态亮牌/出牌信息最大化团队利益”还有明显差距。

### 1.2 本设计要解决的问题

设计一个**只使用合法信息**的团队出牌策略，综合以下因素：

1. **己方/敌方当前分数**：本局小分、本盘总猪头、5/8 局制、是否加赛、单局副数上限；
2. **牌型与牌张信息**：自己的 13 张牌、各花色长度、大牌控制、缺门、关键牌归属；
3. **动态公开信息**：当前墩、历史墩、已打出的牌、已收牌、已亮关键牌、自动亮、首轮限制状态；
4. **搭档与对手行为**：谁赢当前墩、谁在后续位置、谁可能缺门、谁可能收负分；
5. **比赛阶段**：领先保分、落后追分、临界 ±1000、最后一副、突然死亡等；
6. **四方动态概率**：每一家的全红、满贯、得猪、得羊、变压器负向放大概率，以及这些概率随出牌的变化；
7. **团队目标切换**：配合搭档全红/满贯、保护收变压器的搭档、破坏敌方全红/满贯。

### 1.3 非目标

本设计明确不做以下事情：

- **不读取任何未公开手牌**，包括其他三家的手牌、牌堆剩余牌、未揭晓亮牌；
- **不使用“上帝视角”求解器**；不会重新引入读取四家真实手牌的完美信息分析工具；
- 不实现暗亮 `hidden` 模式；
- 不实现搭档信号系统；
- 不改变现有亮牌规则 V1.0 与计分流水线；
- 不承诺数学意义上的全局最优，只追求在可接受算力下的**近似最优期望收益**。

### 1.4 成功标准

| 维度 | 标准 |
| --- | --- |
| 合法性 | 任何局面都只返回合法出牌；首轮限制、强制跟牌、唯一合法牌全部正确 |
| 信息边界 | AI 接口不包含他人手牌；同一公开信息下，隐藏手牌不同不能改变 AI 的确定性决策 |
| 团队性 | 能区分搭档/对手；搭档赢墩时不无谓盖压；对手赢墩时优先甩负分 |
| 分数感知 | 己方接近 -1000 时明显收敛；对方接近 -1000 时主动施压；临界 +1000 时能判断进攻/防守 |
| 牌型感知 | 能利用缺门、长套、大牌控制、单张/双张、关键牌位置 |
| 概率感知 | 能给出四方全红/满贯/猪/羊/变压器陷阱概率；概率随公开信息变化，硬事实优先于采样 |
| 搭档保护 | 搭档收变压器且小计为负时主动截红桃/截猪；搭档走全红/满贯时改为喂牌而非保护 |
| 敌方破坏 | 敌方全红/满贯概率升高时，能评估并执行破红、抢关键牌 |
| 概率校准 | 在 ≥500 副模拟中，预测概率与实际频率的偏差在可接受范围（如 Brier score 不劣于常数基线） |
| 性能 | 单次 AI 出牌在普通浏览器中默认不超过约 150–300ms；可降级到快速启发式 |
| 可复现 | 固定观察 + 固定种子 → 固定出牌，便于测试与复盘 |
| 强度 | 在 ≥500 副自对弈中，对现有 `choosePlay` 基线取得稳定的猪头差/胜率优势 |

## 2. 设计原则与信息边界

### 2.1 唯一允许的信息

出牌 AI 只能接收一个**公开观察对象** `PlayObservation`。它由 store 从真实 `DealState` 中裁剪生成，绝不把 `hands`（除自己外）或 `originalHands`（除自己外）传给 AI。

允许的信息：

- 自己的当前手牌；
- 自己的原始手牌（仅用于自己亮猪时的“单张黑桃免窝猪”判断）；
- 当前墩的出牌顺序、牌面、领出者、是否首次领出；
- 历史每墩的四张牌、赢家、首引花色、是否首次领出；
- 每家已收牌（所有打出的牌本来就是公开的）；
- 每家剩余手牌数量（13 减去已出牌数）；
- 已亮关键牌、亮牌者、自动亮标记；
- 四个花色的 `NOT_LED/LED` 首轮状态；
- 当前合法出牌集合；
- 本局小分、本盘总猪头、局数、副数、单局上限、赛制、是否加赛；
- 当前墩/历史墩的公开出牌记录；
- 发牌种子（仅用于可复现采样，不用于还原他人手牌）。

禁止的信息：

- 其他三家的当前手牌；
- 其他三家的原始手牌；
- 牌堆剩余顺序；
- 未揭晓的亮牌；
- 任何由服务端/本地状态直接暴露的隐藏牌。

### 2.2 与“完美信息求解器”的区别

上一版被移除的完美信息求解器读取四家真实手牌，属于上帝视角，不能用于游戏内 AI。

本设计使用的是**公共信息信念采样（PIMC）**：

1. 从公开信息出发，枚举/采样所有与公开信息一致的“可能世界”；
2. 每个可能世界只包含**假设的**其他三家手牌；
3. 在这些假设世界上做 rollout 或末局搜索；
4. 对多个可能世界求平均，选择期望收益最高的出牌。

它看起来像“完美信息搜索”，但输入是**采样出来的假设手牌**，不是真实手牌。只要采样器只使用公开信息，就不违反信息边界。

### 2.3 信息边界的三道防线

1. **类型防线**：`PlayObservation` 类型中没有 `hands`/`originalHands` 字段；
2. **构造防线**：`buildPlayObservation()` 只复制白名单字段，不 spread 整个 `DealState`；
3. **测试防线**：构造两个隐藏手牌不同、公开观察完全相同的牌局，固定种子下 AI 必须给出相同出牌。

## 3. 公开观察对象

### 3.1 建议类型

```ts
export interface PlayObservation {
  /** 自己座位与队伍 */
  self: Position;
  partner: Position;
  team: Team;
  opponentTeam: Team;

  /** 自己的当前手牌与原始手牌 */
  ownHand: number[];
  ownOriginalHand: number[];

  /** 每家剩余手牌数（公开：13 - 已出牌数） */
  handSizes: Record<Position, number>;

  /** 当前墩 */
  currentTrick: {
    leader: Position;
    plays: CardPlay[];
    leadSuit: SuitIndex | null;
    isFirstLed: boolean;
  };

  /** 历史墩（含已结算的完整四张牌与赢家） */
  trickHistory: Trick[];

  /** 每家已收牌（公开） */
  collected: Record<Position, number[]>;

  /** 亮牌信息（揭晓后公开） */
  litCards: number[];
  litBy: Record<number, Position>;
  autoLitCards: number[];

  /** 首轮限制状态 */
  firstLedSuitStatus: Record<SuitIndex, SuitStatus>;

  /** 当前合法出牌集合 */
  legalCards: number[];

  /** 本局上下文 */
  round: {
    number: number;
    isExtra: boolean;
    smallScores: Record<Team, number>;
    dealsPlayed: number;
    dealLimit: number;
    lastPigCollector: Position | null;
  };

  /** 本盘上下文 */
  match: {
    format: MatchFormat;
    totalPigHeads: Record<Team, number>;
    rounds: RoundSummary[];
  };

  /** 本副上下文 */
  deal: {
    index: number;
    leader: Position;
    openingDeal: boolean;
    seed: number;
  };

  /** 采样/随机种子；测试可固定 */
  samplingSeed: number;
}
```

`RoundSummary` 只需要 8 局制回溯所需的最小字段：

```ts
export interface RoundSummary {
  roundNumber: number;
  isExtra: boolean;
  smallScores: Record<Team, number>;
  newPigHeads: Record<Team, number>;
  winner: TeamOrNone;
  loser: TeamOrNone;
  result: RoundResultCode;
  endReason: RoundEndReason;
}
```

### 3.2 从观察中可推导的公开知识

AI 自己维护一个 `PublicKnowledge`：

| 知识 | 推导方式 |
| --- | --- |
| 每家剩余张数 | `13 - 已出牌数` |
| 某家某花色缺门 | 该家曾在某花色领出时垫过其他花色 |
| 某家可能持有某花色 | 曾跟过该花色，或亮牌显示持有 |
| 已打出的牌 | 历史墩 + 当前墩 |
| 已收牌 | `collected` |
| 未见的牌 | 全牌堆 − 自己手牌 − 已打出牌 |
| 已亮但未打出的牌 | 属于亮牌者手牌（若尚未打出） |
| 关键牌归属 | 已亮牌公开；未亮牌未知 |
| 首轮限制 | `firstLedSuitStatus` + 当前墩 `isFirstLed` |
| 猪/羊/变压器/♥A 是否已出 | 历史墩 + 当前墩 + 收牌区 |

### 3.3 必须显式建模的不确定性

1. **其他三家手牌**：完全未知，只能按公开约束采样；
2. **未亮关键牌的位置**：可能在任意未缺门玩家手中；
3. **亮猪者的原始黑桃张数**：如果不是自己，公开信息无法直接知道；它影响“单张黑桃亮猪免窝猪”；
4. **对手后续出牌策略**：用统一理性策略近似，不做信号解读；
5. **未来发牌**：本副内不存在，只有下一副才重新发牌，当前决策不需要预测。

## 4. 目标函数与分数模型

### 4.1 为什么不能只看“本墩分数”

拱猪 2v2 的最终目标是**本盘总猪头少者胜**，不是单副分高者胜。单副分通过以下方式影响猪头：

- 本队小分 ≥ +1000：对方被画 2 头；
- 本队小分 ≤ -1000：本队被画 1 头；
- 对方小分 ≥ +1000：本队被画 2 头；
- 对方小分 ≤ -1000：对方被画 1 头；
- 满贯：本队赢下本局，对方被画 1 或 2 头；
- 单局副数上限：小分更低方被画 1 头；
- 5/8 局制还有总猪头、最后一局、回溯、突然死亡等裁决。

所以出牌策略必须把“当前这一手”映射到**本局小分 → 本盘猪头 → 最终胜负**。

### 4.2 终局评估：直接复用真实计分

在每个采样世界的牌打完后，直接调用：

```ts
scoreDeal({
  collected,
  litCards,
  litBy,
  autoLitCards,
  pigLighterSpadeCount,
})
```

得到 `DealScore`，再按真实规则计算：

1. 是否触发满贯；
2. 本副团队小分；
3. 累加后的本局小分；
4. `evaluatePigHeads()` 是否触发画头；
5. `evaluateDealLimit()` 是否触发副数上限；
6. 更新总猪头；
7. 若本局结束，调用 `resolveMatch()` 判断盘终或加赛。

这样终局价值与正式计分完全一致，不需要另写一套近似计分。

### 4.3 盘级效用

建议定义：

```ts
interface MatchUtility {
  /** 从己方视角看的效用，越大越好 */
  value: number;
  /** 本副/本局是否结束 */
  roundEnded: boolean;
  matchEnded: boolean;
  /** 便于调试 */
  ownHeads: number;
  oppHeads: number;
}
```

基础形式：

```text
U_match = -(己方总猪头 - 对方总猪头)
```

若本局结束，再加上：

```text
+ roundWinBonus     // 本局胜，尤其 8 局制回溯有用
- roundLossPenalty
```

若本盘结束：

```text
+ matchWinBonus / - matchLossPenalty
```

若进入 5 局制突然死亡或 8 局制同猪头裁决，按真实规则给终局 ±大值。

### 4.4 局内中间态效用

在 rollout 尚未结束时，需要一个平滑的局内势能，避免“只有最后才看分”的短视：

```text
U_round_potential =
    w_diff      * (SA - SB) / 1000
  - w_own_neg   * max(0, -SA / 1000)   // 己方负分越深，风险越大
  - w_opp_attack* max(0,  SB / 1000)   // 对方正分越高，对方越接近 +1000
  + w_own_attack* max(0,  SA / 1000)   // 己方正分越高，己方越接近 +1000
  + w_opp_neg   * max(0, -SB / 1000)   // 对方负分越深，对方越接近 -1000
```

其中 `SA`/`SB` 是己方/对方本局小分。权重建议初始：

| 权重 | 建议初值 | 含义 |
| --- | --- | --- |
| `w_diff` | 1.0 | 基础分差 |
| `w_own_neg` | 2.0 | 己方负分临界风险 |
| `w_opp_attack` | 2.0 | 对方正分进攻风险 |
| `w_own_attack` | 1.2 | 己方正分进攻收益 |
| `w_opp_neg` | 1.2 | 对方负分收益 |

这些权重只用于 rollout 内部的中途评估；最终仍以真实终局计分为准。

> 注意：变压器会放大拿到它的玩家个人分，因此本副/本局总分不是严格零和。`U_round_potential` 只是中途近似，任何终局判断都必须以 `scoreDeal()` 的真实团队分为准，不能假设“双方总分恒定”。

> 概率层与势能层不重复计分：`U_round_potential` 只负责“小分接近 ±1000”的平滑势能；全红/满贯/猪/羊/变压器陷阱由第 5 章的 `ThreatModel` 单独进入候选评分，终局再由 `scoreDeal()` 统一结算。三者各司其职，避免同一事件被重复加权。

### 4.5 分数情境分类

AI 每手先判定当前情境，再调整风险系数：

| 情境 | 条件示例 | 策略倾向 |
| --- | --- | --- |
| `normal` | 双方小分接近 0，非临界 | 平衡，优先正期望 |
| `protect-lead` | 己方总猪头明显领先，或本局小分领先且接近结束 | 降低方差，避免送猪/送红桃，优先安全垫牌 |
| `chase` | 己方总猪头落后，或本局小分落后 | 提高方差，争羊/变压器/全红，必要时赌博性亮猪/抢分 |
| `danger-zone` | 己方小分接近 -1000 | 强规避负分，宁可放弃羊，也不让己方收猪/红桃 |
| `finish` | 己方小分接近 +1000 或对方接近 -1000 | 主动施压，争取触发画头 |
| `slam-watch` | 自己或搭档已收/可能收 3 张关键牌 + 大量红桃 | 评估满贯路线，优先关键牌 |
| `all-red-watch` | 自己或搭档已收 ≥10 张红桃 | 评估全红反转，决定继续收还是止损 |
| `last-deal` | 本局最后一副或盘末关键副 | 按盘级胜负裁决调整，不只看本副 |

> 4.5 的“分数情境”只描述小分/猪头/阶段；第 5 章的“概率模式”描述全红/满贯/猪/羊/变压器陷阱。两者正交，最终在候选评分中叠加：分数情境决定“风险偏好”，概率模式决定“服务谁/破坏谁”。

## 5. 四方动态概率模型（核心）

### 5.1 为什么需要“概率层”

只看“这一墩谁赢、这张牌多少分”是短视的。拱猪真正的胜负由少数**稀有但高杠杆**的事件决定：

- 某人收齐全红 → 红桃分反转；
- 某人集齐猪、羊、变压器、全部红桃 → 满贯，直接赢下本局；
- 某人收下猪 → 负分；
- 某人收下变压器且同时背猪/大红桃 → 负分被 ×2/×4 放大，可能瞬间击穿 -1000。

这些事件在开局时概率很低，但随着牌一张张打出、关键牌归属逐渐明朗，概率会从接近 0% 快速上升到接近 100%。**策略必须在概率还低的时候提前布局，在概率变高时果断切换目标**，而不是等事件发生后才反应。

因此本设计在“公开观察 → 采样世界 → 效用”之间增加一层**四方动态概率模型**：

> 对包括自己在内的 4 家，每一手都估计：
> 1. 收全红概率；
> 2. 实现满贯概率；
> 3. 得猪概率；
> 4. 得羊概率；
> 5. 得变压器且同时得猪/大红桃（负向放大）的概率。
>
> 并据此决定：配合谁、保护谁、破坏谁、放弃什么。

概率层不是替代搜索，而是：

- 给候选牌提供**可解释的先验**；
- 给 rollout 内部策略提供**模式开关**；
- 给调试/复盘提供人类可读的局面判断；
- 在快速档没有采样时，直接支撑规则化决策。

### 5.2 概率向量定义

对每个座位 `p ∈ {S, E, N, W}`，在当前决策点 `t` 定义：

```ts
interface SeatThreat {
  seat: Position;
  team: Team;

  /** 个人事件：该家最终收齐 13 张红桃 */
  pAllRed: number;
  /** 个人事件：该家最终集齐猪 + 羊 + 变压器 + 13 张红桃 */
  pGrandSlam: number;
  /** 个人事件：该家最终收下 ♠Q */
  pPig: number;
  /** 个人事件：该家最终收下 ♦J */
  pSheep: number;
  /** 个人事件：该家最终收下 ♣10 */
  pTransformer: number;
  /** 个人事件：该家收 ♣10 且最终小计为负（变压器负向放大） */
  pTransformerNegative: number;
  /** 个人事件：该家收 ♣10 且同时收猪或大红桃 */
  pTransformerTrap: number;
  /** 个人事件：该家最终收下 ♥A */
  pHeartA: number;
  /** 个人事件：该家收猪，且猪未被满贯抑制 */
  pEffectivePig: number;

  /** 估计置信度：采样世界数、方差、是否使用了解析近似 */
  confidence: number;
  /** 该家当前已确定收下的关键牌（公开信息，非概率） */
  confirmed: {
    pig: boolean;
    sheep: boolean;
    transformer: boolean;
    heartA: boolean;
    hearts: number;
    keyCards: number;
  };
}
```

团队级事件由个人概率聚合，但要区分“任一人”与“指定人”：

```ts
interface TeamThreat {
  /** 己方/对方任一成员完成全红 */
  pAllRedAny: number;
  /** 己方/对方任一成员完成满贯 */
  pGrandSlamAny: number;
  /** 己方/对方最终小分 ≥ +1000（触发对方被画头） */
  pPositive1000: number;
  /** 己方/对方最终小分 ≤ -1000（本队被画头） */
  pNegative1000: number;
  /** 己方/对方收下猪（任一成员） */
  pPigAny: number;
  /** 己方/对方收下羊（任一成员） */
  pSheepAny: number;
  /** 己方/对方陷入变压器负向放大 */
  pTransformerTrapAny: number;
}

interface ThreatModel {
  seat: Record<Position, SeatThreat>;
  own: TeamThreat;
  opp: TeamThreat;
  /** 当前主导模式，见 5.12 */
  modes: ThreatMode[];
  /** 模式迟滞状态，见 5.15 */
  hysteresis: Record<ThreatMode, boolean>;
}

type ThreatMode =
  | 'normal'
  | 'own-allred'
  | 'partner-allred'
  | 'break-opp-allred'
  | 'own-slam'
  | 'partner-slam'
  | 'break-opp-slam'
  | 'protect-transformer'
  | 'exploit-transformer'
  | 'pig-evade'
  | 'pig-maintain'
  | 'sheep-contest'
  | 'danger-zone'
  | 'finish';
```

> 说明：`pAllRedAny` 不能简单写成 `pA + pB`，因为两名队友不可能同时收齐同一副的 13 张红桃。实践中用采样世界中“该队任一成员全红”的频率直接统计，避免重复计数。

#### 5.2.1 输入与输出

每一家的概率都只由三类输入构造：

| 输入 | 来源 | 作用 |
| --- | --- | --- |
| 自己的牌型 | 自己的当前手牌 + 原始手牌 | 自己的花色长度、大牌控制、关键牌、缺门 |
| 亮牌 | `litCards` / `litBy` / `autoLitCards` | 未打出的亮牌 100% 属于亮牌者；亮牌修正分值 |
| 公开出牌信息 | 历史墩、当前墩、已收牌、剩余张数、首轮状态 | 推断缺门、剩余牌、关键牌归属与收牌概率 |

输出即 5.2 的 `SeatThreat` / `TeamThreat`。**“每一家”包括自己**：自己的手牌完全已知，概率更精确；其他三家只能基于公开信息估计。

#### 5.2.2 一致性约束（用于测试）

| 约束 | 说明 |
| --- | --- |
| `Σ_p pPig = 1` | 猪未打出前必然属于某一家；打出后该家为 1，其余为 0 |
| `Σ_p pSheep = 1` | 同上 |
| `Σ_p pTransformer = 1` | 同上 |
| `Σ_p pAllRed ≤ 1` | 一副牌最多一人全红 |
| `pGrandSlam(p) ≤ pAllRed(p)` | 满贯必须包含全红 |
| `pTransformerTrap(p) ≤ pTransformer(p)` | 陷阱是收变的子事件 |
| `pTransformerNegative(p) ≤ pTransformer(p)` | 负向放大是收变的子事件 |
| `pEffectivePig(p) ≤ pPig(p)` | 满贯抑制猪后，有效猪概率下降 |

这些约束不依赖真实隐藏手牌，可直接用于单元测试和采样器自检。

### 5.3 “大红桃”的判定口径

“变压器 + 大红桃”是用户特别指出的高风险组合。本设计把“大红桃”定义为**可配置的口径**，默认：

| 口径 | 默认值 | 含义 |
| --- | --- | --- |
| 大牌红桃 | ♥A、♥K、♥Q、♥J 任一张 | 单张即可显著放大负分 |
| 红桃负分阈值 | 该家红桃基础分 ≤ -60 | 多张中牌累积也会触发 |
| 强口径 | ♥A 或 ♥K | 更保守，只把真正的大牌视为“大红桃” |

判定：

```text
hasBigHeart(p) =
    该家已收或高概率将收的 {♥A, ♥K, ♥Q, ♥J} 非空
  ∨ 该家红桃基础分 ≤ -60
```

“变压器陷阱”最终以**小计为负**为准，而不是只看猪/大红桃，因为：

- 变压器 ×2/×4 作用于**小计**，小计为负才是真正的负向放大；
- 若该家同时收羊或正分红桃，小计可能为正，变压器反而变成收益放大器；
- 猪在满贯时被抑制，满贯路线下的“收猪”不构成陷阱。

因此：

```text
pTransformerNegative(p) = P(p 收 ♣10 ∧ subtotal(p) < 0)
pTransformerTrap(p)     = P(p 收 ♣10 ∧ (p 收猪 ∨ p 收大红桃))
```

两者都要估计：前者是真正的分数风险，后者是可解释的“危险组合”提示。

### 5.4 概率的来源与精度层级

| 来源 | 适用 | 精度 | 成本 |
| --- | --- | --- | --- |
| 已确定事实 | 已收牌、已打出、已亮且未打出的牌 | 0/1 | 0 |
| 解析近似 | 未见牌归属、关键牌持有、全红上界 | 中 | 极低 |
| 采样频率 | 收牌归属、全红、满贯、±1000 | 高 | 中 |
| 末局精确 | 剩余 ≤5 墩时的条件概率 | 最高 | 高 |

统一约定：

- **快速档**：只用已确定事实 + 解析近似；
- **标准档**：解析近似作为先验，采样频率作为主估计；
- **强化档**：增加世界数，末局用精确搜索统计事件频率；
- 任何概率都必须来自公开信息，禁止用真实隐藏手牌直接算 0/1。

### 5.5 关键牌归属概率

未见牌集合：

```text
U = 全 52 张 − 自己手牌 − 所有已打出的牌
```

对每家 `p` 的剩余容量：

```text
cap[p] = 13 − 已出牌数[p]
```

**无花色约束时的超几何近似**：

```text
P(某张未见牌 c 属于 p) ≈ cap[p] / Σ_q cap[q]
```

**有缺门约束时按花色分配**：设花色 `s` 的未见牌集合为 `U_s`，可持有该花色的玩家集合为 `Eligible_s`（未在该花色垫过牌），则：

```text
P(c ∈ p) ≈ E[分配给 p 的 s 花色张数] / |U_s|,  c ∈ U_s
```

其中期望分配由“容量 + 花色约束”的约束随机分配决定。精确值由采样器统计：

```text
P(c ∈ p) = (1/N) × Σ_world 1[c 在 world 中属于 p]
```

硬信息优先级最高：

1. 已打出 → 归属已确定；
2. 已亮且未打出 → 100% 属于亮牌者；
3. 自己手牌 → 100% 属于自己；
4. 其余才进入采样。

### 5.6 收牌归属概率（猪 / 羊 / 变压器 / ♥A）

单张关键牌“被谁收下”不等于“谁持有它”。持有者可能被迫打出，非持有者也可能用大牌抢走。因此：

```text
P(p 收 c) = (1/N) × Σ_world 1[c 最终进入 collected[p]]
```

解析近似（快速档）：

```text
P(p 收 c) ≈ P(c ∈ p) × P(p 赢下 c 所在墩 | c ∈ p)
```

其中“赢下该墩”的能力由以下特征估计：

- 该花色剩余更大的牌数量；
- 该家该花色长度与控制；
- 该家是否可能缺门；
- 该墩是否已被更高牌压住；
- 该家是否愿意为该墩付出代价（策略层修正，不进入纯概率）。

> 关键牌收牌概率与“持有概率”必须分开：亮猪者持有♠Q 的概率是 100%，但收猪概率可能远低于 100%，因为他可以用黑桃大牌把猪送出去。

### 5.7 全红概率

#### 5.7.1 定义与结构

全红是**个人事件**：某一家最终收齐全部 13 张红桃，红桃分从负转正（未亮♥A 为 +200，亮♥A 为 +400）。

必要条件：

```text
该家已收红桃数 + 该家将收的剩余红桃数 = 13
```

因此：

- 若其他任何一家已收至少 1 张红桃，则该家**永远不可能**全红（全红被破）；
- 若某家已收 `h` 张红桃，则剩余 `13 − 已出红桃数` 张红桃必须**全部**由该家收下；
- 全红概率随剩余红桃数减少而单调上升，最后一张红桃归属确定时变为 0 或 1。

#### 5.7.2 解析上界

```text
pAllRedUpper(p) =
    1,   若 p 已收 13 张红桃
    0,   若其他任一家已收 ≥1 张红桃
    Π_{每张剩余红桃 h} P(p 赢下 h 所在墩),  否则
```

这个上界假设“每张剩余红桃独立”，实际存在强相关（同一花色控制、同一领出者），所以只作为快速档的粗估。

#### 5.7.3 采样估计

标准档直接统计：

```text
pAllRed(p) = (1/N) × Σ_world 1[world 结束时 collected[p] 含 13 张红桃]
```

采样世界必须满足“已收红桃归属”这一硬事实，因此不会出现“已经收过红桃的人又被算出全红”的低级错误。

#### 5.7.4 全红的可控杠杆

| 杠杆 | 作用 |
| --- | --- |
| 红桃大牌（♥A/K/Q/J） | 决定能否赢下红桃墩 |
| 红桃长度 | 决定是否需要被迫垫红桃 |
| 其他家红桃缺门 | 缺门者垫牌时可能把红桃送给赢家 |
| 领出权 | 全红者需要持续获得领出或迫使红桃被领出 |
| 队友配合 | 队友停止收红桃、主动让红桃，可显著提高目标队友全红概率 |
| 对手破坏 | 对手只要赢下任意一墩含红桃的牌，即可破红 |

#### 5.7.5 概率分级与策略含义

| 区间 | 分级 | 含义 |
| --- | --- | --- |
| 0 | 已破 | 无需再考虑 |
| (0, 10%) | 极低 | 只做低成本保留 |
| 10%–40% | 中 | 开始关注，避免无意破红/送红 |
| 40%–75% | 高 | 进入全红模式，团队配合 |
| > 75% | 极高 | 优先服务全红，允许牺牲本墩/羊 |

### 5.8 满贯概率

#### 5.8.1 定义与必要条件

满贯是**个人事件、团队结果**：某一家集齐猪、羊、变压器、全部 13 张红桃，则本队直接赢下本局，对方画 1 头（非全亮）或 2 头（四张全亮）；该副不生成正式个人分。

因为满贯要求全部 13 张红桃，所以：

```text
pGrandSlam(p) ≤ pAllRed(p)
```

这是最重要的结构约束：**没有全红，就没有满贯**。

#### 5.8.2 分解

```text
pGrandSlam(p) = pAllRed(p) × P(p 收齐猪、羊、变压器 | p 全红)
```

按已确定收牌分阶段：

| 该家已收关键牌数 | 满贯概率主导因素 |
| --- | --- |
| 0 | 极低，需要同时收齐三张关键牌 + 全红 |
| 1 | 低，仍需要两张关键牌 + 全红 |
| 2 | 中，只差一张关键牌，且必须全红 |
| 3 | 等于全红概率（猪/羊/变已齐） |

注意：满贯者收猪不记负分，且不触发窝猪。因此**走满贯路线的人不应因为“怕猪”而放弃**；相反，猪是满贯的必要拼图。

#### 5.8.3 采样估计

```text
pGrandSlam(p) = (1/N) × Σ_world 1[isGrandSlam(world.collected[p])]
```

团队级：

```text
pGrandSlamAny(team) = (1/N) × Σ_world 1[该队任一成员满贯]
```

#### 5.8.4 满贯的收益与防守阈值

满贯收益极高：直接本局获胜 + 对方 1–2 头。因此防守阈值应显著低于全红：

| 对象 | 进攻阈值 | 防守阈值 |
| --- | --- | --- |
| 己方/搭档满贯 | > 35% 进入 `slam-protect` | — |
| 敌方满贯 | — | > 25% 进入 `slam-break` |

原因：满贯一旦成立，本副的小分争夺全部失效，不能用“这墩亏一点”来衡量。

### 5.9 得猪概率

#### 5.9.1 风险来源

猪（♠Q）基础 -100；亮猪 -200；亮猪者自收且非单张黑桃 → 窝猪 -400。满贯者收猪被抑制。

```text
P(p 收猪) = (1/N) × Σ_world 1[PIG ∈ collected[p]]
```

#### 5.9.2 解析特征

| 特征 | 对“得猪”的影响 |
| --- | --- |
| 是否持有♠Q | 持有者风险最高，但可用大牌送出 |
| 黑桃长度 | 越长越容易被逼收猪；越短越可能缺门垫牌 |
| 黑桃大牌（♠A/♠K） | 可控制黑桃墩，决定猪的流向 |
| 是否亮猪 | 猪分翻倍，且全场知道猪在谁手里 |
| 原始黑桃张数（仅自己可精确知道） | 单张亮猪自收仅 -200，不窝猪 |
| 其他家黑桃缺门 | 缺门者无法接猪，猪更可能回到持有者 |

#### 5.9.3 例外：什么时候可以接受猪

1. **走满贯**：猪被抑制，收猪是必要拼图；
2. **保护搭档**：搭档即将收变压器负向放大或更大负分，自己收猪可能是更小的损失；
3. **阻断敌方满贯**：敌方已收两张关键牌且全红概率高，自己收猪可破坏其满贯，-100 远小于“本局输 + 1–2 头”；
4. **单张亮猪自收**：仅 -200，且不窝猪，风险可控（但仍不是首选）。

除以上情形，默认避免己方得猪。

### 5.10 得羊概率

羊（♦J）基础 +100；亮羊 +200。羊是正分，己方收是收益，对方收是损失。

```text
P(p 收羊) = (1/N) × Σ_world 1[SHEEP ∈ collected[p]]
```

解析特征：

- 方块控制（♦A/K/Q）决定谁能赢下方块墩；
- 方块长度决定是否被迫跟牌；
- 羊是中张（J），上方还有 Q/K/A，因此“持有羊”不等于“能收羊”；
- 亮羊后价值翻倍，争夺优先级上升。

边际价值修正：

- 己方小分已接近 +1000：羊的边际价值下降，不必为羊破坏更重要的目标；
- 对方小分接近 -1000：给羊可能帮对方“回血”，需要计算净效应，不能只看“羊是正分”；
- 对方小分接近 +1000：阻止对方收羊优先级上升。

### 5.11 变压器陷阱概率

#### 5.11.1 三种结果

变压器（♣10）不是单纯的“好牌”或“坏牌”，它有三种结果：

| 结果 | 条件 | 分数效果 | 策略含义 |
| --- | --- | --- | --- |
| 独拿 | 只有变压器，无猪/羊/红桃 | +50（未亮）/ +100（亮） | 稳定小收益 |
| 正向放大 | 小计 > 0 | 小计 ×2/×4 | 收益放大，值得争 |
| 负向放大 | 小计 < 0 | 小计 ×2/×4 | 风险放大，必须避免 |

其中：

```text
pTransformerNegative(p) = P(p 收变 ∧ subtotal(p) < 0)
pTransformerTrap(p)     = P(p 收变 ∧ (p 收猪 ∨ p 收大红桃))
```

#### 5.11.2 为什么“变 + 猪/大红桃”特别危险

举例（未亮变压器）：

```text
猪 -100 + ♥A -50 + 变压器 ×2 = (-150) × 2 = -300
```

若亮猪、亮变：

```text
窝猪 -400 + ♥A -50 + 变压器 ×4 = -1800
```

单副即可击穿 -1000，直接把本局送给对方。因此“变压器 + 猪/大红桃”不是普通负分，而是**可能直接决定本局胜负的尾部风险**。

#### 5.11.3 对搭档的保护责任

当搭档的 `pTransformerNegative` 或 `pTransformerTrap` 升高时，自己应主动承担“脏活”：

1. **截红桃**：对手领红桃时，自己尽量抢下，避免搭档被迫收；
2. **截猪**：黑桃局主动控制，必要时自己收猪，避免搭档收猪后被变压器放大；
3. **不领危险花色**：不主动领搭档可能被迫赢的红桃/黑桃；
4. **放弃羊**：若争羊会导致搭档收负分，优先保护搭档；
5. **反向操作**：若搭档同时在全红/满贯路线，则**不要保护**，反而要继续喂红桃/关键牌，因为全红会反转红桃、满贯会抑制猪。

#### 5.11.4 对对手的利用

- 对手收变且小计为负 → 主动把猪/大红桃塞给对手，放大其负分；
- 对手收变且小计为正 → 避免给其正分，优先让其收负分或独拿；
- 对手收变且接近 -1000 → 这是己方最有利的局面，应保护该局面，不要帮对手“解套”。

### 5.12 概率 → 模式 → 策略

概率不直接等于出牌，而是先映射为**模式**，再由模式调整候选评分与硬约束。

| 模式 | 触发条件（默认） | 目标 | 典型动作 |
| --- | --- | --- | --- |
| `normal` | 无其他模式 | 平衡期望 | 常规启发式 |
| `own-allred` | 己方某人 `pAllRed` > 60% | 服务全红 | 让红桃、停止争红桃、保护目标队友 |
| `partner-allred` | 搭档 `pAllRed` > 60% | 服务搭档全红 | 主动喂红桃、替搭档挡对手破红 |
| `break-opp-allred` | 敌方某人 `pAllRed` > 40% | 破红 | 赢下任意含红桃的墩、逼其垫红桃 |
| `own-slam` | 己方某人 `pGrandSlam` > 35% | 服务满贯 | 让关键牌、让红桃、放弃猪的规避 |
| `partner-slam` | 搭档 `pGrandSlam` > 35% | 服务搭档满贯 | 喂关键牌/红桃，替其挡枪 |
| `break-opp-slam` | 敌方某人 `pGrandSlam` > 25% | 破坏满贯 | 抢猪/羊/变、破红，必要时自己收猪 |
| `protect-transformer` | 搭档 `pTransformerNegative` > 40% | 保护搭档 | 截红桃/截猪、不领危险花色 |
| `exploit-transformer` | 对手 `pTransformerNegative` > 40% | 放大对手负分 | 塞猪/红桃给对手 |
| `pig-evade` | 己方 `pPigAny` > 50% | 避猪 | 把黑桃控制让给对手、避免领黑桃 |
| `pig-maintain` | 对手 `pPigAny` > 60% | 保持对手猪压力 | 不主动领黑桃帮其解套 |
| `sheep-contest` | 己方 `pSheep` < 40% 且争夺成本低 | 争羊 | 用方块控制抢羊 |
| `danger-zone` | 己方 `pNegative1000` > 30% | 防守 | 强规避负分，放弃边缘收益 |
| `finish` | 己方 `pPositive1000` > 50% | 进攻 | 主动施压，争取画头 |

### 5.13 模式优先级与冲突消解

多个模式可能同时触发，例如“搭档全红”与“保护搭档变压器”同时成立。默认优先级：

```text
1. 己方/搭档满贯（own-slam / partner-slam）
2. 破坏敌方满贯（break-opp-slam）
3. 己方/搭档全红（own-allred / partner-allred）
4. 破坏敌方全红（break-opp-allred）
5. 保护搭档变压器（protect-transformer）
6. 利用对手变压器（exploit-transformer）
7. 避猪 / 保持对手猪压力（pig-evade / pig-maintain）
8. 争羊（sheep-contest）
9. 分数临界（danger-zone / finish）
10. 常规（normal）
```

但优先级只是默认值，最终仍由期望效用比较决定：

- 若“破红”需要自己吃 -50，而敌方全红价值 +200（亮♥A 时 +400）并可能通向满贯，则破红几乎总是正期望；
- 若“保护搭档变压器”需要自己吃猪 -100，而搭档避免 -400 窝猪 + ×4 放大，则保护通常正期望；
- 若“服务搭档满贯”需要自己放弃羊 +100，而满贯价值“本局胜 + 1–2 头”，则让羊通常正期望。

冲突消解规则：

1. **满贯 > 全红**：满贯包含全红，且直接赢本局；
2. **己方事件 > 阻止敌方事件**：同等概率下优先成事，而不是破坏；
3. **高概率事件 > 低概率事件**：但满贯/全红的收益杠杆大，允许在较低概率时提前防守；
4. **确定性小损失 < 不确定性大损失**：愿意用 -100 的确定损失，换取避免 -400 或本局失败；
5. **不为了小概率事件牺牲确定性收益**：概率低于阈值时只做低成本保留，不豪赌。

### 5.14 关键场景决策表

#### 5.14.1 己方/搭档全红

| 角色 | 动作 |
| --- | --- |
| 全红者本人 | 尽量赢下每墩含红桃的牌；避免被迫垫红桃；保留红桃大牌 |
| 全红者搭档 | 停止收红桃；能赢红桃时让给全红者；对手破红时尽量截胡 |
| 对手 | 赢下任意含红桃的墩；领全红者可能缺门的花色，逼其垫红桃 |

#### 5.14.2 敌方全红

| 情形 | 动作 |
| --- | --- |
| 自己能赢红桃墩 | 用最大红桃抢下，破红 |
| 自己赢不了 | 逼第三家赢，或领敌方缺门花色逼其垫红桃 |
| 破红成本高 | 评估：敌方全红 +200/+400 与可能的满贯，通常仍值得破 |
| 敌方已亮♥A | 破红优先级进一步提高（全红 +400） |

#### 5.14.3 己方/搭档满贯

| 角色 | 动作 |
| --- | --- |
| 满贯者本人 | 收齐剩余关键牌与全部红桃；不再避猪（猪被抑制） |
| 满贯者搭档 | 让出猪/羊/变与红桃；替其挡住对手抢关键牌 |
| 对手 | 抢走任意关键牌或破红，优先抢猪（成本最低、破坏最大） |

#### 5.14.4 敌方满贯

| 情形 | 动作 |
| --- | --- |
| 敌方缺猪 | 自己收猪或逼第三方收猪，破坏满贯 |
| 敌方缺羊/变 | 抢羊/变 |
| 敌方关键牌已齐 | 只能破红：赢下任意红桃墩 |
| 破坏成本 | 即使自己吃 -100/-200，也远小于“本局输 + 1–2 头” |

#### 5.14.5 搭档收变压器

| 搭档状态 | 动作 |
| --- | --- |
| 小计可能为负，未走全红/满贯 | 保护：截红桃、截猪、不领危险花色、放弃羊 |
| 已在全红路线 | 不保护红桃，继续喂红桃；全红会反转红桃为正 |
| 已在满贯路线 | 不保护猪，猪被抑制；继续喂关键牌/红桃 |
| 小计为正 | 变压器是收益放大器，帮助搭档保持正分 |

#### 5.14.6 对手收变压器

| 对手状态 | 动作 |
| --- | --- |
| 小计为负 | 塞猪/大红桃，放大其负分 |
| 小计为正 | 避免给正分，优先让其收负分 |
| 接近 -1000 | 保护该局面，不帮其解套 |
| 接近 +1000 | 阻止其继续收正分，必要时自己收羊/正分红桃 |

### 5.15 概率更新、平滑与迟滞

#### 5.15.1 更新时机

| 时点 | 更新内容 |
| --- | --- |
| 亮牌揭晓后 | 关键牌归属硬信息、亮牌修正 |
| 每张牌打出后 | 未见牌集合、缺门、收牌归属 |
| 每墩结算后 | 收牌归属、全红/满贯/猪/羊/变状态 |
| 每副开始 | 重置个人概率，保留团队分数与猪头 |
| 本局结束 | 重置局内概率，更新盘级状态 |

#### 5.15.2 增量更新

- 已确定事件（某家已收猪）直接从概率变为 0/1；
- 某家已收红桃 → 其他家全红概率立即归零；
- 某家已收 3 张关键牌 → 满贯概率退化为全红概率；
- 某家已收猪且非满贯 → 该家 `pPig=1`，其他家 `pPig=0`。

#### 5.15.3 平滑

采样频率在 N 较小时会出现 0% 或 100% 的假确定性，使用 Laplace 平滑：

```text
p_smooth = (count + α) / (N + 2α),  α 默认 0.5
```

并对 `N < 16` 的结果向解析先验收缩：

```text
p_final = λ × p_sample + (1 − λ) × p_prior
λ = min(1, N / 32)
```

#### 5.15.4 迟滞（防止模式抖动）

模式进入与退出使用不同阈值：

| 模式 | 进入 | 退出 |
| --- | --- | --- |
| `own-allred` / `partner-allred` | 60% | 45% |
| `break-opp-allred` | 40% | 25% |
| `own-slam` / `partner-slam` | 35% | 20% |
| `break-opp-slam` | 25% | 15% |
| `protect-transformer` | 40% | 25% |
| `pig-evade` | 50% | 35% |

迟滞状态在同一副内保持，跨副重置。

### 5.16 概率层与搜索层的关系

```text
公开观察
  → 解析先验（关键牌归属/全红上界）
  → 采样世界
  → 概率统计（全红/满贯/猪/羊/变陷阱/±1000）
  → 模式判定（含迟滞）
  → 候选评分（模式先验）
  → rollout（模式作为内部策略）
  → 真实计分效用
  → 最终出牌
```

职责边界：

| 层 | 是否决定最终出牌 | 作用 |
| --- | --- | --- |
| 概率层 | 否 | 提供可解释的先验与模式 |
| 模式层 | 部分（硬约束） | 触发保护/破坏/放弃等策略 |
| 候选评分 | 是（快速档） | 无采样时的兜底决策 |
| rollout | 是（标准/强化档） | 用真实计分修正先验 |
| 效用层 | 是 | 最终比较 |

> 概率层不能单独决定出牌，否则会退化为“看到概率高就机械执行”。例如敌方全红概率 45%，但破红需要自己吃 -50 且会导致己方 -1000，此时不应机械破红，而要比较期望效用。

### 5.17 一次完整的概率驱动决策示例

**局面**：

- 南家（A 队）手牌含 ♥A、♥2、♠A、♦Q 等；
- 北家（搭档）已亮变压器，且已收 ♣10、♥K，小计约 -50（亮变后 ×4）；
- 东家已收 10 张红桃，西家已收 1 张红桃；
- 当前墩：东家领出 ♥J，北家跟 ♥Q，西家跟 ♥8，轮到南家出牌；
- 南家合法牌为 ♥A、♥2；
- 本局小分：A = -300，B = +500。

**概率估计**：

| 事件 | 估计 | 依据 |
| --- | --- | --- |
| 东家全红 | 0（已破） | 西家已收 1 张红桃 → 东家不可能全红 |
| 敌方满贯 | 0（已破） | 满贯要求全红，全红已破 |
| 北家变压器负向放大 | 高 | 已收变 + ♥K，小计为负；若再收本墩会被 ×4 |
| 南家收猪 | 低 | 手中 ♠A 可控 |
| 北家全红 | 极低 | 红桃已分散，且北家小计为负，不适合转全红 |

> 注意：东家全红从“已收 10 张”看似很高，但西家收下 1 张红桃后立即归零。这是一个“概率从高瞬间归零”的例子，说明硬事实必须优先于采样，也说明概率必须随每张牌动态更新。

**两种出牌的估算**：

| 出牌 | 本墩归属 | 北家小计变化 | 南家小计变化 | 团队影响 |
| --- | --- | --- | --- | --- |
| ♥2（让北家赢） | 北家收 ♥J+♥Q+♥8+♥2 = -60 | -50 → -110，×4 = **-440** | 0 | 北家被放大，差 |
| ♥A（南家抢下） | 南家收 ♥J+♥Q+♥8+♥A = -110 | 保持 -50，×4 = **-200** | -110 | 用南家 -110 换北家少亏 240，团队净 +130 |

**决策**：

- 北家已收变且小计为负，若再赢下本墩，红桃负分会从 -50 变成 -110，再被亮变 ×4，直接到 -440；
- 南家出 ♥A 抢下该墩，自己承担 -110，但把北家从 -440 拉回 -200，团队净收益为正；
- 若南家判断北家已转全红路线（例如北家已收 10+ 张红桃），则结论反转：应出 ♥2 让北家继续收红桃，因为全红会把红桃反转成正分，变压器反而放大正收益。

这个例子体现三点：

1. **概率是动态的**：西家一张红桃就让东家全红归零；
2. **保护搭档不是无条件**：要看搭档是否在走全红/满贯；
3. **最终仍是效用比较**：自己吃小负分 vs 搭档被变压器放大，选期望损失更小的一边。

### 6.1 分层职责

| 层 | 职责 | 是否接触隐藏信息 |
| --- | --- | --- |
| `buildPlayObservation` | 从 store 裁剪公开信息 | 构造时接触，但只复制白名单 |
| `PublicKnowledge` | 维护缺门、剩余牌、关键牌状态 | 否 |
| `BeliefSampler` | 按公开约束采样可能世界 | 否 |
| `ThreatModel` | 统计四方全红/满贯/猪/羊/变压器陷阱概率，判定模式 | 否 |

## 7. 公共信息信念采样器

### 7.1 未见牌集合

```text
未见牌 = 全 52 张
       − 自己的当前手牌
       − 所有已打出的牌（历史墩 + 当前墩）
```

注意：

- 已收牌属于已打出牌，不重复计算；
- 已亮但尚未打出的牌仍在亮牌者手中，不能放进“任意未知牌”；
- 自己的原始手牌只用于自己的亮猪判断，不用于推断他人；
- 其他三家的原始手牌完全不可见。

### 7.2 硬约束

采样出的每个世界必须满足：

1. **张数**：每家手牌数 = `13 - 该家已出牌数`；
2. **不重复**：52 张牌不重复；
3. **已亮牌归属**：未打出的亮牌必须在该亮牌者手中；
4. **缺门**：某家在某花色领出时垫过其他花色 → 该家该花色剩余张数为 0；
5. **已出牌**：已打出的牌不能再出现在任何人手中；
6. **自己手牌**：自己的手牌固定，不参与采样；
7. **首轮限制**：不改变手牌归属，只影响合法出牌；采样器不需要额外处理，但 rollout 必须使用真实合法出牌函数。

### 7.3 软约束与权重

第一版建议**均匀采样**所有满足硬约束的世界。后续可加入重要性权重：

- 对手曾主动领出某花色 → 该花色长度可能更长；
- 对手在能赢时选择不赢 → 可能在保留大牌/避免收负分；
- 对手早期垫牌 → 可能牌型弱；
- 亮牌行为本身包含信息：亮猪者通常黑桃较长，亮羊者通常方块较强，亮变者通常梅花有控制。

第一版不做复杂对手建模，避免过拟合；但采样器接口预留 `weight`。

### 7.4 采样算法

推荐“按花色分配 + 随机回溯”：

```text
1. 计算每家容量 capacity[p] = 13 - playedCount[p]
2. 先把未打出的亮牌固定到亮牌者
3. 对每个花色 s：
   a. 收集该花色所有未见牌
   b. 排除在该花色缺门的玩家
   c. 按容量随机分配，保证不超过 capacity
4. 若某一步无解，回溯上一步重新随机
5. 若多次失败，放宽软约束（只保留张数/不重复/亮牌归属）并记录警告
```

为了性能，可以先用随机贪心 + 局部交换修复，而不是完整回溯；只有在失败时回退到回溯。

### 7.5 亮猪者原始黑桃张数

`scoreDeal()` 需要 `pigLighterSpadeCount` 判断“单张黑桃亮猪免窝猪”。

- 如果亮猪者是**自己**：使用自己的 `ownOriginalHand` 精确计算；
- 如果亮猪者是**他人**：公开信息只能知道其已打出的黑桃数、是否缺门、是否还持有亮猪；
  - 采样时为其原始黑桃张数生成一个与公开信息一致的假设值；
  - 若其亮猪仍在手中，则原始黑桃张数 ≥ 1；
  - 若其曾在黑桃领出时垫牌，则其当前黑桃为 0，但亮猪必须已打出，矛盾时说明数据异常；
  - 默认按“非单张”处理，除非采样世界生成单张；
  - 该不确定性只影响窝猪 -400 的概率，不影响合法性。

### 7.6 采样数量与复现

| 难度 | 世界数 N | 说明 |
| --- | --- | --- |
| 快速 | 0（纯启发式） | 不采样 |
| 标准 | 32–64 | 默认 |
| 强化 | 128–256 | 可选，时间预算更高 |
| 末局精确 | 16–32 | 剩余 ≤5 墩时，每个世界做精确搜索 |

随机种子：


固定观察 + 固定种子 → 固定采样世界 → 固定出牌，便于测试和复盘。

## 9. 团队感知启发式策略

这一层既要作为 rollout 的内部策略，也要作为时间不足时的兜底。

### 9.1 出牌评分框架

对每个合法牌 `c` 计算：

```text
score(c) =
    w_trick    * 本墩期望团队收益
  + w_future   * 未来控牌/领出权收益
  + w_key      * 关键牌处理收益
  + w_score    * 分数情境收益
  + w_threat   * 概率模式收益（全红/满贯/猪/羊/变压器陷阱）
  - w_risk     * 风险惩罚
  + w_noise    * 少量随机扰动
```

`w_threat` 项由第 5 章的 `ThreatModel` 提供，输入不是“当前墩分数”，而是“这一手如何改变四方全红/满贯/猪/羊/变压器陷阱概率”。例如：

- 打出红桃让敌方全红概率从 55% 降到 5% → 大幅正收益；
- 打出红桃让搭档变压器负向放大概率从 30% 升到 70% → 大幅负收益；
- 让出猪给敌方满贯路线 → 破坏敌方满贯，正收益；
- 自己收猪但自己正在走满贯 → 猪被抑制，负收益很小。

### 9.2 领出策略

领出时没有当前赢家，重点是“把局面引向己方有利的牌型”。

优先级：

1. **安全低牌**：优先非计分、低点数、不会送猪/送红桃的牌；
2. **长套建立**：己方长套且对手可能缺门时，出小牌建立控制；
3. **避免送负分**：不主动领红桃（除非要逼对手收红桃/全红路线）；不主动领猪所在花色（除非有把握）；
4. **逼对手垫牌**：对手缺门时，领该花色可逼其垫牌，但要注意不要逼对手把负分甩给己方；
5. **搭档配合**：如果搭档可能缺门/有控制，领搭档能赢的花色；
6. **关键牌保护**：不轻易领出自己需要保留的 A/K/Q；
7. **分数情境**：
   - 领先：优先安全牌，降低方差；
   - 落后：可领有风险但高收益的花色，争羊/变压器/全红；
   - 己方接近 -1000：绝不主动领红桃/猪门；
   - 对方接近 -1000：可主动领红桃/猪门逼其收负分；
8. **概率模式**（详见第 5 章）：
   - 搭档全红/满贯概率高 → 领搭档能赢的花色，主动喂红桃/关键牌；
   - 敌方全红概率高 → 领红桃逼其必须赢，或领其缺门花色逼其垫红桃；
   - 敌方满贯概率高 → 领黑桃/方块/梅花，逼其关键牌提前暴露；
   - 搭档变压器负向放大概率高 → 不领红桃/黑桃，避免搭档被迫赢；
   - 己方得猪概率高 → 不领黑桃，把黑桃控制让给对手；
   - 对手得猪概率高 → 保持黑桃压力，不主动领黑桃帮其解套。

### 9.3 跟牌策略

跟牌时先判断当前赢家：

| 当前赢家 | 策略 |
| --- | --- |
| 搭档 | 尽量不盖压；如果本墩有正分，搭档赢是好事；如果本墩有负分，考虑是否需要帮搭档挡枪 |
| 对手 | 能赢且本墩正分/关键牌 → 争；能赢但会收负分 → 谨慎；不能赢 → 优先甩负分给对手 |
| 自己 | 已赢则按“保赢/不保赢”判断是否继续加牌（通常一墩只需最大牌） |
| 未知（后面还有人） | 按剩余玩家可能出牌估计胜率，不只看当前最大牌 |

具体规则：

1. **有领出花色必须跟**：在合法集合内选；
2. **搭档赢墩**：
   - 不无谓盖压；
   - 若自己盖压能让本墩分数更安全（例如防止对手反超），可以盖；
   - 若本墩是负分，搭档赢反而可能害搭档，需评估是否接手；
3. **对手赢墩**：
   - 本墩有正分（羊/变压器）→ 尽量争；
   - 本墩有负分（猪/红桃）→ 不要抢，优先让对手收；
   - 若无法赢，优先垫负分给对手，但避免把负分送给搭档；
4. **最后一家**：
   - 当前墩结果已知，直接按“赢/不赢”计算；
   - 能赢且收益为正 → 赢；
   - 不能赢 → 选对团队最有利的垫牌；
5. **缺门垫牌**：
   - 对手赢墩 → 优先垫猪/红桃；
   - 搭档赢墩 → 优先垫非计分牌，避免把负分塞给搭档；
   - 自己赢墩 → 不要垫负分给自己；
6. **变压器**：
   - 自己收变压器：若自己当前总分为正，变压器放大正分（好）；若为负，放大负分（坏）；独拿 +50/+100；
   - 对手收变压器：若对手总分为负，放大负分（对己方好）；若为正，放大正分（对己方坏）；
   - 不要机械地“抢变压器”，要看谁收更有利；
7. **猪**：
   - 猪是负分，送给对手是好事，送给搭档/自己是坏事；
   - 亮猪后猪分 -200，窝猪 -400，风险更高；
   - 若自己亮猪且黑桃只有 1 张，自收只 -200，不触发窝猪，风险相对可控；
8. **羊**：
   - 羊是正分，己方收是好事，对手收是坏事；
   - 若己方已接近 +1000，羊的边际价值下降；若对方接近 -1000，给羊反而可能帮对方脱离负分（需具体计算）；
9. **红桃 A**：
   - 亮♥A 后全场红桃翻倍；
   - 若己方大概率收红桃，亮♥A 会放大己方负分；
   - 若对方大概率收红桃，亮♥A 会放大对方负分（对己方有利）；
   - 出牌阶段无法改变已亮状态，但可以通过“谁收红桃”影响结果；
10. **全红/满贯**：
    - 若己方已收 ≥10 张红桃，评估继续收全红 vs 止损；
    - 若己方已收猪/羊/变压器 + 大量红桃，评估满贯路线；
    - 满贯收益极高，但需要个人集齐，团队配合要避免“分散关键牌”；
11. **概率模式**（详见第 5 章）：
    - 搭档全红概率高 → 搭档赢红桃墩时不盖压，自己赢时尽量把红桃让给搭档；
    - 敌方全红概率高 → 用最大红桃抢下任意含红桃的墩，破红优先于本墩小分；
    - 搭档满贯概率高 → 让猪/羊/变，替搭档挡住对手抢关键牌；
    - 敌方满贯概率高 → 抢猪/羊/变，成本最低的破坏优先；
    - 搭档变压器负向放大概率高 → 主动截红桃/截猪，宁可自己吃小负分；
    - 对手变压器负向放大概率高 → 把猪/大红桃塞给对手，放大其负分。

### 9.4 分数情境调整

| 情境 | 调整 |
| --- | --- |
| 己方小分接近 -1000 | 负分牌风险权重 ×2；优先让对手赢负分墩；避免主动领红桃/猪门 |
| 对方小分接近 -1000 | 负分牌收益权重 ×1.5；主动把猪/红桃送给对方；避免对方通过羊/变压器回到安全区 |
| 己方小分接近 +1000 | 正分牌收益权重 ×1.3；保护领先，避免大起大落 |
| 对方小分接近 +1000 | 正分牌风险权重 ×2；阻止对方收羊/变压器；必要时牺牲己方正分 |
| 己方总猪头领先 | 降低方差，安全第一 |
| 己方总猪头落后 | 提高方差，争高分/满贯/全红 |
| 最后一副/最后一局 | 按盘级裁决，必要时接受本副亏损换取盘胜 |

### 9.5 概率模式调整

| 模式 | 评分调整 |
| --- | --- |
| `own-allred` / `partner-allred` | 红桃正收益权重 ×2；自己收红桃的惩罚上升；让红桃给目标队友的收益上升 |
| `break-opp-allred` | 赢下含红桃墩的收益 ×2；自己吃红桃负分的惩罚下降（视为破红成本） |
| `own-slam` / `partner-slam` | 关键牌收益 ×2；猪的负分惩罚按“满贯抑制”归零；让关键牌给满贯者的收益上升 |
| `break-opp-slam` | 抢关键牌收益 ×2.5；自己收猪的惩罚下降（视为破坏成本） |
| `protect-transformer` | 搭档收红桃/猪的惩罚 ×2；自己截红桃/截猪的负分惩罚 ×0.5 |
| `exploit-transformer` | 对手收红桃/猪的收益 ×2；避免给对手正分 |
| `pig-evade` | 己方收猪惩罚 ×2；领黑桃惩罚上升 |
| `pig-maintain` | 对手收猪收益 ×1.5；不主动领黑桃 |
| `sheep-contest` | 羊收益 ×1.5；方块控制牌保留价值上升 |
| `danger-zone` | 所有负分惩罚 ×2；正分收益 ×0.8 |
| `finish` | 正分收益 ×1.3；负分惩罚 ×0.8 |

> 实现补充（2026-11-22）：红桃去向不是只看当前赢家，还要看“同伴全红是否已被证实放弃”。同伴的全红压力为 0 之前，红桃垫给其他家会直接拆掉同伴的全红，因此优先喂给同伴；只有敌方全红压力更高时，才改为垫给非目标敌方或自己吃进破红。当前赢家是全红目标时，不把红桃喂给目标；其他家一旦收下红桃，同伴全红即被证实破产，此时恢复正常垫牌。该判断与 `allRedPressure()` 使用同一硬事实口径。

### 9.6 兜底启发式伪代码

```ts
function heuristicPlay(
  obs: PlayObservation,
  world: World,
  knowledge: PublicKnowledge,
  threat: ThreatModel,
): number {
  const candidates = obs.legalCards;
  let best = candidates[0];
  let bestScore = -Infinity;

  for (const card of candidates) {
    const trick = evaluateTrickOutcome(world, obs, card, knowledge);
    const future = evaluateFutureControl(world, obs, card, knowledge);
    const key = evaluateKeyCards(world, obs, card, knowledge);
    const scoreCtx = evaluateScoreContext(obs, trick, key);
    const threatDelta = evaluateThreatDelta(obs, card, threat, trick, key);
    const risk = evaluateRisk(world, obs, card, knowledge);

    const total =
      1.0 * trick.teamDelta +
      0.8 * future.teamDelta +
      1.2 * key.teamDelta +
      1.5 * scoreCtx.teamDelta +
      1.8 * threatDelta.teamDelta -
      1.0 * risk.penalty;

    if (total > bestScore) {
      bestScore = total;
      best = card;
    }
  }
  return best;
}
```

`evaluateThreatDelta` 只使用 `ThreatModel` 与公开信息，不接触隐藏手牌。具体权重在实现阶段通过自对弈调参，不在本评审稿中冻结。

## 10. 搜索与决策

### 10.1 主流程：PIMC + rollout

```ts
function choosePlay(obs: PlayObservation, options: AiOptions): number {
  if (obs.legalCards.length === 1) return obs.legalCards[0];

  const knowledge = buildPublicKnowledge(obs);
  const worlds = sampleWorlds(obs, knowledge, options.worlds);

  if (worlds.length === 0) {
    const prior = estimateThreatsFromPrior(obs, knowledge);
    return heuristicPlayWithoutWorld(obs, knowledge, prior);
  }

  // 1. 用同一批世界估计四方概率与模式
  const threat = estimateThreats(obs, knowledge, worlds);

  // 2. 快速启发式给出先验最优（也作为超时兜底）
  const heuristic = heuristicPlay(obs, worlds[0], knowledge, threat);

  const totals = new Map<number, number>();
  for (const card of obs.legalCards) totals.set(card, 0);

  for (const world of worlds) {
    for (const card of obs.legalCards) {
      const sim = cloneWorld(world);
      applyCard(sim, obs.self, card);
      const result = rolloutToEnd(sim, knowledge, threat, options);
      totals.set(card, totals.get(card)! + matchUtility(result, obs).value);
    }
  }

  const best = argmax(obs.legalCards, (card) => totals.get(card)! / worlds.length);
  return options.debug ? best : best ?? heuristic;
}
```

要点：

- `estimateThreats` 与 rollout 共用同一批采样世界，不额外读取隐藏信息；
- `threat` 作为 rollout 内部策略的模式输入，使模拟更接近“团队会怎么打”；
- 若采样失败，`estimateThreatsFromPrior` 只使用解析先验，仍能触发基本保护/破坏模式；
- 超时或异常时回退到 `heuristicPlay`，不返回非法牌。

### 10.2 共同随机数

对每个候选牌使用**同一批采样世界**，降低方差：

- 对每个世界，分别模拟每个候选牌；
- 或者对每个世界只模拟“当前最优候选”并做逐步选择（计算量更小，但方差更大）。

推荐第一版使用“同一批世界 × 全部候选”，因为出牌候选通常只有 2–13 张，世界数 32–64，仍可控制在预算内。

### 10.3 末局精确搜索

当剩余墩数 ≤ `exactTricks`（建议 5）时：

1. 对每个采样世界，使用带 alpha-beta 的精确搜索；
2. 终局直接调用 `scoreDeal()`；
3. 对多个世界的结果求平均；
4. 仍然只使用采样世界，不读取真实隐藏手牌。

精确搜索的输入是 `World`（采样出的四家手牌），不是 `DealState.hands`。

### 10.4 时间预算与降级

```ts
interface AiOptions {
  strength: 'fast' | 'standard' | 'strong';
  worlds: number;
  exactTricks: number;
  timeLimitMs: number;
  seed: number;
}
```

| 强度 | worlds | exactTricks | 时间预算 | 适用 |
| --- | --- | --- | --- | --- |
| `fast` | 0 | 0 | <10ms | 人类提示、低端设备 |
| `standard` | 48 | 4 | 150ms | 默认 AI |
| `strong` | 160 | 5 | 600ms | 复盘/高难度 |
| `analysis` | 256+ | 6 | 2s+ | 离线分析，可选 |

时间预算检查点：

- 每完成一个世界检查一次；
- 超时立即返回当前最优候选；
- 若一个世界都没完成，回退到纯启发式。

### 10.5 决策顺序

1. 唯一合法牌 → 直接出；
2. 构造 `ThreatModel`：解析先验 + 采样频率 → 四方概率 → 模式（含迟滞）；
3. 快速启发式给出初值（带概率模式）；
4. 若时间/强度允许 → 采样世界 + rollout（模式作为内部策略）；
5. 若剩余墩数 ≤ `exactTricks` → 采样世界内精确搜索；
6. 若超时/异常 → 返回启发式最优；
7. 记录调试信息（候选估值、世界数、概率、模式、耗时、是否降级）。

### 10.6 一次决策示例（定性）

假设南家（A 队）当前：

- 本局小分：A = -700，B = +200；
- 当前墩：东家领出 ♥10，北家跟 ♥5，西家跟 ♥Q；
- 南家手中有 ♥A、♥K、♥2，轮到南家最后一家出牌；
- 合法牌为 ♥A、♥K、♥2。

不同策略的差异：

| 出牌 | 结果 | 评价 |
| --- | --- | --- |
| ♥A | 南家赢墩，收下 ♥10+♥5+♥Q+♥A 的负分 | A 队接近 -1000，极差 |
| ♥K | 南家赢墩，收下负分 | 同样差 |
| ♥2 | 西家（B 队）赢墩，B 队收负分 | A 队避免负分，且 B 队负分增加，最优 |

PIMC 会在采样世界中模拟后续墩数，确认“让西家赢”是否会导致 B 队其他收益（例如西家获得领出权后连续收分），再综合选择。这个例子说明：**本墩分数不是唯一目标，分数情境和收牌者归属同样重要**。

## 11. 难度、性能与工程实现

### 11.1 难度设置

建议在开始页或设置中提供：

- **基础**：现有启发式 + 少量牌型/分数修正，最快；
- **标准**：PIMC 48 世界 + 末局精确，默认；
- **强化**：PIMC 160 世界 + 更深末局，较慢。

默认使用“标准”，避免首次进入游戏就明显卡顿。

### 11.2 性能优化

1. **位图表示**：52 张牌用 `bigint` 或两个 32 位整数表示，快速求交/并/计数；
2. **预计算**：花色、点数、基础分、是否计分牌、关键牌表；
3. **合法出牌缓存**：同一手牌 + 当前墩 + 首轮状态可缓存；
4. **世界复用**：同一墩内多个候选共用采样世界；
5. **增量评估**：只重算受影响的花色/牌；
6. **置换表**：末局精确搜索使用状态哈希；
7. **Web Worker**：若标准/强化仍阻塞 UI，将搜索放入 Worker，主线程只负责调度与超时；
8. **降级策略**：低端设备/后台标签页自动降为 `fast`。

### 11.3 UI 集成注意

当前 `recommendedCard` 是 `computed`，会在渲染时同步计算。若直接接入 PIMC，可能导致每次重绘都触发搜索。

建议：

- 人类提示默认使用 `fast`（<10ms）；
- AI 座位使用 `standard`，在 `scheduleAiIfNeeded` 的 `setTimeout` 中计算；
- 若提供“深度提示”按钮，点击后异步计算一次并缓存；
- 出牌后清除缓存；
- 绝不在 `computed` 中做 100ms 以上的搜索。

## 13. 测试与验收

### 13.1 单元测试

| 测试 | 内容 |
| --- | --- |
| 合法性 | 任意观察下返回的牌都在 `legalCards` 中；首轮限制、唯一合法牌正确 |
| 采样张数 | 每个采样世界四家手牌数正确，总牌数 52，无重复 |
| 采样缺门 | 曾垫牌的花色不再出现在该玩家手中 |
| 亮牌归属 | 未打出的亮牌在亮牌者手中 |
| 自己手牌 | 采样不改变自己的手牌 |
| 终局计分 | rollout 终局调用 `scoreDeal`，结果与真实计分一致 |
| 分数情境 | 己方接近 -1000 时不主动收猪/红桃；对方接近 -1000 时主动甩负分 |
| 搭档配合 | 搭档赢墩时不无谓盖压；对手赢墩时优先甩负分 |
| 关键牌 | 猪/羊/变压器/♥A 的处理符合收益方向 |
| 全红概率 | 其他家已收红桃 → 该家 `pAllRed` 立即归零；目标家收满 13 张 → `pAllRed=1` |
| 满贯概率 | `pGrandSlam ≤ pAllRed`；已收 3 张关键牌时 `pGrandSlam ≈ pAllRed` |
| 猪/羊概率 | 已收猪/羊 → 对应概率变 0/1；亮猪后风险权重上升 |
| 变压器陷阱 | 收变且小计为负 → `pTransformerNegative` 上升；收变且满贯路线 → 猪惩罚被抑制 |
| 搭档保护 | 搭档收变且小计为负时，AI 优先截红桃/截猪；搭档走全红时改为喂红桃 |
| 破坏敌方 | 敌方全红概率 > 阈值时，AI 愿意吃小负分破红；敌方满贯概率 > 阈值时，AI 抢关键牌 |
| 模式迟滞 | 概率在阈值附近波动时，模式不抖动 |
| 概率校准 | 500 副模拟中，预测概率与实际频率的 Brier score 不劣于常数基线 |
| 确定性 | 固定观察 + 固定种子 → 固定出牌 |
| 时间预算 | 超时能降级，不抛异常 |

### 13.2 信息边界测试（必须）

构造两个牌局：

- 公开信息完全相同（自己的手牌、当前墩、历史、收牌、亮牌、分数）；
- 其他三家隐藏手牌不同；
- 固定 `samplingSeed`。

断言：

```ts
expect(choosePlay(obs, opts)).toBe(choosePlay(obs2, opts));
```

如果 AI 读取了真实隐藏手牌，这个测试会失败。

### 13.3 模拟测试

- 1000 副全 AI 对局，无非法出牌、无死锁、52 张牌全部收完；
- 全托管连续多局进入盘终；
- 覆盖 5 局制/8 局制/加赛/单局上限；
- 覆盖满贯、全红、窝猪、变压器独拿/非独拿等极端结算。

### 13.4 强度基准

建议用“旧 AI vs 新 AI”自对弈：

- 至少 500 副，双方交换座位，消除发牌偏差；
- 指标：
  - 总猪头差；
  - 本局胜率；
  - 平均本副团队小分；
  - 触发画头/满贯/全红的次数；
  - **敌方全红/满贯被破坏率**（新 AI 应显著高于旧 AI）；
  - **搭档变压器负向放大发生率**（新 AI 应显著低于旧 AI）；
  - **概率校准**：`pAllRed`/`pGrandSlam`/`pPig` 的预测值与实际频率对比；
- 目标：新 AI 在总猪头差上稳定优于旧 AI，而不是只赢几副。

### 13.5 性能基准

- 标准强度单次出牌 P50 ≤ 150ms，P95 ≤ 300ms；
- 强化强度单次出牌 P95 ≤ 800ms；
- 人类提示 P95 ≤ 20ms（fast）；
- 低端设备可降级。

## 14. 风险与限制

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| PIMC 策略融合 | 多个采样世界平均后可能选出“对每个世界都不最优”的牌 | 增加世界数、使用 ISMCTS、对候选做稳健性检查 |
| 采样偏差 | 均匀采样忽略了对手出牌倾向 | 后续加入重要性权重/对手模型 |
| 计算量 | 13 墩 × 多世界 × 多候选可能很慢 | 时间预算、末局精确、启发式兜底、Worker |
| UI 阻塞 | 同步搜索卡住主线程 | 人类提示用 fast；AI 用 setTimeout/Worker |
| 隐藏黑桃张数 | 对手亮猪时无法知道是否单张 | 采样该变量；默认非单张 |
| 概率误估 | 采样偏差导致全红/满贯概率系统性偏高或偏低 | 平滑、向先验收缩、Brier score 校准、迟滞 |
| 概率自证 | AI 按概率行动后，采样世界被自身策略污染，导致概率失真 | 概率估计与 rollout 分离；估计阶段使用中性策略 |
| 模式抖动 | 概率在阈值附近反复穿越，导致策略摇摆 | 进入/退出双阈值 + 同一副内保持 |
| 过度保护 | 为保护搭档变压器而放弃过多正分 | 用期望效用比较，不设无条件保护 |
| 保护与全红冲突 | 搭档走全红时仍机械保护，反而破坏全红 | 优先级：满贯 > 全红 > 变压器保护 |
| 过度拟合 | 权重只针对少量种子调优 | 大样本自对弈、交叉验证 |
| 规则变化 | 未来计分/赛制变化 | 终局统一调用真实 `scoreDeal`/`evaluatePigHeads`/`resolveMatch` |
| 信息边界回归 | 后续开发者误传全量状态 | 类型白名单 + 构造测试 + code review |

### 14.1 明确不做“绝对最优”

完整信息不完全条件下的最优策略是信息集博弈均衡，计算量远超本地单机需求。本设计追求：

- 合法；
- 信息边界正确；
- 比现有启发式明显更强；
- 可解释、可测试、可降级。

8. **随机性**：是否允许少量随机扰动增加变化，还是要求完全确定性？
9. **强度验收**：是否接受“500 副自对弈 + 交换座位，新 AI 总猪头差优于旧 AI”作为门槛？
10. **代码范围**：是否允许重构 `choosePlay` 的签名与 store 调用点，还是要求保持旧接口兼容？
11. **概率口径**：“大红桃”默认按 ♥A/K/Q/J 任一张，还是只按 ♥A/♥K？红桃负分阈值默认 -60 是否合适？
12. **概率阈值**：全红 60%/40%、满贯 35%/25%、变压器保护 40% 的默认阈值是否接受？是否需要在设置中可调？
13. **概率展示**：是否只在复盘/开发模式展示四方概率，正式对局中完全隐藏？
14. **保护优先级**：是否确认“满贯 > 全红 > 变压器保护 > 避猪 > 争羊”的默认优先级？
15. **概率层定位**：概率模型是否在 `fast` 档也默认启用（解析近似），还是只在 `standard/strong` 档启用？本文建议快速档也启用，以保证人类提示和低端设备也能做出基本保护/破坏决策。

### 17.3 术语

| 术语 | 含义 |
| --- | --- |
| 公共信息 | 所有玩家都能看到的信息 |
| 对家 / 搭档 | 本文均指同一队的队友（南↔北、东↔西） |
| 信念状态 | 与公共信息一致的所有可能世界集合 |
| PIMC | Perfect Information Monte Carlo，对采样世界做完美信息模拟并平均 |
| rollout | 从当前局面按策略模拟到终局 |
| 信息集 | 玩家在当前观察下无法区分的世界集合 |
| 策略融合 | PIMC 在多个世界上平均后产生的非最优选择现象 |
| 全红 | 单一玩家收齐 13 张红桃，红桃分反转（未亮♥A +200，亮♥A +400） |
| 满贯 | 单一玩家集齐猪、羊、变压器、全部 13 张红桃，本队直接赢下本局 |
| 变压器陷阱 | 收 ♣10 且最终小计为负，负分被 ×2/×4 放大 |
| 大红桃 | 默认指 ♥A/♥K/♥Q/♥J 任一张，或红桃基础分 ≤ -60 |
| 破红 | 让非目标玩家收下至少一张红桃，使目标玩家无法全红 |
| 迟滞 | 进入/退出使用不同阈值，避免模式在临界点反复切换 |
| Brier score | 概率预测的均方误差，用于校准评估 |
