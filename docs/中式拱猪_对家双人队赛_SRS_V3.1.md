## 一、对评审意见的评估结论

**总体判断：该评审意见基本合理，建议采纳其大部分意见，但需要按 SRS 边界做裁剪后纳入 V3.1。**

- **可直接采纳（P0）**：9.1 出牌阶段补充“自己的剩余手牌/合法出牌集合”；首轮限制明确生效范围并增加 `firstLedSuitStatus`；5.2 计分流水线形式化并增加 `ScoreBreakdown`；满贯基于本副最终收牌归属且不生成正式普通分；6.4/6.5 明确本局胜负字段与兜底裁决；拆分“超时自动出牌”和“断线 AI 接管”；细化服务端状态机、事件记录、幂等与防重复提交；补充随机发牌审计要求；增加计分测试矩阵和平衡性模拟指标。
- **调整采纳（P1）**：房间匹配、UI/UX、战绩统计、规则解释等属于产品与交互需求，不应塞进核心规则章节；V3.1 增加“产品范围与后续需求”章节，列为 P1/P2，不改变核心规则。
- **暂不冻结、保留临时默认**：`autoLightLastOne`、6.4 裁决、20 副兜底、5 局加赛、8 局回溯、断线 AI 策略强度、差值分模式。评审也认为这些应通过模拟和产品确认后再冻结，V3.1 保留⚠️并增加验证要求。
- **不采纳“直接认定符合传统规则”**：评审已说明没有基准传统规则，不能据此认定所有特殊规则符合某地方玩法；V3.1 只保证内部一致和可开发。
- **洗牌审计不指定具体算法**：SRS 规定“可审计洗牌”的要求（算法版本、种子、哈希、重放验证、公开时机），具体算法由技术设计确定，避免 SRS 绑定实现。

**结论：可采纳。以下为修订后的 SRS V3.1 全文。**

## 1. 概述

### 1.1 项目目标

开发一款4人2v2中式拱猪对家赛。游戏以“局”为画猪头段：每局内可连续打多副牌，小分累计用于判定画猪头条件；每达到画猪头条件，本局结束，负方被画相应数量猪头，双方小分清零，进入下一局。最终在规定局数内比较双方累计猪头数，猪头少者获胜。

核心设计：
- 只做南北 vs 东西固定对家赛，不做个人赛。
- 小分不是最终胜负依据，只用于触发画猪头和决定画几头。
- 满贯为个人事件，但触发后本队立即赢下本局，给对方画猪头。
- 支持暗亮：亮牌阶段结束前，其他方只能看到“已亮牌背/数量”，不能看到具体牌。

### 1.2 术语定义

| 术语 | 定义 |
|---|---|
| 盘 | 整场对赛，由固定局数组成（5局制/8局制）；最终比较双方猪头总数 |
| 局 | 画猪头段。从0分开始，可包含多副牌，直到某副牌结算后触发画猪头或满贯；画头后本局结束，小分清零 |
| 副牌 | 一次发牌→亮牌→出牌→结算的完整过程 |
| 小分 | 每副牌个人/团队计分，仅用于判定画猪头条件，不直接决定最终胜负 |
| 猪头 | 本局负方被记录的惩罚标记；盘终猪头少者胜 |
| 窝猪 | 亮猪者本人最终自己收下♠Q，猪分记-400 |
| 满贯 | 单个玩家集齐猪、羊、变压器、全部13张红桃；触发后本队立即赢下本局 |
| 全亮 | **本副牌**四张关键牌均被亮出（含自动亮），不论谁亮 |
| 暗亮 | 亮牌提交阶段互相不可见具体牌，亮牌阶段结束后统一公开 |
| 计分牌 | ♠Q、♦J、♣10、全部13张红桃（含♥4~♥2）。♣10为变压器本身，在独拿判定中作为“变压器”，不计入“其他计分牌” |
| 独拿变压器 | 玩家实际收牌中除♣10外没有任何其他计分牌；普通黑桃/方块/梅花非关键牌不影响独拿 |
| 首轮限制花色 | 本副牌中某花色首次作为领出花色的一墩；限制仅作用于该墩 |
| 差值分 | 可选计分模式，V3.1 不采用；固定团队原始和累计 |
| 正式个人分 | 参与团队小分累计的个人分；满贯触发时不生成正式个人分 |
| 模拟展示分 | 满贯时仅用于展示/复盘的普通计分模拟结果，不参与小分和画头判定 |

## 2. 用户角色与座位

1. 固定4个座位：南、北、东、西。出牌顺序为逆时针：南→东→北→西。
2. 队伍固定：南+北为一队（下称 A 队）；东+西为一队（下称 B 队）。
3. 任意座位可为真人或 AI 机器人，支持真人+真人、真人+AI、AI+AI 混合。
4. V3.1 不提供单打模式、不提供自由换座组队。

## 3. 总体游戏流程

```
创建对局（选择赛制、座位真人/AI）
→ 盘开始
   └─ 新局开始，双方小分清零
      → 发牌（每人13张）
      → 亮牌阶段（暗亮提交，全员提交后先执行自动亮判定，再提前揭晓）
      → 亮牌揭晓（统一公开正面）
      → 出牌阶段（13墩）
      → 副牌结算
         ├─ 满贯判定（结算时判定）：触发则本队赢下本局，给对方画1或2头
         ├─ 普通计分：个人分→团队小分累计
         ├─ 画猪头判定：达到条件则画头，本局结束
         └─ 未触发：继续下一副牌，小分继续累计
      → 本局结束：记录猪头，小分清零
      → 判断赛制是否结束：未结束则进入下一局
→ 盘结束：统计双方总猪头，少者胜；同猪头按赛制规则裁决
```

## 4. 对局规则

### 4.1 发牌与领出

1. 一副牌52张，无大小王，随机洗牌后每人13张。
2. 每局第一副牌：持有♠3的玩家领出，首引花色不限。
3. 局内后续副牌：上一副牌拿到猪（♠Q）的玩家领出，领出花色不限。
4. 若上一副因满贯结束，本局随即结束，不进入下一副；新局第一副重新按♠3规则。
5. 画猪头后本局结束，新局第一副重新按♠3规则。

### 4.2 亮牌规则

#### 4.2.1 可亮牌
♠Q猪、♦J羊、♣10变压器、♥A红桃A。

#### 4.2.2 亮牌阶段
1. 发牌后进入亮牌阶段，玩家自主选择亮/不亮，允许一名玩家同时亮多张关键牌。
2. **暗亮**：亮牌阶段未结束时，自己可见自己亮牌正面；其他方只能看到“已提交亮牌数量/牌背”，不能看到具体牌种。
3. 亮牌阶段结束后，统一公开所有亮牌正面，之后所有人可见。
4. 提交后不可撤回；超时未提交视为不亮；全部4家提交后立即进入揭晓。
5. 自动亮：四张可亮牌已亮3张时，若配置 `autoLightLastOne` 开启（V3.1 默认开启⚠️），由服务端在**全员提交后或亮牌截止时**判定剩余1张自动亮，判定后立即揭晓并公开。
6. 固定为“揭晓后公开正面”，不做“出牌阶段仍隐藏具体亮牌”的扩展模式。
7. 自动亮的牌与其他亮牌同等适用 4.2.4 首轮限制；自动亮在揭晓时公开，未揭晓前不计入“已亮N张”展示。
8. 自动亮判定顺序：先收集4家提交结果；若已亮3张且 `autoLightLastOne` 开启，则将剩余1张标记为自动亮；然后统一揭晓。若关闭自动亮，则按实际提交结果揭晓。

#### 4.2.3 亮牌对计分的影响
亮牌是个人行为，只影响拿牌者计分；满贯画猪头为团队结果，属于例外（见 5.6）。

#### 4.2.4 亮牌首轮限制
1. **每副牌**中，某花色第一次作为领出花色的一墩，该花色中**被亮过的牌**不能领出，也不能跟牌。
2. 限制仅作用于“该花色首次作为领出花色的那一墩”；该墩结算后，该花色首轮限制解除。
3. 若某花色此前仅被垫牌、未被作为领出花色，不消耗该花色首轮限制；该花色首次被领出时才触发。
4. 例外①（跟牌）：若玩家手中该花色仅剩这一张受限制亮牌，跟牌时必须出。
5. 例外②（领出）：玩家不允许主动领出受限制亮牌；允许领出同花色非亮牌。若轮到领出且手中只剩受限制亮牌、无其他合法领出牌，兜底允许任选一张受限制亮牌领出，避免死锁（V3.1 默认⚠️，UI 需提示）。
6. 该限制对亮猪、亮羊、亮变、亮♥A一致适用；自动亮的牌同样适用。
7. 服务端须维护 `firstLedSuitStatus`：♣/♦/♥/♠ 各为 `NOT_LED` 或 `LED`；某花色首次成为领出花色时置为 `LED`，并在该墩执行首轮限制合法性校验。

### 4.3 出牌与收墩

1. 一墩：领出一家出一张，逆时针依次跟牌，4张为一墩，共13墩。
2. 强制跟牌：有领出花色必须跟同花色；没有该花色可任意垫其他花色，垫牌视为本墩最小。
3. 同花色点数最大者赢墩；无将牌，不同花色不比较大小。
4. 赢墩者收下本墩所有分牌，并获得下一墩领出权。
5. 一墩分牌归赢墩个人，结算时先算个人分，再相加为团队小分。
6. 牌大小：A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2。

## 5. 计分规则

### 5.1 基础分值

| 牌 | 名称 | 基础分 | 亮牌后 |
|---|---|---|---|
| ♠Q | 猪 | -100 | -200 |
| ♦J | 羊 | +100 | +200 |
| ♣10 | 变压器 | 特殊倍率 | 倍率升级（×2→×4） |
| ♥A | 红桃A | -50 | -100（即全场所有选手红桃分值×2，含♥A自身） |
| ♥K | 红桃K | -40 | -80 |
| ♥Q | 红桃Q | -30 | -60 |
| ♥J | 红桃J | -20 | -40 |
| ♥10~♥5 | 红桃10~5 | 各-10 | 各-20 |
| ♥4~♥2 | 红桃4~2 | 0 | 0 |

全部红桃原始总分：-200。♥4~♥2虽为0分，仍属于“计分牌/红桃牌”，用于变压器独拿判定与超时垫牌“非计分牌优先”。

### 5.2 个人分计算顺序与 ScoreBreakdown

固定顺序如下，不得调换：

1. 统计四名玩家各自实际收下的分牌，形成原始收牌集合。
2. 判满贯：若触发，进入满贯分支（5.6），本队赢下本局，本副不再生成正式普通个人分。
3. 应用亮牌修正：亮猪按 -200、亮羊按 +200；亮♥A使全场所有选手的红桃分值×2（含♥A自身）。亮变不在此步处理。
4. 判全红（5.4）：在亮♥A翻倍之后反转红桃总分。
5. 处理窝猪（5.5）：亮猪者自收♠Q时猪分直接记 -400，替代亮猪 -200；非亮猪者收♠Q按亮猪后 -200 或未亮猪 -100。
6. 处理变压器倍率（5.3）：独拿则 +50/+100；非独拿则对修正后非零总分×2/×4。
7. 得到个人本副正式分。
8. 团队本副小分 = 南分+北分（A队），或东分+西分（B队）；固定团队原始和累计。
9. 将团队本副小分累加到本局团队小分。

**计算约束：**
- 变压器本身不作为普通正负分参与求和。
- 变压器只影响实际收下♣10的玩家。
- 倍率只应用一次，不允许重复触发。
- 独拿判断基于实际收牌，不基于亮牌状态。
- 全部计算使用整数，不做中间舍入。
- 每个玩家、每副牌必须生成 `ScoreBreakdown`，至少记录：基础分、亮牌修正、全红修正、窝猪修正、变压器修正、最终个人分。结算后可展开查看。

### 5.3 变压器规则

1. **独拿变压器**：玩家实际收牌中，除♣10外没有任何其他计分牌（♠Q、♦J、任意数量红桃，含♥4~♥2），则基础 +50；亮变压器后 +100。普通黑桃/方块/梅花非关键牌不影响独拿。
2. **非独拿变压器**：玩家实际收牌中除♣10外还有任意计分牌（包括猪、羊、任意数量红桃，含0分红桃），则不适用 +50/+100；先按 5.2 顺序累加该玩家修正后总分（含猪、羊、红桃、全红、窝猪等），再对该非零总分×2；亮变则×4。若修正后总分为0，则×2/×4仍为0，不触发 +50/+100。
3. 变压器放大的是“拿到它的那个玩家”的个人分，不直接放大团队分。
4. 示例：
   - 仅♣10 + 普通非计分牌：独拿，+50；亮变 +100。
   - ♣10 + ♥4（0分红桃）：非独拿，修正后总分0，×2/×4仍0，不+50。
   - 窝猪 -400 且亮变：有猪，非独拿，×4 = -1600。
   - 窝猪+全红+亮♥A = 0，且亮变：非独拿，×4仍0。

### 5.4 全红规则

1. 单个玩家收集全部13张红桃：红桃总分从 -200 反转为 +200；若♥A亮牌，先翻倍至 -400 再反转为 +400。
2. 全红只反转红桃分数，猪分照常计算；若同时窝猪，按 5.5 叠加。
3. 全红为个人事件，不支持两人合全红。

### 5.5 窝猪规则

1. 仅当**亮猪者本人最终自己收下♠Q**时触发窝猪，猪分直接记 -400，不再按亮猪 -200 计算。
2. 非亮猪者收下♠Q：无论同伴还是对手，均按亮猪后 -200 计猪分；若猪未亮，收者按 -100。
3. 自动亮的猪若本人自收，算窝猪（V3.1 默认⚠️）。
4. **免窝猪例外**：亮猪时亮猪者手中只有一张黑桃（即 ♠Q 本身），最终由本人自收 ♠Q，不记窝猪；猪分仍按亮猪后的 -200 计算。
5. 窝猪与全红同时发生：先算全红红桃反转分，再叠加窝猪 -400。
   - 窝猪+全红 = -400 + 200 = -200；亮♥A则 -400 + 400 = 0。
6. 窝猪后若该玩家拿变压器且亮变，按 5.3 非独拿处理：对最终个人非零总分应用×4。
   - 窝猪-400且亮变 → -1600；窝猪+全红=-200且亮变 → -800；窝猪+亮♥A全红=0且亮变 → 0（×4仍0，不触发 +50/+100）。
7. 满贯触发时，不触发窝猪，不计算猪负分。

### 5.6 满贯规则

1. 满贯条件：单个玩家集齐猪、羊、变压器、全部13张红桃。必须个人拿齐，不支持合满贯。
2. 满贯一律在**整副牌结算时**判定，不做墩内中断。
3. **满贯判定依据是本副牌最终收牌归属**，不是手牌、亮牌或曾经持有的牌。
4. 满贯优先级最高：触发后本队立即赢下本局，不结算普通小分，不触发窝猪，不再检查小分阈值。
5. 满贯给对方画猪头：
   - 非全亮：对方画1头。
   - 四张全亮：对方画2头。
6. “四张全亮”定义：**触发满贯的该副牌**四张关键牌均被亮出（含自动亮），不论谁亮。
7. 满贯时满贯者自己得猪也不计负分；普通分牌仅可做展示/复盘，不参与本局小分和画头判定。满贯触发后，本局之前已累计小分不再用于画头，本局结束清零，仅保留展示/复盘数据。
8. 满贯时**不生成正式普通个人分**，不将该副牌普通分加入局累计小分；可生成仅用于展示/复盘的“模拟展示分”，并明确标记“非正式、不计入小分”。
9. 满贯本局结束后，双方小分清零，进入下一局。

## 6. 画猪头判定与一局结束

### 6.1 判定流程

每副牌结算后：
1. 先判满贯（5.6）：触发则按 6.3 处理，结束本局。
2. 未触发满贯，累加团队小分后按 6.2 表判定。
3. 触发画头则本局结束；未触发则继续下一副牌。

### 6.2 普通画猪头条件

设 A 队、B 队本局累计小分为 SA、SB。**画头结果列指“被画头的一方”**。正分阈值是进攻：某队小分达到 +1000 或更高，由对方被画头；负分阈值是防守：某队小分达到 -1000 或更低，本队被画头。

| 触发条件 | 画头结果（被画头方） | 本局胜者 |
|---|---|---|
| 仅 SA ≤ -1000 | A队画1头 | B队 |
| 仅 SA ≥ +1000 | B队画2头 | A队 |
| 仅 SB ≤ -1000 | B队画1头 | A队 |
| 仅 SB ≥ +1000 | A队画2头 | B队 |
| SA ≤ -1000 且 SB ≥ +1000 | A队画3头 | B队 |
| SA ≥ +1000 且 SB ≤ -1000 | B队画3头 | A队 |
| SA ≥ +1000 且 SB ≥ +1000 | 双方各画2头 | 按 6.4 裁决 |
| SA ≤ -1000 且 SB ≤ -1000 | 双方各画1头 | 按 6.4 裁决 |

说明：
- 单队不可能同时满足正负两条阈值，无需额外规则。
- 某队小分达到 +1000、+2000 或更高，均按“对方被画2头”处理，不是给自己画头。
- 双方均正高时，双方各自的正高分别使对方画2头，故双方各画2头。
- 双方均负低时，双方各自的负低分别使本队画1头，故双方各画1头。

### 6.3 满贯画头

满贯优先于普通阈值：触发满贯即本队赢下本局，给对方画1头（非全亮）或2头（该副四张全亮），不再检查 6.2 表。

### 6.4 新增猪头相同时的本局裁决（临时默认⚠️）

双方本局新增猪头数相同时，依次比较：
1. 本局双方累计小分，小分更低（更负）的一方为本局负者；
2. 若小分也相同，本局判和局，双方各记本局胜负为平。

统一定义：
- `roundWinner`：本局胜者，可为 A队、B队、NONE。
- `roundLoser`：本局负者，可为 A队、B队、NONE。
- `roundResult`：`A_WIN`、`B_WIN`、`DRAW`。
- 6.4 仅用于记录本局胜负和 8 局制回溯，不改变总猪头比较。

### 6.5 一局兜底终止（新增⚠️）

单局设副数上限（默认20副，可配置）。达到上限仍未触发画头时：
1. 比较双方本局累计小分，小分更低方被画1头，另一方为本局胜者，本局结束；
2. 小分相同则双方各画1头，本局按 6.4 判和局。

### 6.6 画头后处理

1. 本局立即结束。
2. 记录双方本局新增猪头数，累加到本盘总猪头。
3. 双方本局小分清零。
4. 进入下一局；新局第一副由持♠3者领出，首引花色不限。

## 7. 赛制与最终胜负

### 7.1 5局制

1. 固定进行5局，累计双方总猪头数。
2. 5局后猪头总数少者获胜。
3. 若5局后双方总猪头数相同，进入加赛（临时默认⚠️）：
   - 加赛采用“突然死亡”：每加赛1局结束后比较**总猪头数**，总猪头少者立即获胜。
   - 若总猪头仍相同，继续加赛，直至分出胜负。
   - 6.4 仅用于记录该加赛局本局胜负，不直接决定加赛胜负。
   - 加赛局产生的猪头正常累计入总猪头。

### 7.2 固定8局制

1. 固定进行8局，累计双方总猪头数。
2. 8局后猪头总数少者获胜。
3. 若8局后双方总猪头数相同，判**最后一局输者负**。最后一局输者定义（V3.1 默认⚠️）：
   1. 最后一局新增猪头多者为本局输者；
   2. 若最后一局双方新增猪头相同，按 6.4 判本局胜负；若 6.4 判出胜负，该局负者为输者；
   3. 若 6.4 判和局，依次向前回溯最近一局有胜负的局，该局负者为输者；
   4. 若整盘无胜负局（极端情况），双方判和。

### 7.3 本局胜负用途

本局胜负用于：记录本局谁赢、固定8局同猪头时回溯裁决、展示与战绩。最终胜负仍以总猪头数少者为准。UI 在盘终必须展示最终裁决依据，不能只显示胜/负。

### 7.4 计分模式备注

V3.1 固定采用团队**原始和**累计。该模式下：
- 正分（羊、变压器、全红）是进攻性资源：本队正分越高，越会使对方被画猪头。
- 负分（猪、红桃）是防守风险：本队负分越低，本队越会被画猪头。
- 玩家策略上会争抢羊、变压器、全红，同时规避猪和红桃负分，与传统“抢羊抢变”体验一致。
- 差值分模式列为后续可选；若产品需要调整攻防平衡，可再评估。

## 8. 对局过程管理

### 8.1 限时

| 环节 | 时限（默认，可配置） |
|---|---|
| 亮牌阶段 | 30秒（可设 5~60 秒，或“无读秒”） |
| 每墩出牌 | 20秒（可设 5~60 秒，或“无读秒”） |

> 两种读秒都只在剩余 10 秒及以内显示倒计时并语音播报；若配置时限不足 10 秒，则从实际秒数开始读秒。  
> 无读秒时不启动倒计时，也不会自动提交/出牌，需玩家手动操作；AI 座位仍按 AI 调度行动。

### 8.2 超时自动出牌

1. 亮牌超时未提交：视为不亮。
2. 出牌超时：由系统按“最小合法牌规则”自动打出，对局不中断。
3. 最小合法牌规则：在合法出牌集合中，优先非计分牌，再按点数最小；若必须跟牌，同花色最小合法；若受首轮限制，按合法牌选择。
4. 系统代打需在 UI 明确标记，复盘可见。

### 8.3 断线重连与 AI 接管

1. 断线 AI 接管与超时自动出牌不同：断线后立即由**基础策略 AI** 接管并标记（V3.1 默认⚠️），不是简单最小合法牌。
2. 断线后保留座位60秒；60秒内重连：恢复正常操作，历史牌局状态全量同步。
3. 超时未归：判为离场，该座位由基础策略 AI 永久接管至本盘结束。
4. 基础策略 AI 必须遵守第9章信息集，不得读取未公开手牌、未揭晓亮牌或牌堆剩余牌；第一版至少支持合法出牌、基本跟牌/垫牌、基础计分规避。

### 8.4 真人离场

真人主动退出按 8.3 第3条处理，不可中途换人。

## 9. 信息可见性与AI

### 9.1 信息集（接口级约束）

服务端按阶段下发信息，任何客户端（含 AI）不得获取超出下表的信息：

| 阶段 | 可见信息 |
|---|---|
| 暗亮阶段 | 自己的13张手牌、自己亮牌正面、每家已提交亮牌数量（不含尚未判定的自动亮；仅数量与牌背，不含牌种） |
| 亮牌揭晓后 | 自己的手牌、所有亮牌正面（含自动亮） |
| 出牌阶段 | 自己的剩余手牌、当前合法出牌集合、各家剩余牌数、当前墩出牌情况、历史出牌记录 |
| 结算后 | 各玩家本副收牌明细、个人分、团队分、计分过程（ScoreBreakdown） |

硬约束：
- 暗亮阶段其他方不能通过任何接口获取具体亮牌。
- 不能获取其他玩家的剩余手牌。
- 不能获取尚未公开的任何牌。
- AI 与真人使用同一权限边界。

### 9.2 AI约束

1. AI 只接收与真人玩家相同的信息集，不得读取未公开手牌、未揭晓亮牌、其他玩家手牌或牌堆剩余牌。
2. AI 需支持合法出牌、基本跟牌/垫牌、基础计分规避。
3. 高级AI亮牌策略、关键牌概率推断、搭档信号解读列为后续阶段。
4. 断线/离场 AI 与座位 AI 使用同一信息约束；策略强度可配置。

### 9.3 信号系统

V3.1 不做信号系统：UI 不展示信号解读，AI 不依赖信号。

## 10. 数据模型与状态机

### 10.1 状态机

```
盘(Match) ──包含──> 局(Round) ──包含──> 副(Deal)
副的状态机：
  DEALING → LIGHTING → REVEALING → PLAYING → SCORING → ROUND_CHECKING → COMPLETED
PLAYING 子状态：
  WAITING_FOR_LEAD
  WAITING_FOR_FOLLOW_1
  WAITING_FOR_FOLLOW_2
  WAITING_FOR_FOLLOW_3
  TRICK_SETTLING
局结束 → 新局 或 盘结束 → 终局结算
```

要求：
- 所有状态转换由服务端权威执行。
- 重复提交、过期请求、状态不匹配请求必须被幂等拒绝。
- 同一墩不得重复结算。

### 10.2 核心实体（最小集）

- Match：赛制、局数上限、双方总猪头、状态、`auditSeed`、`shuffleAlgorithmVersion`。
- Round：本局双方小分、本局新增猪头、副数计数、状态、`winner/loser/result`。
- Deal：四家手牌、亮牌记录（含自动亮标记）、`allKeyCardsLit`、`firstLedSuitStatus`、13墩记录、领出权、结算结果。
- Trick：领出者、四张出牌、赢墩者、分牌归属。
- Player：座位、真人/AI、断线状态、`takeoverMode`。
- GameEvent：游戏事件记录。
- PlayerAction：玩家亮牌、出牌、操作记录。
- ScoreBreakdown：计分中间过程。
- StateSnapshot：关键状态快照。
- AuditRecord：洗牌、种子、发牌哈希及审计信息。

### 10.3 事件记录要求

至少记录以下事件：
```
DEAL_CREATED
PLAYER_LIGHT_SUBMITTED
AUTO_LIGHT_TRIGGERED
LIGHT_REVEALED
CARD_PLAYED
TRICK_COMPLETED
SCORE_CALCULATED
PIG_HEAD_ASSIGNED
ROUND_COMPLETED
MATCH_COMPLETED
PLAYER_DISCONNECTED
AI_TAKEOVER_STARTED
PLAYER_RECONNECTED
TIMEOUT_AUTO_PLAY
```

### 10.4 回放与审计

1. 每副牌记录完整操作序列（含系统代打、AI接管标记），支持整盘回放。
2. 发牌结果记录随机种子，支持重现与审计。
3. 审计要求：记录洗牌算法版本、随机数算法/版本、种子、发牌哈希、公开时机；支持按种子重放验证发牌结果。仅有种子字段不构成完整审计方案。
4. 具体洗牌算法由技术设计确定，但必须满足可重放、可验证、不可预测。

## 13. 验收要点

1. 暗亮阶段其他方无法通过任何接口获取具体亮牌；自动亮未揭晓前不提前展示。
2. 亮牌首轮限制正确作用于每副牌：仅该花色首次作为领出花色的那一墩生效；受限制亮牌不能领出、不能跟牌；唯一亮牌跟牌必须出；允许领出同花色非亮牌；兜底领出不死锁；该墩结算后解除。
3. 窝猪仅亮猪者自收触发-400；被同伴或对手收按-200；未亮猪收者按-100；自动亮猪自收算窝猪。
4. 数值用例：
   - 窝猪+全红 = -200；窝猪+全红+亮♥A = 0；窝猪+亮变 = -1600；窝猪+全红+亮♥A+亮变 = 0（非独拿×4仍0）。
   - 独拿变压器 +50，亮变 +100；仅♣10+♥4（0分红桃）为非独拿，结果0，不+50。
5. 满贯在结算时判定，基于本副最终收牌归属，立即结束本局，不结算普通小分，不触发窝猪；按触发满贯的该副牌四张关键牌是否全亮，给对方画1或2头；不生成正式普通个人分。
6. 普通画猪头表（6.2）全组合正确：正分高使对方被画头，负分低使本队被画头；含对称组合；画头后小分清零；`roundWinner/roundLoser/roundResult` 正确。
7. 局内未画头可多副累计，下一副由上一副拿猪者领出；单局达副数上限按6.5兜底，兜底后本局胜负正确。
8. 5局制/8局制最终猪头比较和同猪头裁决（含加赛、回溯）正确；UI 展示裁决依据。
9. 超时自动出牌与断线 AI 接管行为不同且符合第8章；断线立即 AI 代打并标记；重连全量同步。
10. 任意座位真人/AI混合可正常对局；AI 不超出公开信息集；出牌阶段接口返回自己的手牌和当前合法出牌集合，不返回他人手牌。
11. 无单打、无自由组队入口。
12. 支持整盘回放、发牌种子审计、事件记录与幂等防重复提交。
13. 每个玩家每副牌有 ScoreBreakdown，可展开查看计分中间过程。
14. 计分测试矩阵覆盖亮猪/不亮猪、亮羊/不亮羊、亮♥A/不亮♥A、全红/非全红、窝猪/非窝猪、亮变/不亮变、独拿/非独拿及总分为零组合。

## 14. 服务端接口与事件需求（新增，P0）

### 14.1 通用约束

1. 服务端为权威状态源，客户端只提交操作意图，不得直接修改状态。
2. 所有请求携带 `matchId`、`roundId`、`dealId`、`actionSeq`、`actionId`；服务端按 `actionId` 幂等处理。
3. 非法操作返回明确错误码，不改变状态。
4. 客户端不得通过任何接口获取超出 9.1 的信息。

### 14.2 核心接口（逻辑接口，不限定传输协议）

| 接口 | 作用 | 关键约束 |
|---|---|---|
| 创建/加入对局 | 创建盘、分配座位 | 固定4座，不提供自由组队 |
| 亮牌提交 | 提交亮/不亮选择 | 暗亮，不可撤回，超时视为不亮 |
| 亮牌揭晓同步 | 下发所有亮牌正面 | 全员提交/截止并完成自动亮判定后 |
| 出牌提交 | 提交出牌 | 服务端校验合法出牌集合、首轮限制、轮次 |
| 墩结算同步 | 下发本墩结果 | 防重复结算 |
| 副结算同步 | 下发 ScoreBreakdown、收牌明细 | 满贯时标记正式/模拟 |
| 局/盘结算同步 | 下发猪头、胜负、裁决依据 | 含 roundWinner/loser/result |
| 断线恢复 | 全量快照+事件增量 | 60秒内恢复 |
| 回放/审计查询 | 按盘查询事件、种子、哈希 | 权限控制 |

### 14.3 错误码分类

至少包括：非法操作、非当前行动者、状态不匹配、重复请求、超时、权限不足、信息越权、内部错误。

## 15. 测试规范与计分矩阵（新增，P0）

### 15.1 单元测试

必须覆盖：
- 计分流水线各步骤及 ScoreBreakdown。
- 变压器独拿/非独拿、亮变/不亮变、总分为零。
- 窝猪自收/同伴收/对手收/未亮猪收。
- 全红、亮♥A、窝猪叠加。
- 首轮限制：唯一亮牌跟牌、无其他红桃、无领出花色、只剩受限制亮牌兜底、花色曾垫牌未领出。
- 6.2 全组合、6.4、6.5。
- 满贯判定与全亮按副。
- 自动亮时点。

### 15.2 计分组合矩阵

至少覆盖以下维度组合：
亮猪×自收/同伴/对手；亮羊×收/不收；亮♥A×全红/非全红；窝猪×全红；亮变×独拿/非独拿；修正后总分为0；满贯×全亮/非全亮。

### 15.3 集成测试

- 多人并发提交、超时、重复提交、断线重连、AI接管。
- 状态机非法转换拒绝。
- 信息越权接口测试。
- 回放与种子重放一致性。

### 15.4 模拟测试与平衡性指标

先开发无 UI 规则模拟引擎，统计：
平均每局副数、平均每盘时长、满贯发生率、窝猪发生率、双方同时画头比例、20副兜底触发率、先手/座位胜率、真人与AI胜率、+1000/-1000阈值触发频率、变压器极端分分布。

模拟必须使用真实规则、随机发牌和符合信息约束的AI策略。平衡性参数验证后再冻结。

## 16. 非功能与公平性审计（新增，P1）

1. 性能：单房间出牌响应满足产品设定；支持多房间并发；超时与AI代打不阻塞对局。
2. 安全：服务端权威校验；信息隔离；防篡改；操作日志不可抵赖。
3. 稳定性：断线恢复、幂等、重复请求防护、异常状态可恢复。
4. 可观测性：关键事件日志、错误码、审计记录。
5. 公平性：可重放洗牌；记录算法版本、种子、哈希；公开时机由产品配置；支持审计验证。

## 17. 产品范围与后续需求（新增，P1/P2，不改变核心规则）

### 17.1 第一版建议范围

- 支持好友房/人机混合对局；公开匹配、观战可后置。
- 固定4座，不提供自由组队、单打。
- 基础战绩：每盘胜负、双方最终猪头、每局小分、每副个人分、满贯/窝猪/独拿/亮牌/AI代打次数。
- UI 必须同时展示小分与猪头，结算可展开 ScoreBreakdown 和裁决依据。

### 17.2 UI/UX 需求（P1）

手牌排序与分牌标记、亮牌选择与提交状态、自动亮提示、当前行动玩家与倒计时、合法出牌提示、系统代打/AI接管标记、本副/本局/整盘结算、规则解释入口。

### 17.3 房间与匹配（P1/P2）

创建房间、邀请好友、房主指定AI座位、未满4人处理、公开匹配、观战。V3.1 不冻结具体方案，第一版建议只做好友房/人机混合。

### 17.4 运营与数据（P2）

排行榜、历史记录、统计报表、平衡性数据采集。
