# 现有亮牌规则文件审查报告

**审查对象**：`rules/` 目录下模块 A/B/C/D 与 YAML 配置草案。  
**参照**：`docs/中式拱猪_对家双人队赛_SRS_V3.1.md`、当前实现交互（亮牌提交即公开、第四张自动亮可配置、读秒 5–60 秒或无读秒、单张黑桃亮猪免窝猪）。  
**结论**：分层设计合理，但当前文件还不能作为“代码只读配置”的唯一依据；存在定义冲突、边界跳变、配置缺失和与现行计分规则脱节的问题。

## 一、总体评价

合理之处：

1. A→B→C→D 分层清晰：分数基准、牌型修正、满贯修正、综合约束职责分离。
2. 使用分支旗标、乘性因子、阈值与互斥表，便于配置化和审计。
3. 有调试字段与采样/确定性双模式的设计意识。
4. 对殉爆、冲锋、绝境博弈等极端分数场景有明确策略方向。

主要问题：

- 部分核心变量定义自相矛盾，按原文无法唯一实现。
- 分支入口处存在概率突降，和“越接近临界越应该亮”的策略意图相反。
- C 模块缺少可执行的满贯概率估算器，且正文有大量文本损坏。
- YAML 并未覆盖 A/B/C/D 的全部参数，且与正文表格数值不一致。
- 与当前实际规则（一次性亮牌、单张黑桃免窝猪、自动亮默认开启）存在冲突或遗漏。

## 三、建议修正的问题（P1）

1. **术语统一**：本游戏用“满贯”表示猪+羊+变压器+全部红桃；“全红”只表示全部红桃。避免“一条龙”与满贯混用。
2. **“我方”定义**：AI 只能读取本座位手牌；“我方”不得解释为搭档手牌并集。
3. **YAML 形式**：当前是 `.txt` 且包在 Markdown 代码围栏中，不能直接加载；应改为纯 `.yaml`。
4. **D.7 公式**：存在嵌套 `aligned` 和转义错误，需重写。
5. **截断区间**：模块 B 为 `[0.05, 2.50]`，YAML 为 `[0.1, 2.0]`；V1 采用 `[0.05, 2.50]` 并集中配置。
6. **三张变压器上限 0.90**：应明确是 `F_cnt` 上限还是 `F_card` 上限；V1 定义为仅限制 `F_cnt`。
7. **互斥算法**：“每新增一张，集合内所有成员概率乘以 F_mutex”存在顺序依赖和重复衰减；V1 改为“最终集合的统一互斥因子”。
8. **采样可复现**：未指定随机种子来源；V1 要求由发牌种子、座位、副序号派生。
9. **合法性约束**：AI 模块未明确“只能亮自己持有的关键牌、不能重复亮、超时视为不亮”；应作为硬约束写入。
10. **边界测试**：应覆盖 S=-1000、-800、-600、0、+800、+1000 及阈值等号情形。
11. **参数标定**：当前常数多为经验值，缺少模拟验证；应先离线模拟，再冻结。
12. **文档可维护性**：C 模块的 MathJax、列表和引用符损坏较多，建议重排。

## 四、关于分值临界：绝对分值改为相对分值

现有模块 A 使用 `S_me < -800`、`S_op < -500`、`S_me > +800`、`S_op > +700` 等绝对分值触发分支与硬否决。这会把“双方都接近 +1000”或“双方都接近 -1000”误判为极端局面，即使双方实际差距很小。

V1 改为以**当前局双方小分差**作为策略临界量：

$$
\Delta = S_{me} - S_{op},\qquad x=\frac{\Delta}{S_{ref}}
$$

- `S_me`：本队当前局小分；`S_op`：对方当前局小分。
- `S_ref`：相对分值尺度，默认 1000，可配置。
- `x > 0`：本队领先；`x < 0`：本队落后；`x = 0`：均势。
- 绝对 ±1000 只保留为**游戏终止线**，不再直接作为 AI 分支阈值。
- 分支阈值改为相对阈值：`x ≤ -0.60` 殉爆；`-0.60 < x ≤ -0.30` 绝境博弈；`x ≥ +0.60` 冲锋；其余常规。
- 原“敌方超过 +700 禁羊”改为相对否决：`x ≤ -0.80` 时禁羊。
- 常规基准公式也改用 `x` 表达，避免同一局中因双方共同涨分而误触发。

这样可解决“双方都 +900 但差距 0”和“双方都 -900 但差距 0”被绝对阈值误判的问题。

## 五、审查结论

- 保留 A/B/C/D 的分层思想，但**不能直接照原文编码**。
- V1 应冻结以下口径：花色长度作为张数、统一 `k_top`、分支 B/C 取 `max`、分值临界使用相对分值、C 可选且默认关闭、D 统一互斥与上限、单张黑桃免窝猪、一次性亮牌、自动亮可配置。
- 详细可执行规则见：`rules/拱猪亮牌规则_V1.0.md`。
