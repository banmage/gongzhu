# 打牌策略规范 V1.0（已归档）

> **已归档**：本文件已于 2026-11-24 被 [`docs/打牌策略规范 V2.0.md`](../docs/打牌策略规范%20V2.0.md) 替代。
> 保留原文仅用于追溯；不得作为当前开发、测试或验收依据。
> 现行规则以 `docs/中式拱猪_对家双人队赛_SRS_V3.1.md` 为准。

> **定位**：人类策略提示与 AI 出牌策略共用规范。  
> **规则基准**：以《中式拱猪【对家双人队赛】SRS V3.1》为准；满贯为“本队赢下本局、对方画 1/2 头”，不采用旧版“满贯 +800”口径。  
> **信息边界**：只使用自己的手牌、已公开亮牌、已出牌/收牌、剩余张数、首轮状态、当前墩、历史墩、本局小分、本盘猪头、赛制阶段。**不读取他人手牌，不依赖暗号；下文“信号”均指从公开出牌中可推断的意图。**  
> **目标**：在合法出牌前提下，最大化己方团队从“本副小分 → 本局画头 → 本盘猪头/胜负”的期望收益。

---

## 1. 核心决策框架

每一手按以下顺序决策：

1. **合法牌过滤**：首轮限制、强制跟牌、唯一合法牌先处理。
2. **更新公开知识**：未见牌、缺门、剩余张数、关键牌归属、已收关键牌。
3. **更新四方动态概率**：每家收全红、满贯、得猪、得羊、得变压器、变压器负向放大概率。
4. **判定分数情境**：己方/对方距 ±1000、总猪头差、是否最后一副/加赛。
5. **判定威胁模式**：己方/搭档全红或满贯、敌方全红或满贯、搭档变压器风险、避猪/争羊等。
6. **判断当前墩归属与攻防方向**：谁赢对本队有利、本墩分数与关键牌。
7. **候选牌评分**：本墩收益 + 未来控制 + 关键牌处理 + 分数情境 + 威胁模式 − 风险 − 信息泄露。
8. **选择最高分**；平局优先安全、少泄露、可复现随机。

> 关键原则：**正分是进攻资源**（己方 +1000 使对方画头）；**负分是防守风险**（己方 -1000 本队被画头）。出牌不能只看“本墩谁收分”，必须看“谁收、收后概率如何变、是否改变画头/满贯路线”。

## 2. 公开信息与关键牌归属推断

### 2.1 硬事实优先

关键牌归属按以下优先级更新，硬事实直接置 0/1：

| 信息 | 推断 |
|---|---|
| 已亮且未打出 | 100% 在亮牌者手中 |
| 已打出/已收 | 归属收牌者，不再属于手牌 |
| 自己手牌 | 100% 自己持有 |
| 某家在某花色领出时垫过其他花色 | 该家该花色已缺门，剩余张数 0 |
| 某家已收红桃 | 其他家全红概率立即归零 |
| 某家已收 3 张关键牌 | 该家满贯概率退化为全红概率 |
| 某家已收猪 | 其他家得猪概率归零 |

### 2.2 软信息推断

在硬事实之外，用公开出牌推断关键牌位置与意图：

| 观察 | 推断 | 策略含义 |
|---|---|---|
| 首轮领短套 | 该家想制造缺门，卖出猪/♥A/红桃 | 同伴短套可帮其垫负；敌方短套要防其甩负 |
| 首轮领长套 | 该家有控制，想帮同伴卖牌或建立长套 | 保留该花色大牌配合/阻止 |
| 首轮领 A | 强控信号，想收该花色或逼关键牌 | 不轻易盖，除非要破全红/满贯 |
| 跟同花色大牌 | 欢迎继续该花色、有控制 | 可继续领；但防其诱骗 |
| 跟同花色最小牌 | 不欢迎、无控制、请求换花色 | 换花色或让同伴接手 |
| 搭档赢墩时不盖 | 让搭档收 | 若本墩负分且搭档有变压器风险，考虑接手 |
| 对手赢墩时垫负分 | 甩负 | 不要让同伴接；能截则截 |
| 敌方主动拱猪 | 想送猪 | 避免自己收猪；可用黑桃控制逼其自收 |
| 敌方不领黑桃 | 可能持猪等断门 | 保持黑桃压力，不帮其解套 |
| 敌方亮猪 | 想送猪，且猪分翻倍 | 不接猪；有猪圈可拱其自收窝猪 |
| 敌方亮羊 | 想争羊 | 抢方块控制，阻止其落羊 |
| 敌方亮变 | 可能正分放大或陷阱 | 若其小计为负，塞猪/大红桃放大；若为正，阻止正分 |
| 敌方亮♥A | 红桃翻倍 | 若其全红概率低，让其收红桃放大负分；全红概率升高则优先破红 |

### 2.3 关键牌剩余分布与安全脱手

维护每张关键牌 `k` 的归属概率 `P(k∈p)` 与“被谁收下”概率 `P(p收k)`。当剩余关键牌集合缩小，可确定脱手目标。

**示例**：♠Q 未出，黑桃未见牌只剩 ♠Q 和一张小黑桃 ♠x；东、西已缺黑桃，则 ♠Q 只能在南/北中；若自己持 ♠x，则 ♠Q 必在另一家。若另一家是敌方且接近 -1000、或亮变、或负分风险高，可出 ♠x 诱导其赢墩收猪；若另一家是同伴，避免让其收猪，除非同伴在走满贯。

**安全脱手矩阵**：

| 关键牌高概率归属 | 优先让谁收 | 避免让谁收 |
|---|---|---|
| 猪在敌方且敌方负分风险高/亮变 | 该敌方 | 同伴、自己 |
| 猪在敌方普通 | 敌方 | 同伴；自己单张亮猪可控时可接受 |
| 猪在同伴 | 敌方 | 同伴，除非同伴满贯路线 |
| 羊在己方控制范围 | 己方 | 敌方 |
| 变在搭档且搭档小计为负 | 自己截负 | 搭档 |
| 变在对手且对手小计为负 | 塞猪/大红桃给对手 | 给对手正分 |
| ♥A 在敌方且敌方全红概率低 | 让其收红桃放大负分 | 帮其全红 |
| ♥A 在敌方且全红概率升高 | 破红 | 继续喂红 |

> 关键牌归属概率不是“持有概率”本身；亮猪者持有♠Q 是 100%，但收猪概率可能很低，因为他可以用黑桃大牌送出。

## 3. 四方动态威胁概率与模式

### 3.1 需要动态维护的概率

对每家 `p`（含自己）维护：

- `pAllRed(p)`：收齐 13 张红桃；
- `pGrandSlam(p)`：集齐猪、羊、变、全部红桃；
- `pPig(p)`：最终收猪；
- `pSheep(p)`：最终收羊；
- `pTransformer(p)`：最终收变；
- `pTransformerNegative(p)`：收变且小计为负；
- `pTransformerTrap(p)`：收变且同时收猪/大红桃；
- `pHeartA(p)`：收♥A；
- `pEffectivePig(p)`：满贯抑制后的有效猪风险。

团队级统计“任一成员完成”的频率，不要简单把两人概率相加。

### 3.2 概率变化如何影响策略

| 概率区间 | 策略含义 |
|---|---|
| 0（硬事实已破） | 不再考虑该路线 |
| 0–10% | 只做低成本保留，不豪赌 |
| 10–40% | 开始关注，避免无意破红/送关键牌 |
| 40–75% | 进入对应模式，团队配合/破坏 |
| >75% | 优先服务/破坏，允许牺牲本墩小分 |

**硬事实优先于采样**：某家收下 1 张红桃，其他家全红立即归零；某家收 3 关键牌，满贯≈全红；某家收猪，其他家得猪=0。

### 3.3 模式优先级

默认优先级，但最终仍由期望效用比较：

1. 己方/搭档满贯；
2. 破坏敌方满贯；
3. 己方/搭档全红；
4. 破坏敌方全红；
5. 保护搭档变压器负向放大；
6. 利用对手变压器负向放大；
7. 避猪/保持对手猪压力；
8. 争羊；
9. 分数临界（己方 -1000 防守、对方 -1000 施压、±1000 攻防）；
10. 常规。

冲突消解：满贯 > 全红；己方成事 > 阻止敌方；高杠杆事件允许在较低概率提前防守；确定性小损失可换不确定性大损失；不为小概率豪赌。

## 4. 攻防信息解读

### 4.1 己方攻防

| 局面 | 攻击信息 | 防守信息 |
|---|---|---|
| 己方正分接近 +1000 | 争羊/变/正分红桃，主动施压 | 防对方破坏正分 |
| 对方负分接近 -1000 | 继续送猪/红桃给对方 | 防对方“回血”拿羊/变 |
| 己方负分接近 -1000 | 放弃边缘正分，先止损 | 强避猪/红桃/变压器负放大 |
| 对方正分接近 +1000 | 阻止其收羊/变/正分红桃 | 必要时自己收正分或破坏 |

### 4.2 从首轮出牌读意图

- **领短套**：想制造缺门，卖出猪/♥A/红桃；或短套无控制，请求同伴接手。
- **领长套**：有控制，想帮同伴卖牌、建立长套或领羊。
- **领 A**：强控，想收该花色/逼关键牌；也可能是“我有强套，你放心垫负分”。
- **领小牌非 A**：试探，寻找安全送分路线。
- **主动拱猪**：想逼♠Q 现身，把猪送给敌方。
- **不领黑桃**：可能持猪，等断门后垫出。
- **主动分红**：想把红桃负分送出去。
- **主动攻变**：争夺变压器或保护/放大某人小计。

### 4.3 从跟牌大小读意图

- 跟大牌：欢迎继续该花色、我有控制、愿意接；也可能是被迫。
- 跟最小牌：不欢迎、无控制、请换花色。
- 搭档赢墩时不盖：让搭档收；若本墩负分且搭档有变压器负风险，考虑接手。
- 对手赢墩时垫负分：对手在甩负，不要让同伴接；能截则截。
- 垫关键牌：异常，通常表示满贯/全红路线或已无安全牌。

> 以上只用于概率修正，不能机械执行；必须结合缺门、剩余张数、关键牌归属和分数情境。

## 5. 通用出牌原则（修正版）

1. **常规不想收全红/满贯时**：优先出“中间安全牌”，保留两头——大牌用于控制/得羊/破全红/破满贯，小牌用于安全跟牌/垫牌。若某花色 5 张以上，可保留最小张（2、3）作为安全张，同时保留大牌控制。  
   **若己方目标转为全红/满贯**：改为出小牌、留控制张，尽量保留能赢红桃/关键墩的大牌。
2. **无得猪危险时跑猪圈**：在黑桃安全、首轮限制允许、敌方亮猪且自己有控制时，可领♠A/♠K 跑猪圈，逼猪现身或逼亮猪者自收；但**想收满贯时不要先出黑桃大牌**，猪在满贯中被抑制，应保留控制张。
3. **需要卖猪/♥A/羊时出短套**：短套领出可制造缺门，后续垫负分。但若同伴亮羊/同伴困难，应改出长套帮同伴卖；若敌方全红/满贯威胁高，优先破坏。
4. **同伴困难或亮羊时出长套**：长套建立控制，帮同伴卖出猪/红大牌或领羊。但不要把负分塞给同伴；同伴若在走全红/满贯，则改为喂红桃/关键牌。
5. **想收满贯先出小牌留控制**：满贯路线下猪被抑制，不因“怕猪”放弃；关键牌让给满贯者，红桃控制保留，搭档负责挡对手抢关键牌。

## 6. 领出策略：首轮

### 6.1 无任何亮牌

| 自身情况 | 首轮动作 | 说明 |
|---|---|---|
| 无猪、无猪圈；或有 1 个猪圈但黑桃≥4 | 出黑桃非亮牌拱猪 | 表明自己无猪/无猪圈，逼猪现身；首轮亮猪牌不能出 |
| 有猪或黑桃短且多猪圈，有困难 | 出较短花色 | 让同伴从该花色帮自己卖猪/♥A/红桃；避免主动拱猪反被送猪 |
| 短套是红桃且同伴可能收 | 谨慎分红 | 先判断同伴是否全红/是否需要红桃 |
| 自己亮猪 | 不出♠Q；可出黑桃非亮牌或短套 | 亮猪牌首轮受限制 |

### 6.2 同伴亮猪

- 一般出**长套**，帮同伴建立控制、制造断门，让同伴把猪垫给敌方。
- 自己黑桃短时，可领黑桃非亮牌逼猪现身，但不要自己收猪。
- 若敌方全红/满贯概率高，优先破坏，不机械帮卖猪。

### 6.3 同伴亮♥A

- 自己持小红心或 ♥Jxx，可出 ♥J 或小红心，确认同伴是否想收全红。
- 同伴全红概率升高 → 喂红桃、让红桃墩。
- 敌方全红/满贯威胁升高 → 优先破红，不无谓送红桃给敌方。
- 不要因为同伴亮♥A 就把大红桃送给敌方收。

### 6.4 同伴亮羊

- 自己有含 ♦A 的两张以上：出方块中间大小，第二轮用 ♦A 领羊；这是固定配合信号。
- 若自己不是首轮领出者，一旦上手应马上出第一轮方块表示有 ♦A；若该副已出过方块，则该信号失效。
- 自己没有大方块，但有其他长套和上手张：出长套，准备上手后领羊。
- 若敌方正分接近 +1000，羊的边际价值下降，优先阻止敌方而非机械争羊。

### 6.5 自己亮羊且有 ♦A

- 可先拔 ♦A，明确告知同伴“有 ♦K 可领羊”。
- 同伴若只有 ♦Q，应视情况扔掉 ♦Q，让亮羊者判断能否安全落羊；若持 ♦Q 者已得变压器，另当别论（避免变压器负放大）。
- 若同伴无 ♦K、敌方全红/满贯威胁高，优先破坏/防守，不机械落羊。

### 6.6 敌方亮猪

- 应出黑桃非亮牌拱猪；有猪圈时首领 ♠A/♠K，逼亮猪者自收窝猪。
- 第一张亮猪不能出；想收满贯时不能先出黑桃大牌。
- 若自己黑桃短/无控制，不强行拱猪，改出短套让同伴控制，避免反被敌方送猪。
- 若敌方亮猪者小计为负且有变压器，拱其自收可放大负分，优先级上升。

### 6.7 敌方亮羊/亮变/亮♥A

| 敌方亮牌 | 首轮倾向 |
|---|---|
| 亮羊 | 抢方块控制，阻止其落羊；自己有 ♦A/K 可领方块 |
| 亮变 | 若其小计为负，准备塞猪/大红桃；若为正，阻止其收正分 |
| 亮♥A | 判断其全红概率：低则让其收红桃放大负分；高则优先破红 |

## 7. 领出策略：非首轮

非首轮领出按优先级：

1. **安全低牌**：非计分、低点数、不送猪/红桃。
2. **短套卖负**：需要卖猪/♥A/红桃时，领短套制造缺门。
3. **长套帮同伴**：同伴困难/亮羊/亮猪时，领长套建立控制，帮其卖牌。
4. **逼缺门**：敌方缺门时领该花色，逼其垫牌；但不要把负分逼给同伴。
5. **关键牌保护**：不轻易领自己需要保留的 A/K/Q；不领搭档变压器风险花色。
6. **分数情境**：
   - 己方领先/总猪头领先：降方差，安全第一；
   - 己方落后/总猪头落后：提高方差，争羊/变/全红；
   - 己方接近 -1000：绝不主动领红桃/猪门；
   - 对方接近 -1000：主动领红桃/猪门施压；
   - 对方接近 +1000：阻止其正分，必要时自己收正分。
7. **威胁模式**：
   - 搭档全红/满贯：领搭档能赢的花色，喂红桃/关键牌；
   - 敌方全红：领红桃逼其赢，或领其缺门逼其垫红桃；
   - 敌方满贯：领黑桃/方块/梅花逼关键牌提前暴露；
   - 搭档变压器负风险：不领红桃/黑桃，避免搭档被迫赢；
   - 己方得猪风险高：不领黑桃，把控制让给对手；
   - 对手得猪风险高：保持黑桃压力，不帮其解套。

### 7.1 同伴亮羊但自己无上手张

- 非首轮后持续帮同伴打方块，让同伴自己落羊。
- 若敌方全红/满贯威胁高，改为破红/抢关键牌，不机械帮羊。

### 7.2 无敌方全红/满贯风险时的负分处理

- 手中剩较多负分张：出大牌避免上手，尽快把负分甩给对手；但**同伴得变压器需保护时除外**。
- 反之，若己方需要得羊/控制敌方全红/满贯：保留大牌，不轻易扔掉控制张。
- 搭档全红/满贯路线：不按“避免上手”处理，改为喂牌/让墩。

## 8. 跟牌策略

### 8.1 先判断当前赢家

| 当前赢家 | 策略 |
|---|---|
| 搭档 | 不无谓盖压；本墩正分让搭档收；本墩负分且搭档有变压器负风险/非全红满贯，考虑接手 |
| 对手 | 正分/关键牌能争则争；负分不抢，优先垫负给对手；不能赢则甩负 |
| 自己 | 已赢则判断是否保赢；通常一墩只需最大牌，不重复浪费 |
| 未知（后面还有人） | 估计剩余玩家胜率，不只看当前最大牌 |

### 8.2 跟牌细则

1. 有领出花色必须跟；首轮限制下受限制亮牌不能跟，除非手中该花色仅剩这一张亮牌。
2. 搭档赢墩：
   - 不无谓盖压；
   - 若自己盖压能防止对手反超且本墩负分危险，可盖；
   - 搭档全红/满贯路线：让红桃/关键牌给搭档，不抢。
3. 对手赢墩：
   - 本墩有羊/变/正分：尽量争；
   - 本墩有猪/红桃负分：不抢，优先让对手收；
   - 不能赢：优先垫负分给对手，避免垫给搭档。
4. 最后一家：
   - 当前墩结果已知，直接按“赢/不赢”的团队收益选择；
   - 能赢且收益正 → 赢；不能赢 → 选对团队最有利的垫牌。
5. 缺门垫牌：
   - 对手赢墩 → 优先垫猪/红桃/危险负分；
   - 搭档赢墩 → 优先垫非计分/安全牌；搭档全红/满贯则喂红桃/关键牌；
   - 自己赢墩 → 不垫负分给自己。
6. 跟牌大小作为信息：
   - 跟大牌 = 欢迎继续/有控制；
   - 跟最小 = 不欢迎/无控制/请换花色；
   - 但必须结合已知缺门与剩余张数，不机械解读。

### 8.3 特殊牌跟牌表

| 牌 | 己方收 | 敌方收 | 关键判断 |
|---|---|---|---|
| 猪 ♠Q | 避免；单张亮猪自收仅 -200 可控；满贯路线不避 | 优先送给敌方，尤其亮变/接近 -1000 | 窝猪 -400；首轮亮猪限制；黑桃控制 |
| 羊 ♦J | 争；己方 +1000 边际下降 | 阻止；对方 -1000 时给羊可能帮其回血 | 方块控制；亮羊翻倍 |
| 变 ♣10 | 小计为正放大收益；小计为负放大风险 | 对手小计为负则塞负放大；为正则阻止 | 独拿 +50/+100；非独拿 ×2/×4 |
| ♥A | 若己方全红则收；否则避免负分 | 敌方全红概率低则让其收红桃放大负分；高则破红 | 亮♥A 红桃×2；全红反转 |
| 红桃 | 己方全红喂；否则避免 | 敌方全红破红；否则可送红桃给敌方 | 谁收红桃决定全红生死 |

## 10. 候选评分与决策伪代码

```ts
score(c) =
    w_trick   * 本墩团队收益(c)          // 谁收、收什么、是否关键牌
  + w_future  * 未来控制/领出权收益(c)
  + w_key     * 关键牌处理收益(c)        // 猪/羊/变/♥A
  + w_score   * 分数情境收益(c)          // ±1000、猪头差、最后一副
  + w_threat  * 威胁模式收益(c)          // 全红/满贯/变压器/避猪/争羊
  - w_risk    * 风险惩罚(c)              // 送同伴负分、帮敌方全红/满贯
  - w_leak    * 信息泄露惩罚(c)          // 无谓暴露控制张/关键张
  + w_noise   * 少量随机扰动
```

决策流程：

```ts
function choosePlay(obs) {
  if (obs.legalCards.length === 1) return obs.legalCards[0];

  const knowledge = updatePublicKnowledge(obs);
  const threat = updateThreatProbabilities(obs, knowledge);
  const context = classifyScoreContext(obs);
  const modes = resolveModes(threat, context); // 含迟滞

  let best = obs.legalCards[0], bestScore = -Infinity;
  for (const card of obs.legalCards) {
    const legal = isLegal(card, obs);
    if (!legal) continue;

    const trick = evaluateTrickOutcome(obs, card, knowledge, threat);
    const future = evaluateFutureControl(obs, card, knowledge);
    const key = evaluateKeyCards(obs, card, knowledge, threat);
    const scoreCtx = evaluateScoreContext(obs, trick, key, context);
    const threatDelta = evaluateThreatDelta(obs, card, threat, modes, trick, key);
    const risk = evaluateRisk(obs, card, knowledge, threat);
    const leak = evaluateInformationLeak(obs, card, knowledge);

    const total =
      1.0 * trick.teamDelta +
      0.8 * future.teamDelta +
      1.2 * key.teamDelta +
      1.5 * scoreCtx.teamDelta +
      1.8 * threatDelta.teamDelta -
      1.0 * risk.penalty -
      0.3 * leak.penalty;

    if (total > bestScore) { bestScore = total; best = card; }
  }
  return best;
}
```

权重可调；关键牌/威胁项在接近画头、满贯、全红时提高。

## 11. 更新、迟滞与信息隐藏

### 11.1 更新时机

| 时点 | 更新 |
|---|---|
| 亮牌揭晓 | 关键牌归属硬信息、亮牌修正 |
| 每张牌打出 | 未见牌、缺门、关键牌剩余、收牌概率 |
| 每墩结算 | 收牌归属、全红/满贯/猪/羊/变状态 |
| 每副开始 | 重置副内概率，保留团队分数与猪头 |
| 本局结束 | 重置局内概率，更新盘级状态 |

### 11.2 迟滞

模式进入/退出用双阈值，避免概率在临界点抖动。例如全红进入 60%、退出 45%；敌方满贯进入 25%、退出 15%。同一副内保持，跨副重置。

### 11.3 信息隐藏

- 不无谓暴露关键控制张；但为配合同伴可主动发“公开出牌信号”。
- 不通过出牌泄露自己持有猪/变/♥A，除非能换来更大团队收益。
- AI 不依赖约定暗号；人类若开启搭档信号，AI 仍只按公开信息决策。

## 13. 与亮牌规则/SRS 的关系

1. 首轮限制：受限制亮牌不能领出/跟牌；唯一亮牌跟牌必须出；兜底领出不死锁。
2. 亮牌揭晓后公开正面；自动亮在揭晓时公开；AI 不读取未揭晓亮牌。
3. AI 不依赖暗号；人类提示只基于公开信息。
4. 满贯以 SRS V3.1 为准：本队赢本局、对方画 1/2 头；不结算普通小分；不触发窝猪。
5. 本文是策略规范，不改变计分、赛制、亮牌合法性规则；任何冲突以 SRS V3.1 为准。
