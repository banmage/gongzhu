# 拱猪 · 对家双人队赛（Gongzhu 2v2）

基于《中式拱猪_对家双人队赛_SRS_V3.1》实现的本地单机版拱猪。人类控制南家，东/北/西为概率团队策略 AI；开始页可开启“四家 AI 全自动演示”，也可在对局中随时“托管南家”。界面沿用 `bridge_MVP` 的牌桌、发牌与出牌风格，并加入亮牌 → 统一揭晓 → 出牌的完整流程。

## 快速开始

```bash
cd gongzhu
npm install
npm run dev        # 本地开发
npm run build      # 类型检查 + 生产构建
npm run preview    # 预览构建产物
npm test           # 运行规则/计分/模拟/状态机测试
```

技术栈：Vue 3 + TypeScript + Pinia + Element Plus + Vite。

## 已实现内容

### 对局流程

- 52 张牌，无大小王，每人 13 张；Fisher-Yates 洗牌，按种子可复现。
- 每局第一副：持 ♠3 者领出，首引花色不限；后续副由上一副拿到 ♠Q 的玩家领出。
- 出牌顺序逆时针：南 → 东 → 北 → 西；同花色点数最大者赢墩，无将牌。
- 13 墩打完后结算；满贯/画猪头/单局副数上限触发后本局结束。
- 提前结束本副：所有红桃与猪/羊/变压器均已有归属，或剩余牌均为无分牌且全红已不可能、变压器也不会被剩余红桃改变时，自动进入结算。若单独变压器持有者仍可能收下剩余红桃（独拿 +50/+100 可能变为 0），则不提前结束。
- 最大牌提前结束：领出者剩余牌全为场上最大牌时，自动亮开所有人的剩余手牌，并由该领出者收下全部剩余牌后进入结算。
- 出牌阶段用闪烁箭头指示当前出牌方；轮到南家时，箭头直接指向系统推荐的出牌。悬停这张推荐牌会显示 AI 推荐理由与公开信息推断（缺门、关键牌归属、同花色未见大牌、残局路线），不展示其他三家的内部概率或未公开手牌。
- 出牌操作全部在手牌上完成：单击合法牌将其向上弹出，再次单击收回；右键单击任意合法牌直接出牌；双击合法牌也直接出牌。底部不再显示“轮到你出牌”和“出牌”按钮。
- 轮到南家且只剩唯一合法牌时，短暂停留后自动打出，墩面标记“唯一”，并在事件记录中标记为“唯一合法牌自动出牌”。
- 每墩四张牌出完后先完整展示 2 秒，再高亮赢家并收牌；赢家高亮结束后才进入下一墩。
- 每家座位旁有收牌区，实时展示已收到的红桃与猪/羊/变压器等计分牌（比手牌小一号）；亮牌以正面高亮牌面公开；亮牌读秒直接显示在南家可亮牌的中央，出牌读秒中自己的显示在系统推荐的牌上，其他玩家显示在中间一张未翻开牌背的正中。两种读秒都只在最后 10 秒出现，并同步语音播报；时限不足 10 秒时从实际秒数开始读秒。已打出的亮牌仍保留在座位旁，但会半透明降亮。
- 南家区域按“左侧已亮牌 / 中间手牌 / 右侧已收计分牌”三列排布，两侧牌略小并紧贴手牌；南家座位信息框与底部出牌按钮已移除。手牌按视口宽度分档放大，矮屏自动收紧以保证整桌无需滚动。右侧“亮牌提交”面板只在亮牌阶段显示，出牌阶段不再留下空面板。

### 亮牌与揭晓

- 可亮：♠Q 猪、♦J 羊、♣10 变压器、♥A 红桃A；允许同时亮多张。
- 进入亮牌阶段时，手中所有可亮牌都带金色外框；系统推荐的亮牌会自动弹起，玩家点击可亮牌也能弹起/收回，点击“亮牌”时只亮出已弹起的牌。
- 亮牌提交后不可撤回，并立即在该座位旁正面公开；提交前只显示提交状态。自己已亮的牌在手牌中以金色描边和提亮强调。
- 手中没有可亮牌时自动跳过亮牌提交，不再显示“提交亮牌”按钮。
- 全员提交或倒计时结束后统一揭晓；`autoLightLastOne` 可在开始页选择开启/关闭，开启时已亮 3 张即自动亮最后一张。
- 自动亮牌在揭晓时才公开，未揭晓前不计入“已亮 N 张”；揭晓后在座位旁以“半明半暗斜向分割纹路 + 自动标签”与普通亮牌区分。
- 亮牌阶段中央显示两队本局总分（含已结算各副），无需等到结算页即可比较当前形势。
- 所有分数统一按“正分红、负分绿、零分中性”着色，覆盖亮牌阶段比分、结算弹窗、盘终记录与逐副复盘。
- 首轮限制：每副牌中某花色第一次作为领出花色的一墩，该花色中被亮过的牌不能领出/跟牌；该墩结算后解除。
  - 跟牌例外：该花色只剩受限制亮牌时必须出。
  - 领出例外：手中只剩受限制亮牌时，兜底允许任选一张领出，该牌会以虚线标出。
  - 自动亮牌同样适用首轮限制。

### 亮牌规则引擎（V1.0，可热插拔）

- 推荐亮牌不再使用写死的基础策略，而是严格按 `docs/拱猪亮牌规则_V1.0.md` 的 A→B→C→D 分层计算：相对分差分支、基准概率、牌型因子、满贯修正（默认关闭）、互斥与采样。
- 规则配置与文档第 10 节字段一致（snake_case JSON）。系统管理员可在开始页或顶栏打开“亮牌规则”面板，编辑 JSON、导入/导出文件、恢复内置默认。
- 应用规则后立即替换内存中的激活规则并持久化到 localStorage；后续推荐与 AI 亮牌立即使用新规则，无需刷新页面。亮牌阶段尚未提交时，南家的推荐会自动刷新。
- 随机采样由“发牌种子 + 座位 + 副序号 + 牌种”派生，固定输入可复现；调试可把 `sampling.mode` 改为 `threshold` 直接按阈值出牌。
- 规则中的 `game` 段随 JSON 导出/导入，便于审计；实际读秒与第四张自动亮仍以开始页设置为准。
- 引擎只使用自己的手牌、公开分数与已公开亮牌，不读取他人手牌。
- 猪门恰好 3 张时，常规分支硬性不推荐亮猪；绝境/搏杀分支仍按规则文档保留赌博性亮猪。
- 短套结构奖励（文档 6.9）：无大红桃、无猪圈时，2~3 张梅花带 ♣10 可亮变压器，3 张方块带 ♦J 可亮羊，4 张黑桃含 ♠Q 或 4 张红桃含 ♥A 且另有单缺花色时可亮猪/♥A；该奖励通过 `module_b.shape_bonus` 热插拔开关与阈值控制。
- 模块 C（满贯概率修正）在接入可复现估算器前禁止启用，避免“看起来开启、实际 `F_slam=1`”的静默无效。
- 实现审计见 [`_archive/亮牌规则实现审计.md`](_archive/亮牌规则实现审计.md)，其中区分了已实现条款、产品化偏差与规范自身问题。

### 出牌 AI（概率团队策略）

- 每次出牌先把真实牌局裁剪成不含他人手牌的 `PlayObservation`，再推导缺门、未见牌、关键牌归属等公共知识。
- 对包括自己在内的四家动态估计全红、满贯、得猪、得羊、变压器负向放大等概率；概率随每张牌打出更新。
- 全红概率不是简单的边际乘积：已收红桃进度与剩余高红桃控制力会动态抬高全红概率；收下一圈红桃且手中只剩 ♥A 时，会立即切换到全红模式，不再把 ♥A 当作垫牌。
- 根据局势切换团队模式：配合己方/搭档全红或满贯、保护收变压器的搭档、破坏敌方全红/满贯、避猪/保猪、争羊、危险分与终点判断。
- 满贯概率严格以全红概率为前提：其他家已收红桃、全红已经不可能时，不再按“三张关键牌 + 六张红桃”虚报满贯威胁。
- 关键牌硬事实：任意一家收到红桃、羊、变压器或猪后，其他家满贯概率立即归零；收到红桃后其他家全红概率也归零。
- 关键牌难度区分：持羊且方片短小时，因 Q/K/A 很少被垫掉，羊更容易被抢，满贯概率下调；持猪即使黑桃短，早期落猪通常无人抢，仍按“可安全收下”估计。
- 敌方已收三张关键牌或八张以上红桃时，即使概率估计仍不高，也会按“进度威胁”主动截红桃、破满贯，必要时用大红桃吃入；阻止敌方全红/满贯的优先级高于普通避负分。
- 手持 ♥A + 少量小牌（HAxx/HAx）时，不再把自己当作全红目标：优先把 ♥A 垫给没有负向变压器的同伴，或垫给非全红目标的敌方；没有垫牌机会时在前期主动用 ♥A 落墩，把负分封顶并剥夺敌方的 ♥A。
- 同伴尚未被证实放弃全红（其全红概率不为 0）时，不轻易把红桃垫给其他家：能把红桃喂给同伴就喂给同伴，自己不主动领出 ♥A；只有为了替同伴挡变压器或破坏更高的敌方全红压力，才自己吃进。
- 敌方任一家的全红压力升高时，优先把红桃垫给同伴或非目标敌方来破红；当前赢家正好是全红目标时不把红桃喂给目标。其他家已收红桃、使同伴全红被证实破产后，自动恢复普通垫牌，不再过度保护。
- 残局按剩余牌型留牌：只剩羊/正向变压器等高价值目标时优先保留大牌；只剩亮猪/负向变压器等高风险负值时优先脱手大牌、保留小牌。
- 默认使用快速概率启发式，不采样完整牌局，保证整场比赛与界面响应；固定公开观察 + 固定种子下出牌确定。

### 信息边界

- 所有亮牌推荐与出牌 AI 只使用自己的手牌、当前墩、已打出的牌、已公开亮牌、公开分数与合法出牌集合。
- 不读取、不推断未公开的其他玩家手牌，不存在“上帝视角”分析路径；复盘与事件记录也只展示已经公开或已经结束的牌局信息。

### 计分（严格按 SRS 5.2 顺序）

1. 统计四人实际收牌。
2. 判满贯：单人集齐猪、羊、变压器、全部 13 张红桃 → 本队立即赢下本局，不生成正式个人分。
3. 亮牌修正：亮猪 -200、亮羊 +200；亮 ♥A 使全场所有选手的红桃分值 ×2（含♥A自身）。
4. 全红：单人收齐 13 张红桃，红桃总分反转（-200 → +200；亮 ♥A 则 -400 → +400）。
5. 窝猪：亮猪者本人自收 ♠Q，猪分记 -400；自动亮猪自收同样算窝猪。例外：亮猪时手中只有单张黑桃（即 ♠Q），本人自收 ♠Q 不记窝猪，仍按亮猪 -200。
6. 变压器：独拿 +50（亮变 +100）；非独拿对修正后非零总分 ×2（亮变 ×4）；总分为 0 时仍为 0，不触发 +50。
7. 个人正式分；团队本副小分 = 南+北（A队）或 东+西（B队）。
8. 团队小分累加到本局。

结算弹窗先醒目展示本副四张关键牌的亮/未亮状态、亮牌者与自动亮标记，再显示两队本局总分（含本副），并按南北队（左栏）/ 东西队（右栏）展示本副各选手得分，最后只展示每位选手实际涉及的红桃、羊、猪、变压器明细，未涉及的类别整行不显示。结算弹窗为每位玩家展示完整 `ScoreBreakdown`：基础分、亮牌修正、全红、窝猪、变压器、最终分与收牌明细。收牌明细只展示参与计分的猪、羊、变压器与红桃，不显示无关垫牌。结算弹窗可用右上角或页脚“关闭”按钮收起；关闭后主页面仍保留“查看结算”和“下一副/进入下一局”入口，不会卡在结算页。

### 画猪头与赛制

- 6.2 全组合：正分高使对方被画头，负分低使本队被画头；双方同高/同低按 6.4 比较小分。
- 6.4：新增猪头相同 → 小分更低者负；小分相同判和。
- 6.5：单局默认 20 副上限，达到上限未画头 → 小分更低方画 1 头；相同各画 1 头判和。
- 满贯画头：非全亮 1 头；触发满贯的该副四张关键牌全亮（含自动亮）2 头。
- 5 局制：5 局后总猪头少者胜；相同进入突然死亡加赛，每局比较总猪头。
- 8 局制：8 局后总猪头少者胜；相同按“最后一局新增猪头多者负 → 6.4 → 向前回溯 → 判和”。
- 盘终弹窗展示最终裁决依据，不只显示胜负。

### 对局管理与审计

- 亮牌/出牌读秒默认 30s/20s，可在开始页设为 5–60 秒，或勾选“无读秒”关闭倒计时。读秒只在剩余 10 秒及以内显示倒计时并语音播报，不足 10 秒时从实际秒数开始；关闭后不会自动提交/出牌，需玩家手动操作。出牌超时按“最小合法牌规则”自动出牌并标记“超时”。
- 托管南家：南家交给概率团队策略 AI，与真人使用同一公开信息边界。开始页的“四家 AI 全自动演示”开关等价于开局即托管南家，可完整跑完发牌、亮牌、出牌与结算；对局中仍可从顶栏随时切换。
- 每副记录：种子、洗牌算法、RNG 版本、牌堆哈希、发牌哈希、公开时机。
- 事件记录：开赛、发牌、亮牌提交、自动亮、揭晓、出牌、超时、墩结算、提前结束、副结算、画猪头、局/盘结算等。
- 顶部“记录”按钮可查看事件记录与逐副复盘（按墩回看出牌、亮牌、收牌与个人分；提前结束时不足 13 墩），并导出审计 JSON。

- 计分流水线：猪/羊/♥A、全红、窝猪（含单张黑桃亮猪免窝猪）、变压器独拿/非独拿/零分、满贯全亮/非全亮。
- 首轮限制：跟牌、唯一亮牌、缺门、已解除、领出兜底；首引不强制花色。
- 亮牌规则 V1.0：分支阈值、羊硬否决、猪门 3 张常规硬否决、牌型因子、零风险变压器、互斥/上限、确定性采样与热插拔更新；亮牌读秒超时自动提交当前选择；模块 C 无估算器时禁止启用。
- 6.2 画猪头全组合、6.4、6.5。
- 5 局制加赛、8 局制最后一局/回溯/判和。
- 40 个种子的整副牌 AI 模拟，验证无死锁、52 张牌全部收完。
- 概率出牌策略：全红/满贯概率硬约束（全红不可能时满贯归零、其他家收走任意关键牌后满贯归零）、收牌进度与高红桃控制驱动的全红概率上调、羊/猪关键牌难度差异、猪归属、搭档变压器保护、敌方满贯破坏、♥A 垫同伴/敌方与前期落 ♥A、同伴全红未破时的红桃去向（不垫给非同伴、不主动领 ♥A、同伴赢墩继续喂牌、破产后恢复）、敌方全红压力下的破红去向（垫给非目标敌方、不喂目标家）、残局高价值留大牌/高风险留小牌、信息边界与确定性。
- store 端到端：发牌 → 亮牌 → 揭晓 → 出牌（含提前结束）→ 结算；全托管连续多局进入盘终。
- 推荐解释与读秒定位：推荐牌返回合法牌、理由与公开推断；悬停推荐牌才显示理由浮层；出牌读秒在推荐牌/中间牌背之间切换，顶栏不再显示出牌读秒。

## 说明与边界

- 本项目是本地单机实现，Pinia store 充当权威状态源；未包含 SRS 第 14 章的联机服务端、房间/匹配、断线重连与权限接口。对应地，用“托管南家”演示 AI 接管，超时自动出牌与 AI 出牌均有标记。
- 团队出牌策略的设计与实现说明见 [`docs/打牌策略规范 V2.0.md`](docs/打牌策略规范%20V2.0.md)。当前默认实现为“四方动态概率 + 团队启发式”快速层；文档中的 PIMC 采样搜索、模式迟滞与末局精确搜索保留为后续 `standard/strong` 强度扩展，未默认启用。推荐出牌的解释层在 `src/core/aiExplain.ts`，只复用公开观察与候选评分明细，不额外读取隐藏信息。旧版策略文档已归档到 `_archive/`。
- “复盘”为按副、按墩的静态回看，不是动画回放；完整事件与牌局数据可通过审计 JSON 导出后离线分析。
- 满贯时的个人分为“模拟展示分”，界面明确标注不计入小分。
- 按当前交互要求，亮牌在提交后立即在各座位旁正面公开；这覆盖了 SRS 中“暗亮、揭晓前不可见”的展示限制，其余亮牌规则（不可撤回、自动亮、首轮限制）保持不变。
